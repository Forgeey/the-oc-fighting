# 文档模板覆盖矩阵与完成定义

> 更新日期：2026-08-01  
> 本表用于回答“文档模板是否齐全”，不代表对应游戏系统已经实现，也不代表模板内容已经完成评审。

## 1. 完成状态口径

| 层级 | “已完成”含义 | 当前状态 |
|---|---|---|
| 目录与规范 | 文档分层、命名、评审、追踪和归档规则已经建立 | 已完成 |
| 模板覆盖 | 当前范围内的系统有 SDD、TDD、测试模板或明确的合并归属 | 已完成 |
| 正式设计 | 将模板中的“待定”替换为项目决策，并完成评审 | 未开始/按系统推进 |
| 功能实现 | 按已评审设计完成 Godot/Fray 代码、资源和场景 | 不属于本次文档整理结果 |
| 验收发布 | 执行测试、性能、长稳和发布检查并留存结果 | 未开始/随版本推进 |

## 4. 使用建议

1. 先复制并填写 GDD、版本范围和总体 SDD。
2. 按垂直切片顺序把对应 P0 SDD 从“模板”推进到“草稿/评审中/已确认”。
3. 只有高风险或跨多个文件的模块才复制专项 TDD；简单改动直接更新所属 SDD 或内容模板。
4. 每个正式需求填写稳定 ID，并在需求追踪矩阵中链接 SDD、TDD、实现与测试。
5. 模板中的“待定”是待决策项，不应被误认为已经完成设计。
