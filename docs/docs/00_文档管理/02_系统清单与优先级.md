# 游戏系统清单与优先级

> 本清单基于当前 GDD 中的 Windows PC、本地 1v1、AI、训练、基础教程、OC 外观编辑、招式装配、多层视差和破墙换场目标整理。

## 1. 优先级定义

- **P0：可玩闭环必需。** 缺失时不能形成稳定 MVP。
- **P1：首发质量或内容效率需要。** 可分阶段完成，但应在首发前评估。
- **P2：未来独立立项。** 不应默认进入 MVP。

## 2. 系统全表

| ID | 系统 | 优先级 | 为什么需要 | 主要文档 |
|---|---|---:|---|---|
| SYS-ARCH | 总体软件架构 | P0 | 统一模块边界、依赖、生命周期和数据所有权 | 总体 SDD |
| SYS-COMBAT | 战斗系统 | P0 | 移动、攻击、防御、受击、连段、资源、KO | 战斗 SDD + 多个 TDD |
| SYS-FIGHTER | 角色运行时与状态机 | P0 | 把角色流程映射为 Fray 状态机 | 角色运行时 SDD |
| SYS-INPUT | 输入与设备 | P0 | 键盘、手柄、重映射、缓冲、指令识别 | 输入 SDD + 输入 TDD |
| SYS-APPEARANCE | 自定义角色造型 | P0 | 核心卖点之一，且必须保持判定公平和可读性 | 外观 SDD + 合成 TDD |
| SYS-LOADOUT | 招式装配与构筑 | P0 | 核心卖点之一，负责槽位、预算、兼容性和公平性 | 装配 SDD + 校验 TDD |
| SYS-STAGE | 舞台、视差与场景段落 | P0 | 核心演出、空间边界和破墙换场 | 舞台 SDD + 视差/破墙 TDD |
| SYS-CAMERA | 战斗摄像机与画面表现 | P0 | 双角色构图、缩放、震动、边界和无障碍 | 摄像机 SDD + 摄像机 TDD |
| SYS-MATCH | 比赛、回合与规则流程 | P0 | 倒计时、回合开始、暂停、KO、结算、再战 | 比赛流程 SDD + 协调器 TDD |
| SYS-SESSION | 本地多人和玩家设备会话 | P0 | 分配 P1/P2、键盘冲突、手柄断连和重连 | 会话 SDD + 设备 TDD |
| SYS-UI | 菜单、编辑器、HUD 与无障碍 | P0 | 完成模式选择、角色编辑、对局信息和设置 | UI SDD + HUD TDD |
| SYS-MODES | 游戏模式、训练与教程 | P0 | GDD 明确要求本地对战、CPU、训练、基础教程 | 模式 SDD + 训练 TDD |
| SYS-AI | CPU 与训练假人 | P0 | MVP 包含 AI 对战；训练需要可控假人 | AI SDD + AI/假人 TDD |
| SYS-DATA | 配置、预设与存档 | P0 | 保存 OC、招式装配、设置、解锁和版本迁移 | 数据 SDD + 序列化 TDD |
| SYS-FEEDBACK | 动画、VFX、音频与打击反馈 | P0 | hitstop、命中火花、音效和镜头反馈决定战斗可读性 | 反馈 SDD + 动画同步 TDD |
| SYS-CONTENT | 资源注册、加载与内容生产管线 | P0 | 大量部件、招式和舞台需要稳定的导入与校验方式 | 内容管线 SDD + 注册表 TDD |
| SYS-QUALITY | 调试、测试与性能 | P0 | 60 FPS、判定一致性、训练数据显示和回归验证 | 质量 SDD + 诊断 TDD + 测试/性能文档 |
| SYS-PROGRESSION | 外观解锁与进度 | P1 | GDD 中的局外奖励循环；不应影响竞技数值 | 进度 SDD |
| SYS-PLATFORM | 设置、平台与发布 | P1 | Windows、Steam 可选接入、日志、崩溃和版本管理 | 平台 SDD |
| SYS-REPLAY | 回放与输入记录 | P1 | 支撑训练复盘、最近一局查看和缺陷复现 | 可先并入训练系统 |
| SYS-LOCALIZATION | 本地化 | P1 | 文本、字幕和按键提示需要可扩展 | 可并入 UI SDD |
| SYS-NET | 回滚网络对战 | P2 | 成本高，且会反向约束确定性架构 | 独立立项模板 |
| SYS-UGC | 创意工坊与外部 UGC | P2 | 涉及格式、安全、兼容、审核和版本管理 | 独立立项模板 |

## 3. 推荐开发顺序

### 阶段 A：最小战斗垂直切片

1. 总体架构、输入、角色运行时状态机；
2. 移动、攻击、受击、防御、KO；
3. 动画事件、hitbox、hitstop 和基本 HUD；
4. 单舞台、基础摄像机、本地双人；
5. 调试覆盖层和冒烟测试。

### 阶段 B：核心差异化

1. OC 外观部件合成和可读性校验；
2. 招式资源、槽位、预算和兼容性校验；
3. 多层视差、动态背景和破墙换场；
4. 预设保存和版本迁移。

### 阶段 C：MVP 完整闭环

1. 主菜单、编辑器、角色选择、设置；
2. 比赛流程、再战和结算；
3. CPU、训练模式和基础教程；
4. 音频/VFX、性能预算和完整验收。

### 阶段 D：首发增强

1. 进度与装饰解锁；
2. 街机路线、连段挑战、回放；
3. 平台功能、本地化和无障碍完善。

## 4. 当前不应提前实现的内容

- 不在未立项时构建回滚网络层；
- 不允许外观部件改变 hitbox、hurtbox 或 pushbox；
- 不维护 Fray 之外的第二套输入、状态机或攻击数据系统；
- 不在首个垂直切片阶段制作大量角色和舞台内容；
- 不在数据格式未版本化前开放外部 UGC。
