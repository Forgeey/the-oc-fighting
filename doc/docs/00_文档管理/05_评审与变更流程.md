# 文档评审与变更流程

## 1. 状态流转

```text
模板 → 草稿 → 评审中 → 已确认 → 已废弃/被替代
```

## 2. 评审顺序

1. 玩法负责人确认 GDD/玩法目标；
2. 技术负责人确认 SDD 边界和依赖；
3. 实现负责人确认 TDD 可执行性；
4. 测试负责人确认验收标准和边界用例；
5. 发生重大取舍时创建 ADR。

## 3. 必须更新文档的变更

- 状态机拓扑、输入优先级、攻击属性结构改变；
- 预设/存档格式改变；
- 外观或招式装配规则改变；
- 舞台边界、摄像机或破墙流程改变；
- 公共信号、接口、资源路径改变；
- 性能预算或平台范围改变。

## 4. 完成定义

- 相关文档状态至少为“评审中”；
- 实现与 SDD/TDD 一致；
- 测试项可执行并记录结果；
- 文档没有第二套攻击数值或状态表；
- 必须绕过 Fray 时已有 ADR；
- 变更记录和需求追踪矩阵已更新。
