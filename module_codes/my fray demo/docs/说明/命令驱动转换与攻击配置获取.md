# 命令驱动转换与攻击配置获取

> 2026-11-11 容器式装配更新：叶子和转换不再保存父组字符串；FighterCompoundStateDefinition.states／transitions 直接持有成员与内部边，TransitionLibrary.transitions 仅持有根边。组内归属由资源放在哪个容器决定，详见[状态机资源配置说明](状态机资源配置说明.md)。旧字段说明及示例已删除，不提供兼容别名。


> 当前状态：2026-11-10 扁平化已完成。详见[扁平状态机迁移说明](扁平状态机迁移说明.md)和[状态机资源配置说明](状态机资源配置说明.md)。根直接使用原生 FrayCompoundState，旧版全路径根适配逻辑和无职责的类型包装均已移除。

## 1. 输入与动作身份分离

FighterCommandDefinition.command_id 是逻辑命令，FighterTransitionDefinition.command 是边接受的命令。二者不要求对应唯一 move_id：同一 light_attack 可由 idle、fwalk、bwalk 各自的边接受，也可在相同来源按条件和 priority 选不同目标。

Move.move_id／state_ids 用于装备和资源目录；转换不传 move_id，也不需要 Fighter.try_command。Matcher 在角色构建时配置，识别后直接 buffer_sequence(command_id)。

## 2. 当前转换链

```text
Fray 输入／单一 Matcher
  → command_id
  → 原生 FrayBufferedInputAdvancer
  → 原版 FrayStateMachine.advance(input)
  → 根继承的原生 FrayCompoundState.advance(input)
  → 当前直接子状态的 FrayInputTransitionSequence／普通条件边
  → 原生条件检查与进入／退出
```

Builder 在装配期完成输入边 priority／资源顺序，以及 Move.prereqs 到相应目标入口私有边的合并。根运行时不再扫描全库、查找活动祖先或转换跨组全路径。

攻击失败后可走普通移动／返回；true 仅表示发生转换，不代表攻击成功。原生 advancer FIFO、失败出队、统一时限没有改变。Fighter 的 transitioned 信号监听阻止同帧第二次普通推进。

## 3. 状态通过 context 取得判定属性

FighterState 从 context 取得 hit_state_manager。BasicAttackState 进入时先 super-enter 选中本状态姿态，再由 Manager 获取姿态和框列表，从 kind=ATTACK 的 FighterHitboxAttribute 读取时间配置。

所有 kind 共用 FighterHitboxAttribute 脚本；无需额外 FighterAttackAttribute。startup／active／recovery 和 total_frames 属于 Attribute，不属于 Move；elapsed_frames 属于状态实例。状态按每框窗口控制位，保留 Hurt／Push，退出／中断立即清理。

属性缓存是该状态当前执行所选框的引用，不是每帧盲从 Manager 读取不确定的“当前攻击”。多框总时长等待各框窗口和恢复中的最大完整时长。具体时序见[攻击 Attribute 帧配置与 Fighter 精简记录](攻击Attribute帧配置与Fighter精简记录.md)及其顶部合并更新。

## 4. 当前无需的接口

- FrayStateMachine 不需要 fighter 属性或游戏侧派生节点脚本。
- Fighter 不解析命令为唯一招式，也不传 args["move"]。
- State 不需要由 Builder 绑定 move 来取得帧数。
- 根不需要 try_input／rules／跨层桥接 API。
- 转换端点使用 owner 的直接子状态名称，例如 idle、light_attack、combo1；不带分类前缀。

根对象直接使用原生 FrayCompoundState，旧的无职责根包装及专属 UID、标记测试和引用均已清理，没有新增替代适配器。
