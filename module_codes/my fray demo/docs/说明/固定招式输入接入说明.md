## 本次已实现

- `FighterInput` 角色输入节点：复用 FrayController/FrayInput，按设备过滤事件，忽略 echo；方向先清洗再转成相对面向的数字方向。
- `FighterCommandDefinition`：作者固定的 SINGLE/COMBINATION/SEQUENCE 输入资源。
- `FighterMoveDefinition`：command 内嵌于完整招式资源，含入口、阶段、内部转换、可执行来源与前置条件。
- `FighterLoadout.selected_move_ids`：从 MoveLibrary 按 ID 选择招式，不保存指令覆盖项。
- 构建器合并招式状态依赖、自动创建所需分组，再按可用端点和已装备招式筛选公共转换；按当前约定信任配置有效，不进行装配合法性或冲突检查。
- `inputed_fwalk` 正反条件接回普通转换。无输入保持 Idle，前进输入进入 FWalk，松开返回 Idle；不是把 FWalk 包成攻击指令。
- 游戏层一个普通推进调度者，候选失败保留至过期，成功消费后移除使用同一按钮周期的其他候选。

未新增全量 InputFrame、指令编辑器、指令栏位、公共 CommandLibrary、独立 CommandMatcher 或额外 CommandBuffer 类。候选队列直接保存在 FighterInput 内。

## 节点与帧顺序

`scenes/Fighter.tscn` 新增一个 `FighterInput`（Node）子节点，其余节点保留。

```text
FrayInput 自动采样                  priority -100
FighterInput 方向/事件/候选处理      priority -50
FrayStateMachine 活动状态物理更新    priority 0，advance_mode = MANUAL
Fighter 普通规则推进                priority 50，一帧最多一次
```

FrayBufferedInputAdvancer 继续暂停，不再与状态机 PHYSICS 自动推进并行。优先级在项目侧设置，未修改插件源码。`sample()` 和 `advance_commands()` 不应再由其他调度者重复调用；候选过期统一在 `sample()` 中处理，`get_candidates()` 只过滤尚未就绪的普通单键，不做候选评分或排序。

角色默认面向右；可调用 `fighter.set_facing(-1)` 切换为左，输入和运动同步使用相对方向。没有自动寻找对手/自动换面向系统，也没有新增后退状态。

## 如何制作真正的招式资源

> 2026-10-25 设计修订：每个特殊技固定方向序列和一个指定攻击按钮；每个招式一套明确基础数值，不自动接受轻／中／重按钮选择强度。默认每招自己的执行叶子与脚本，起手／有效／恢复由该叶子内部逻辑帧推进。固定指令并不使脚本复用技术上不可行，但当前不建设通用多招执行器，公共工具照常复用。详见 [疑难解答](招式装配与判定时序疑难解答.md)。

在 Godot Inspector 创建 `FighterMoveDefinition`（保存为 `resource/moves/<move_id>_move.tres`；编号按[招式编号模板](../方案/招式编号模板.md)分配）：

1. 分配八位数字字符串 `move_id` 并填写显示用 `move_name`，例如 `move_id = &"02010001"`、`move_name = "火球"`（制作示例，尚未创建资源）。现有轻攻击为 `&"01010001"` / “轻攻击”。名称不参与查找，按钮名仍是 light_attack 等逻辑动作。
2. 在 `command` 上创建内嵌的 `FighterCommandDefinition`。
3. SINGLE：填一个 buttons；COMBINATION：填至少两个不同逻辑按钮；SEQUENCE：填写 steps。
4. 当前内容约定让 entry_path 指向本招具体叶子，如 action/special_attack/fireball；框架虽允许有效复合入口，不把它用作多招通用派发。
5. 在 StateLibrary 登记本招叶子定义及 state_script，并在 Move.required_state_paths 中引用完整路径。普通三阶段不拆成三个定义。
6. 在 TransitionLibrary 中新增本招可用的发动边：指定 move_id、源/目标端点、条件和 switch_mode，无需再向 Move 或 State 登记转换 ID。所有转换直接在 from_state/to_state 中填写完整状态路径，不再配置转换 group_path。无对应边的来源不能发动；不再配置 allowed_from_paths。
7. inputed_<intent> 条件由 Builder 通用绑定到 FighterInput.has_intent(intent)，不再逐个定义或映射 inputed_xxx()；其他条件仍使用 condition_methods 映射到 Fighter 无参 bool 方法。发动边的 switch_mode 为 AT_END 时同时检查源及最深活动叶子完成；IMMEDIATE 才能跳过完成等待。
8. 把该资源登记到 MoveLibrary，并把 move_id 加入角色 Loadout 的 selected_move_ids。

输入定义示例（字段与已实现脚本一致）：

```text
SINGLE:
  buttons = [light_attack]
  trigger = PRESS

COMBINATION:
  buttons = [light_attack, medium_attack]
  combination_window_frames = 2

SEQUENCE:
  steps = [dir_2, dir_3, dir_6, light_attack]
  max_step_delay_ms = 200
  min_charge_ms = 0
  negative_edge = false
```

方向为 dir_1..dir_9（dir_5 是中立），6 永远是相对面向前。方向和按钮别名使用不同输入流，不把 W 同时产生的 jump 误当成一条多余摇杆步骤。

`resolve_delay_frames` 只用于普通单键等待组合键；有重叠组合键时应覆盖其 `combination_window_frames`，没有组合键需求可设为 0。序列或组合命中后当帧即可尝试执行，不等待该延迟。`buffer_frames` 是从候选生成帧开始计算的保留期限；窗口内不接受并不消费，期限之后不再执行。

按钮事件先交给 Fray 序列匹配器确认特殊指令；未命中才允许生成普通单键。组合键命中后会撤销同源、尚未执行的普通单键候选。同一按钮周期一旦归属于特殊指令，即使特殊技暂时不能执行或候选到期，也不回退普通攻击；再次按下按钮才开始新的输入周期。

### 执行接口边界

固定招式不是在识别信号里直接 goto。Fighter 先查找已装配 TransitionLibrary 中匹配候选 move_id、入口目标与活动源的发动边，再验证 Move 公共前置条件及该规则条件/完成模式，通过后才调用修复插件的 `_transition_to(..., source)` 执行 external 转移。Fray 的公开普通转换端点仅支持本组直接子状态，因此这个跨层入口桥接集中在 Fighter._try_move；以后若升级插件执行接口，主要检查此处。

普通状态／移动转换仍由 Fray.advance 执行；候选执行成功后本帧不再推进第二条普通规则。未来普通招式的三阶段计时在叶子内部，不交给三条 Fray 转换。

显示保留 AnimatedSprite2D；当前未使用的 AnimationPlayer 节点已移除。判定与完成条件将由逻辑帧驱动，不使用动画轨或动画完成信号；本次未实现攻击计时／判定绑定。

### 资源配置约定（构建器不做防御性校验）

`sm_builder.gd` 假设状态、招式、路径、类型、条件映射和方法都存在且正确，直接读取并装配；不再提供 validate_moves 或失败返回。以下由作者保证，不是运行时自动检查。

- 完全重复的输入模式不应在有重叠来源状态/父组时同时装备；组合键的按钮顺序不影响模式身份。
- 多个特殊指令同时匹配同一按钮周期时，按 selected_moves 顺序确认首个匹配；不再按来源条件回退到其他同源招式，作者应避免歧义配置。
- 严格序列前缀（例如 light 与 light→heavy）不应在重叠来源中同时装配；不是已经实现了任意前缀等待和回退。
- 236+轻命中时只保留特殊技候选；没有匹配的特殊指令才回退单个轻。轻+中可以在等待窗口内替换同源单键；已被序列确认的按钮不会再次分配给组合键。
- 指令不再提供数值优先级或具体程度评分；不同输入来源的候选保持生成顺序。状态转换 priority 和物理回调顺序不属于指令选择，本轮保持不变。
- 不会修改任何共享 `.tres` 的 command 内容；方向历史、候选与消费标记都属于每角色节点。

## 当前明确限制

- 首版 SINGLE 支持 PRESS/RELEASE，持续防御/蹲下直接查询 Controller；没有把 held 每帧生成攻击候选。
- COMBINATION 支持按钮集合与帧容错，复用 Fray ASYNC 组合；本版只支持 press。
- SEQUENCE 支持方向/按钮步骤、首步骤方向蓄力、negative edge；序列末步骤只能是一个按钮，暂未实现“序列末尾同时键”。
- 当前游戏实现为每个序列创建独立 Fray matcher；这是接线选择，不是 Fray 要求。一个 tree／matcher 可以注册多个命名序列，不同路径的时限保存在各自 branch；完全相同路径的多个名字才会终点冲突。后续计划改为每角色、每兼容事件域复用一个 matcher，尚未修改运行代码。匹配信号回调内可用 get_match_branch() 读取完整事件；详见[输入系统设计方案第 9 节](../方案/输入系统设计方案.md)。
- 进入阶段时若需要“只接受选择窗口开始后的按键”，状态仍需使用 input_frame/窗口起始帧进行业务验证；本次没有制作具体择招。
- 配置/卸装输入模块时清空旧历史；没有制作战斗中完整状态机 rebuild、选招 UI、改键 UI 或存档。
- 换面向清除半条方向指令，不自动生成反向手势；失焦清历史并暂停输入处理；断线、disabled、切设备时清理。
- device 过滤已存在，但 Godot 全局 action bind 不保证多键盘玩家完全隔离；手柄分设备映射另做。
- Fray 的序列时限仍基于毫秒墙钟，候选有效期用物理帧；未实现暂停/Hitstop 精细政策、网络回滚或确定性回放。

## 输入条件查询简化（2026-11-06）

```gdscript
fighter_input.has_intent(&"fwalk")
fighter_input.has_intent(&"bwalk")
fighter_input.has_intent(&"crouch")
fighter_input.get_movement_axis(&"fwalk")
```

FighterInput.get_movement_intent() 是当前基础移动意图的唯一解释位置：先处理下蹲，再按相对朝向的水平轴区分前后和待机。has_intent() 做通用查询；get_movement_axis() 在指定意图成立时返回世界水平轴，下蹲返回零。

转换资源继续写 inputed_fwalk、inputed_bwalk、inputed_crouch，否定条件继续用 !。它们是条件键，不是需要逐一声明的函数名。condition_methods 只保存非 inputed_ 条件，因此新增输入条件不再需要在 Input/Fighter/映射表重复增加同名函数。

这次不合并 Idle/FWalk/BWalk 状态、不删除状态脚本或 UID，也不修改物理运动代码；前后走状态仅改为直接使用通用轴查询。未来增加跳跃、冲刺等动作时，仍须实现相应的输入识别/意图产生和实际运动语义，不会仅凭配置条件字符串自动获得动作能力。

StateLibrary 现在只保存定义。resolve_selection() 直接建立索引，暂不做空 ID、重复 ID/路径预检；未知引用拒绝和库内引用边界继续保留。
