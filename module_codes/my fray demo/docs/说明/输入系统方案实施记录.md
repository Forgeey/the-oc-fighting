## 1. 已落地的执行链

```text
Loadout.resolve_selection() 成功
  → FighterInput.configure(controller, selection.moves, advancer)
  → 统一注册基础 bind、相对方向条件输入、世界对角、装备组合
  → 按兼容输入域合树；编译相对 command 的左右世界路径
  → 初始化现有状态机和原生 advancer；发布首份朝向

每个物理帧：
FrayInput(-100) → FighterInput(-50) → 状态更新(0)
  → 原版 advancer(25) → Fighter 普通推进及上下文收尾(50)
```

- 正式 `Fighter.tscn` 节点名称、数量、父子关系完全保留，只更换原有状态机节点的挂载脚本。
- 原生 Fray 插件的 197 个文件与本轮开始前的哈希一致；工作区原有 SequenceTree 修正保持不变。
- 转换库没有被本轮保存／改写；12 条移动推进条件和 4 条前置条件仍完整。

## 3. 对外行为和接口变化

### 3.1 转向

- `fighter.set_facing(-1)` 现在只登记请求；正常运行中 Fighter 在 priority=50 的帧末自动调用 publish_input_context。
- 当前攻击未完成时请求暂不提交；恢复完成或进入其他允许状态后生效。真正提交时同步输入朝向、Movement、精灵和判定 Manager。
- 离线测试若停掉了 Fighter 的物理回调，需要显式 publish_input_context() 模拟帧末，不等于正式代码应在任意时刻强制发布。
- 普通转向不重建 matcher、不清世界方向历史、不清 advancer 队列。命令在完成时按合法朝向解释；失焦、换设备、重配才清理会话。

### 3.2 指令配置

- SINGLE／COMBINATION 可设置 `required_direction=1..9`，0 为不限定；要求在触发按钮时满足相对方向。方向可以先按住，无需与按钮同帧。
- SEQUENCE 的作者 steps 仍使用相对 `dir_n`；编译层自动产生左右世界路径，不要求作者配置两份。实际方向事件不跟随转向改名。
- 同一兼容域的多条序列复用一个 FraySequenceMatcher；不同时间、负边或事件过滤需求拆域；同路完全冲突仍由作者消歧。
- 原生 `get_match_branch().duplicate()` 在匹配回调内关联来源；不改共享 Fray 事件。
- 当前运动对角采用同帧轴快照派生一个必要的世界方向变化；上下纯方向域保留独立按下／释放，明确支持下未释放再按上、同帧上下容错。这是薄归一化，不是第二套底层采样或重写序列算法。

### 3.3 缓冲

- 识别成功统一编码成 `game_cmd_<move_id>`，通过原生 advancer.buffer_sequence 入队；原生 FIFO、失败即丢、暂停继续计时和首个 true 后停止均未修改。
- **每招 command.buffer_frames 已移除。**唯一正式缓冲期限由 FighterInput.buffer_frames 统一换算到该角色 advancer.max_buffer_time；默认 6 个物理 tick 对应秒数配置。计时仍是原生墙钟，不承诺严格帧同步。
- 暂时不能执行的命令不会自动留到恢复结束重试；如要在动作期间排队，调用方需明确控制原生 paused，并接受统一期限会过期。
- resolve_delay_frames 仅作单键入队前的识别歧义等待，不是出招失败重试。所有权确认在入队前完成，入队后不改插件私有数组。
- 已删除 get_candidates／consume 等旧候选接口。`Fighter.advance_commands()` 只推进普通规则；原生 advancer 独立调用现有状态机节点的命令薄适配。

## 5. 尚未实现的范围

- 自动寻找对手／自动换边；本轮只落实合法朝向请求／提交机制，外部仍通过 set_facing 提出请求。
- 完整 dial-a-combo 局部路线、命中取消、资源扣除和每段窗口。原生 advancer 不自动具备这些业务。
- Fray 虚拟设备链修复、AI／回放／回滚、同键盘双人、按来源撤回已经入队的命令、每招独立重试期限。
- 特定游戏的全部指令优先级、任意前缀最长匹配；当前内容必须保持明确定义。

上述范围与方案的分期边界一致；本轮没有为了补它们去改 Fray 插件或增加节点。
