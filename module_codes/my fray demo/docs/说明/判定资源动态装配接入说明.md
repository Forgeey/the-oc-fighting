> **2026-11-10 运行状态已扁平化：**分类不再生成运行分组；当前使用 selected_state_names／entry_state 和 idle、light_attack 等直接名称，删除 group_start_states。根直接使用 FrayCompoundState，命令／普通边由 Fray 原生执行。以下旧层级、旧路径及跨层桥接描述仅作历史；最新接口与迁移范围见[扁平状态机迁移说明](扁平状态机迁移说明.md)。

> **2026-11-08 帧配置与命名更新：**Move 三阶段帧字段和 total_frames() 已移除；攻击状态通过 context Manager 读取 FighterAttackAttribute 并按窗口开关框。判定映射统一命名 hit_states；Fighter 的 _initialized 和重复兜底已删除，玩法时序判断保留。两份 Fray get_hitboxes 内部数组类型已做单行同步修复。具体接口、测试和历史说明替代范围见[攻击 Attribute 帧配置与 Fighter 精简记录](攻击Attribute帧配置与Fighter精简记录.md)。

> 2026-11-05 配置契约修订：判定定义必填、默认掩码非零；关闭姿态使用单次 clear_hit_state()，不再支持空定义或用零掩码隐式清理。Fray 插件和清理时的信号屏蔽保持不变。

## 1. 单一角色模板与装备时机

游戏计划只有一个角色，角色状态、招式、转换、动画等所有资源通过自定义装备的方式添加。不在对战中动态添加，在战斗前可以动态添加。

多个 Fighter 是同一模板的独立实例，不是另做多套角色脚本。战前先准备 Loadout，在 add_child(fighter) 前设置；当前生成时一次构建，切换行为只选择已装配姿态。已有角色进场后的 Loadout 修改不隐式触发重建，不提供对战热换装 API。

## 2. 当前节点结构

编辑时 Fighter.tscn 不包含 Manager。运行后默认生成：

```text
Fighter
├─ CollisionShape2D                 # 世界实体碰撞，位置和路径不变
├─ AnimatedSprite2D                 # 既有显示，不新增 VisualRoot
├─ FrayController
├─ FighterInput
├─ FrayStateMachine
│  └─ FrayBufferedInputAdvancer      # 仍暂停
└─ FrayHitStateManager2D             # Fighter._ready 内整体动态挂载
   ├─ Standing_0                    # idle/fwalk/bwalk 共用
   │  ├─ Hurtbox/CollisionShape2D
   │  └─ Pushbox/CollisionShape2D
   ├─ Crouch_1
   │  ├─ Hurtbox/CollisionShape2D
   │  └─ Pushbox/CollisionShape2D
   └─ LightAttack_2
      ├─ Hurtbox/CollisionShape2D
      ├─ Pushbox/CollisionShape2D
      └─ Attackbox/CollisionShape2D
```

节点序号仅用于角色场景树内唯一命名，随装配集合变化，不用它来查业务资源。框是姿态的直接子节点，Shape 是各框子节点。

## 3. 新增/编辑判定姿态

1. 创建根为 FrayHitState2D 的 .tscn，直接添加 FrayHitbox2D 及矩形 CollisionShape2D。
2. 每个框使用 FighterHitboxAttribute，明确 HURT、ATTACK 或 PUSH 用途；在场景中配置 CollisionShape2D 的 debug_color。Builder 不再遍历子节点补调试色。
3. 场景保存时 active_hitboxes=0，所有 Area2D 的 monitoring/monitorable=false；不要靠隐藏代替禁用。
4. 创建 FighterHitStateDefinition，填写 hit_state_scene 和非零 default_active_hitboxes；零掩码仍可作为场景初始停用值，但不是进入状态的默认值。
5. 每个状态定义都必须引用 hit_state_definition；状态必须登记在 StateLibrary，招式只保存 state_ids。多个状态可引用同一份判定定义，不复制重复几何。
6. Loadout 选中状态或装备依赖该状态的招式后，Builder 自动收集；不要把判定引用再复制到 Move。
7. 身体和各判定场景的 Shape 子资源必须设置 resource_local_to_scene=true；由 PackedScene 实例化保证独立，业务脚本不再调用 shape.duplicate()。

## 4. 三种“掩码/类别”不要混淆

- FighterHitboxAttribute.kind：框用途及允许检测关系。ATTACK→HURT、PUSH→PUSH，其余拒绝；同源过滤仍交给 Fray。
- collision_layer / collision_mask：Godot Area2D 物理筛选。当前 Hurt 第 2 层、Attack 第 3 层、Push 第 4 层，分别为位值 2、4、8；Attack mask=2，Push mask=8，Hurt mask=0 但可以被检测。
- active_hitboxes：姿态内按框位序的启用集合，不是碰撞层。默认 Attack 关闭，BasicAttackState 本轮不根据阶段自动开框。

几何是首版简单矩形，不声称已与每张动画精确对齐。Pushbox 的 Area2D 不会自动阻挡或推开 CharacterBody2D。

## 5. 初始化与生命周期

Fighter 战前调用一次 loadout.resolve_selection()，供状态机、判定和输入共用。FighterHitStateBuilder.build(states) 只接收解析后的状态定义数组，不读取 Loadout、招式库或 transition_library，也不调用 SMBuilder；仅保留共享判定定义的实例去重。完整子树离树组装后交给 Fighter；Fighter 先挂载，等同步原生 ready 完成再设置 source 和 facing，最后初始化行为树。

FighterState 基类负责状态进入时调用 fighter.select_hit_state(definition)，退出时 clear_hit_state()；具体状态需调用父方法，CrouchState 同时保留世界碰撞体恢复。动画也在基类进入回调中统一播放，每个状态的 animation_key 必填。

- 判定定义必填，进入状态使用非零默认掩码；不再将空定义或零默认掩码解释为无判定状态。
- select_hit_state：仅在初次进入或旧姿态已清理后调用，不再隐式清理旧姿态。状态机的旧状态退出负责配对清理。
- clear_hit_state：只对已选姿态调用一次，关闭区域监测、清零掩码、隐藏姿态并清空当前引用；之后须 select_hit_state 重新选择。
- set_hit_state_mask：只接受已选择姿态的非零掩码；完全关闭必须显式调用 clear_hit_state()，不再用 set_hit_state_mask(0) 或无当前姿态调用作为兜底。

清理时局部保存/屏蔽姿态信号再停用，避免原生 Manager 对零掩码通知重新 activate；随后恢复原信号屏蔽状态。Fighter 的 _current_hit_state 是实际选择状态，Manager 的最后名称不等于它还有启用框。

Manager.source 统一设置为当前 Fighter。不要在离树构建时指向已经在树内的角色，也不要在碰撞回调中直接切换姿态。当前节点只收集/转发接触，不连接扣血或受击逻辑。

## 6. 独立性与朝向

同角色相同判定定义去重；不同定义即使引用同一个 PackedScene 也有独立实例。身体和判定场景的 Shape 子资源均设置 resource_local_to_scene=true，实例化时获得独立可变资源，不污染共享库；Builder 不再手动复制 Shape。

所有判定场景按局部正 X 为前方制作，Fighter.set_facing() 只对 Manager.scale.x 做一次镜像；Sprite 延续当前 flip_h 约定，世界碰撞体不镜像。
