# 判定资源动态装配接入说明

> 2026-10-27。本轮实现战前装配、姿态选择/清理与镜像，不实现伤害、受击、推挤或攻击有效帧自动开框。

## 1. 单一角色模板与装备时机

游戏计划只有一个角色，角色状态、招式、转换、动画等所有资源通过自定义装备的方式添加。不在对战中动态添加，在战斗前可以动态添加。

多个 Fighter 是同一模板的独立实例，不是另做多套角色脚本。战前先准备 Loadout，在 add_child(fighter) 前设置；当前生成时一次构建，切换行为只选择已装配姿态。已有角色进场后的 Loadout 修改不隐式触发重建，不提供对战热换装 API。

## 2. 当前节点结构

编辑时 Fighter.tscn 不包含 Manager。运行后默认生成：

```text
Fighter
├─ CollisionShape2D                 # 世界实体碰撞，位置和路径不变
├─ AnimatedSprite2D                 # 既有显示，不新增 VisualRoot
├─ FrayController
├─ FighterInput
├─ FrayStateMachine
│  └─ FrayBufferedInputAdvancer      # 仍暂停
└─ FrayHitStateManager2D             # Fighter._ready 内整体动态挂载
   ├─ Standing_0                    # idle/fwalk/bwalk 共用
   │  ├─ Hurtbox/CollisionShape2D
   │  └─ Pushbox/CollisionShape2D
   ├─ Crouch_1
   │  ├─ Hurtbox/CollisionShape2D
   │  └─ Pushbox/CollisionShape2D
   └─ LightAttack_2
      ├─ Hurtbox/CollisionShape2D
      ├─ Pushbox/CollisionShape2D
      └─ Attackbox/CollisionShape2D
```

节点序号仅用于角色场景树内唯一命名，随装配集合变化，不用它来查业务资源。框是姿态的直接子节点，Shape 是各框子节点。

## 3. 新增/编辑判定姿态

1. 创建根为 FrayHitState2D 的 .tscn，直接添加 FrayHitbox2D 及矩形 CollisionShape2D。
2. 每个框使用 FighterHitboxAttribute，明确 HURT、ATTACK 或 PUSH 用途。
3. 场景保存时 active_hitboxes=0，所有 Area2D 的 monitoring/monitorable=false；不要靠隐藏代替禁用。
4. 创建 FighterHitStateDefinition，填写 hit_state_scene 和 default_active_hitboxes。
5. 在 StateLibrary 的目标状态定义中引用 hit_state_definition。多个状态可引用同一份定义，不复制重复几何。
6. Loadout 选中状态或装备依赖该状态的招式后，Builder 自动收集；不要把判定引用再复制到 Move。

当前框位序：Hurtbox=0、Pushbox=1、Attackbox=2（仅攻击姿态有第 2 位）。掩码 3 表示 Hurt+Push，7 才包含 Attack。增删、重排框时同步配置掩码；位序按 FrayHitbox2D 直接子节点计数。

## 4. 三种“掩码/类别”不要混淆

- FighterHitboxAttribute.kind：框用途及允许检测关系。ATTACK→HURT、PUSH→PUSH，其余拒绝；同源过滤仍交给 Fray。
- collision_layer / collision_mask：Godot Area2D 物理筛选。当前 Hurt 第 2 层、Attack 第 3 层、Push 第 4 层，分别为位值 2、4、8；Attack mask=2，Push mask=8，Hurt mask=0 但可以被检测。
- active_hitboxes：姿态内按框位序的启用集合，不是碰撞层。默认 Attack 关闭，BasicAttackState 本轮不根据阶段自动开框。

几何是首版简单矩形，不声称已与每张动画精确对齐。Pushbox 的 Area2D 不会自动阻挡或推开 CharacterBody2D。

## 5. 初始化与生命周期

FighterHitStateBuilder.build(loadout) 直接从 state_library/move_library、selected_state_paths/selected_move_ids 解析内容，不读取 transition_library，不调用 SMBuilder。完整子树离树组装后交给 Fighter；Fighter 先挂载，等同步原生 ready 完成再设置 source 和 facing，最后初始化行为树。

FighterState 基类负责状态进入时调用 fighter.select_hit_state(definition)，退出时 clear_hit_state()；具体状态需调用父方法，CrouchState 同时保留世界碰撞体恢复。动画调用仍在具体状态自己的播放时机进行。

- 空定义：进入后所有姿态关闭。
- 默认零掩码：允许装配场景，但进入时保持完全关闭。
- clear_hit_state / set_hit_state_mask(0)：关闭区域监测、清零掩码、隐藏姿态并清空当前引用；之后须 select_hit_state 重新选择。
- 非零 set_hit_state_mask：只修改已选择姿态的启用位，供后续攻击有效帧接入，不创建节点。

清理时局部保存/屏蔽姿态信号再停用，避免原生 Manager 对零掩码通知重新 activate；随后恢复原信号屏蔽状态。Fighter 的 _current_hit_state 是实际选择状态，Manager 的最后名称不等于它还有启用框。

Manager.source 统一设置为当前 Fighter。不要在离树构建时指向已经在树内的角色，也不要在碰撞回调中直接切换姿态。当前节点只收集/转发接触，不连接扣血或受击逻辑。

## 6. 独立性与朝向

同角色相同判定定义去重；不同定义即使引用同一个 PackedScene 也有独立实例。每个角色的 CollisionShape2D.shape 都复制为独立可变资源，不污染共享库。

所有判定场景按局部正 X 为前方制作，Fighter.set_facing() 只对 Manager.scale.x 做一次镜像；Sprite 延续当前 flip_h 约定，世界碰撞体不镜像。
