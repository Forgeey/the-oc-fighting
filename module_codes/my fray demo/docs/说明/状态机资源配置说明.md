# 当前版本：选择基础状态与固定指令招式

> **2026-10-26 实现更新：**默认 Loadout 已通过 MoveLibrary 装备 J 轻攻击；当前使用 selected_move_ids 和 required_state_paths，转换按端点及已装备 move_id 自动筛选。State/Move 不再包含 transition_ids，转换自身 transition_id 保留；当前约定见[招式参与角色构建方案](../方案/招式参与角色构建方案.md)“转换按端点自动装配”一节。
> 固定招式装配、输入节点、执行时序和现有限制见 [固定招式输入接入说明](固定招式输入接入说明.md)。

## 1. 结构与职责

> 招式库、Loadout 选招及状态机构建的目标调整见[招式参与角色构建方案](../方案/招式参与角色构建方案.md)。

> 2026-10-25 约定：每个特殊技固定方向序列＋指定按钮，不自动派生轻中重数值版本；默认每招独立完整叶子路径；执行协议相同的招式可复用同一脚本类和各自独立的脚本实例。普通起手／有效／恢复是叶子内部逻辑阶段，不机械生成三个状态。AnimatedSprite2D 负责显示，不使用 AnimationPlayer 节点；逻辑帧控制判定和结束。详见 [疑难解答](招式装配与判定时序疑难解答.md)。

```text
公共状态库 + 公共招式库 + 公共转换库
          ↓
FighterLoadout：所选状态路径、所选招式 ID、初始路径、分组默认入口
          ↓
FighterSMBuilder：创建固定分组、实例化所选状态、筛选并注册转换
          ↓
当前 Fighter 独立的运行时状态机
```

不再使用行为模块包装或单独的装配器。当前使用已修复复合状态生命周期的 Fray 插件，业务层不再提供入口兼容类，也不提供战斗中的 rebuild。


默认 Loadout 显式选择 idle、fwalk、bwalk、crouch，并通过 selected_move_ids 装备轻攻击、补入 action/basic_attack/light_attack。StateDefinition 只预留 hit_state_definition，当前不装配判定节点。

原 `fighter_states.tres`、`fighter_transitions.tres` 分别改名为 `state_library.tres`、`transition_library.tres`。不再需要 `base_movement.tres` 包装资源。

## 4. 状态库与角色选择

`FighterStateLibrary.states` 保存 `FighterStateDefinition` 数组，每条定义包括：

- `group_path`：所属固定行为组，根层用空字符串。
- `state_name`：组内状态名。
- `state_script`：继承 FighterState 的叶子脚本，支持无参构造。
- `animation_key`：该状态的动画语义，基本状态和招式状态统一在这里配置；空键表示不请求播放。
- `hit_state_definition`：可空判定定义引用，当前不读取。

状态定义不声明转换依赖；招式定义只声明入口、状态依赖和招式数据，公共转换库独立保存连接及条件。

完整状态标识为 `group_path/state_name`，例如 `neutral/idle`、`action/basic_attack/punch`；根层叶子直接使用状态名。

`FighterLoadout` 包含：

- `state_library`：可供选择的公共状态库。
- `transition_library`：候选转换库。
- `selected_state_paths`：角色选中的完整状态路径，不要重复填写。
- `move_library`：公共招式库。
- `selected_move_ids`：按 ID 选择完整固定指令招式；补入 `required_state_paths` 指定的状态，默认装备轻攻击，不自动生成轻中重版本或三阶段状态。
- `entry_path`：初次进入路径，默认 `neutral/idle`。
- `group_start_states`：分组默认直接子状态，未指定时按构建顺序选择第一个可进入的子状态。

构建器先为状态库建立路径索引，合并 `selected_state_paths` 和已选招式的 `required_state_paths`，再按最终路径顺序实例化所选状态，并在初始化前将只读 StateDefinition 绑定给实例的 state_definition。未选中的定义不创建运行时状态；库里必须存在被选择的完整路径。同组状态名必须唯一。

角色生成系统应在 `add_child(fighter)` 之前设置 `fighter.loadout`，因为当前在 `_ready()` 一次性构建。共享配置按只读使用，不在其中保存角色引用或计时。

## 5. 自动选择转换

转换库只在初始化时扫描一次，不每帧筛选，也不会自动生成库中没有的转换。

`from_state`、`to_state` 直接填写相对根的完整状态路径，转换没有 `group_path`。状态所属分组由状态定义的 `group_path` 提供。State 与 Move 不再维护 `transition_ids`；转换自身的 `transition_id` 仅作稳定标识，不参与筛选。构建器先建立最终状态和分组，再判断端点是否可用：

- 已选叶子：可用。
- 默认入口能够到达已选叶子的分组：可用。
- 未选叶子或空分组：不可用。

只有两个端点均可用，才选择该转换；带 `move_id` 的规则还要求该招式已装备。入选后绑定它在 `advance_conditions` 和 `prereqs` 中使用的条件，同组普通规则注册给 Fray，其余规则保留给现有 Fighter external 桥接。没有选中转换的条件不要求当前 Fighter 实现。

例如选择 idle、fwalk、punch 后，库中的 `punch -> kick` 因为 kick 未选中而不装入。

候选规则保留转换库数组顺序；同一对端点的多条规则和自身转换都会选入，不按端点或转换 ID 去重，也不枚举状态对生成新边。筛选依据是端点可用性及关联招式是否装备，不另设角色转换权限。使用同一转换库、最终状态集合及已装备招式集合的角色，将获得相同的候选转换；实际触发仍由活动源、输入候选、条件及完成模式决定。

条件映射仍是“条件名 -> 当前 Fighter 的无参数 bool 方法名”，支持 `!condition_name` 取反。只有入选规则才读取其条件映射。

## 6. 固定分组与默认入口

`FighterSMBuilder.GROUP_PARENTS` 保持写死：

```text
root
├─ neutral
├─ action
│  ├─ basic_attack
│  ├─ special_attack
│  ├─ composite_attack
│  └─ throw
└─ reaction
```

没有装备特殊技时，special_attack 仍存在，但不会因此选入指向空组的转换。

构建器自底向上选择默认入口，跳过不可进入的子组。`group_start_states` 的值必须是组内可进入的直接子状态，例如 `action -> special_attack`、`action/special_attack -> fireball`。

显式默认入口由配置作者保证正确；若指定了空分组，则不把对应父组标记为可进入，不会自动忽略显式设置改用其他子状态。

构建器直接使用原生 `FrayCompoundState`，不再创建 bootstrap 或使用业务入口兼容类。Fighter 调用 `state_machine.initialize(context, root, loadout.entry_path)`，一次进入真实目标；目标是复合状态时由插件补全默认叶子，显式深路径不会先进入其他默认分支。根的默认入口仍由上述分组配置确定，作为未显式传入入口时的默认值。

资源端点支持完整跨组深路径；Fray 原生 `add_transition()` 只处理直接子状态，所以 Builder 为同组普通规则推导父组并截取直接子名称，跨组规则继续由 Fighter external 桥接处理。本次不修改这两条执行路径。

## 7. 错误处理与资源边界

不恢复 `required`、错误收集或跳过规则日志。缺少未装备端点是正常筛选，不是错误。

构建器假设资源、路径、状态脚本和条件映射均有效，直接装配，不做合法性、指令冲突或入口预检，也不返回失败结果。动态招式分组由依赖路径建立；公共转换库中指向未装备端点的规则仍正常筛除。错误配置不属于当前构建器的处理职责，Fray 插件自身原有检查不变。

默认每招的 state_script 指向该招专用脚本，按完整路径去重，不按脚本文件去重，也不以相同路径后写覆盖实现装备差异。固定 command 和独立脚本是不同维度的选择，公共工具仍可复用。

只创建所选状态的运行对象，不代表资源库中其他脚本不会被加载。状态库和转换库可以被多个角色共享，运行时状态与转换实例仍各自创建。

## 8. HitState 与运行验证

保留独立的 `FrayHitStateManager2D`。行为状态树不从 HitState 节点推断层级，也不自动创建或激活判定节点。

已增加可复现的 Godot headless 集成测试，运行方法见接入说明。基础验收包括：

1. Arena 初始播放 idle，D/右方向进入 fwalk，松开返回 idle。
2. 角色只选择 idle 时，不装入行走状态和行走转换。
3. special_attack 存在但为空时，不选入指向它的转换。
4. basic_attack 留空、special_attack 有实际叶子时，action 默认入口选择可进入的子组。
5. 使用不同分组的同名状态时，按完整路径正确区分。
6. 多个 Fighter 共享相同资源时，运行时状态对象彼此独立。

## 招式发动转换（2026-10-26）

Move 保留 entry_path/required_state_paths，不再包含 allowed_from_paths 或 switch_mode。所有来源许可与转换模式由 TransitionLibrary 的规则表达：规则 move_id 为空时为普通转换；非空时必须由对应招式候选触发。所有规则统一填写完整 from_state/to_state，不再配置转换 group_path；同组普通转换由 Builder 推导注册组，普通跨组和招式转换交给 Fighter 的完整路径执行桥接。轻攻击只配置 idle/fwalk/bwalk 三个来源，均要求 grounded；未配置来源不能发动，也不会因 auto_advance=false 就不检查业务条件。详情见[构建方案第 11 节](../方案/招式参与角色构建方案.md)。


## 默认转换条件与无输入稳定性（2026-10-26）

默认转换库现已补齐条件。自动移动边必须按目标意图填写 inputed_crouch、inputed_fwalk 或 inputed_bwalk；空条件数组表示没有限制，不表示禁止转换。基础状态默认完成，AT_END 也不会等待动画播放。

每个来源先配置具体目标边，最后配置返回 idle 的边，返回条件为源意图取反（例如 fwalk → idle 的 !inputed_fwalk）。这样既能稳定保持持续输入，也能在目标动作未装配时回退 idle；不要把返回条件改成所有方向都释放。当前 Fray 按注册顺序检查规则，本配置不依赖 priority。

轻攻击发动边使用 prereqs=[grounded]；action → neutral 使用 prereqs=[active_leaf_done]。招式候选要求、AT_END 和 Fighter external 桥接未改变。

运行 `tests/neutral/run_headless.py --suite resources --godot <Godot控制台程序路径>` 可验证真实默认资源；该测试不替资源补条件，隔离输入采样，不代表独立的 Fray ispressed 输入错误已修复。完整说明及结果见构建方案末尾“默认转换资源条件修复”。


## 状态动画与自定义表现预留（2026-10-27）

基本状态不再在脚本写死动画，攻击状态也不再读取 Move.animation_key；所有叶子由 StateDefinition.animation_key 配置，并在自己的进入逻辑调用 play_state_animation()。具体播放时机由执行脚本决定，不在基类中自动播放。资源中已配置 idle/fwalk/bwalk/crouch/light_attack。

统一链路是 StateDefinition → FighterState.play_state_animation() → Fighter.play_animation() → _resolve_animation_key() → AnimatedSprite2D.play()。解析函数当前只原样返回 key，尚未实现角色映射资源、换装、分部件动画或战斗中修改配置。初次装配前可以提供不同只读状态配置；不要修改多个角色共享的状态库来实现单角色换皮。

详见[状态动画配置说明](状态动画配置说明.md)。


## 自动转换问题复查（2026-10-27）

本轮复查确认实际转换资源里的条件再次缺失，而不只是文档没有同步。现已在 transition_library.tres 恢复输入/接地/完成条件。condition_methods 只提供条件名到方法的映射，存在映射并不表示规则自动引用它；每条边仍需显式填写 advance_conditions 或 prereqs。

当发生 idle/crouch/fwalk 循环时，应先检查运行场景实际引用的转换库中是否仍保存条件，不要把 MANUAL、AT_END 或 auto_advance=false 当作禁用普通边的开关。保持具体目标优先、idle 返回最后的数组顺序，也不恢复 transition_ids。

BasicAttackState 的文件名现为 action/basic_attack/basic_attack_state.gd。对应状态资源仍是 action/basic_attack/light_attack，数字招式 ID 和动画键不随脚本改名而改变。
