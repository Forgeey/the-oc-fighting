# 状态机资源配置说明：容器式装配

> 2026-11-11 当前实现：状态和转换没有父组字段，也没有分类字段。复合定义直接持有子状态与内部边；实际运行组仍使用原生 FrayCompoundState。已修正的插件递归等待子状态完成，父自然出口直接用 AT_END。

## 1. 角色默认结构

~~~text
root : FrayCompoundState
├─ idle
├─ fwalk
├─ bwalk
├─ crouch
└─ light_attack
~~~

默认五个动作同根。Fighter.tscn、原生 FrayStateMachine、FrayBufferedInputAdvancer、FighterInput 及单 Matcher 均保持原节点结构。组是运行 Resource，不是新增场景 Node。

## 2. 叶子定义只描述自己

FighterStateDefinition 现在只有五个导出字段：

| 字段 | 用途 |
| --- | --- |
| state_id | 库内唯一十位身份，装配时按此解析权威定义 |
| state_name | 库内唯一动作名，基础选择与转换直接端点使用 |
| state_script | 可无参创建的 FighterState 派生脚本 |
| animation_key | 有效动画语义，进入时由基类播放 |
| hit_state_definition | 本叶子的判定姿态 |

叶子没有父组引用，同一个静态定义可被根或多个局部组使用；每个放置位置创建独立运行状态。定义资源不保存当前角色、计时或活动父节点。

## 3. 复合定义直接拥有内部图

FighterCompoundStateDefinition：

~~~gdscript
@export var state_name: StringName
@export var start_state: StringName
@export var states: Array[FighterStateDefinition] = []
@export var transitions: Array[FighterTransitionDefinition] = []
~~~

例如 combo1：

~~~text
state_name = combo1
start_state = B
states = [B定义, C定义, D定义]
transitions = [B到C规则, C到D规则]
~~~

组的 states 是直接成员引用，不是执行顺序。实际起点只由 start_state 决定，后续次序只由转换决定。叶子引用按 state_id 解析到角色 StateLibrary.states；组引用按 state_name 解析到 StateLibrary.compound_states。

状态库登记所有叶子与组，声明“有哪些定义”；组容器声明“本组包含谁”。不通过扫描叶子的反向归属字符串推导组，也不按目录建组。当前只支持根下的一层局部组，组的 states 为叶子数组，不自动推导任意深度嵌套。

## 4. 转换属于哪个容器

转换只描述 transition_id、command、from_state、to_state、prereqs、advance_conditions、auto_advance、switch_mode、priority。端点是存放它的容器的直接孩子。

| 存放位置 | 规则示例 | 运行注册处 |
| --- | --- | --- |
| TransitionLibrary.transitions | idle→light_attack | root |
| TransitionLibrary.transitions | light_attack→combo1 | root |
| TransitionLibrary.transitions | combo1→idle | root |
| combo1.transitions | B→C、C→D | combo1 |

不再对每条规则填写父组名。不要把 B→C 放进根转换库后希望 Builder 自动猜到 combo1。即使根也有叫 B/C 的独立状态，组规则也只注册在其容器中，不泄漏到根。

所有层仍共用 TransitionLibrary.condition_methods 的角色方法映射；Builder 在当前 owner 显式绑定该容器规则的 prereqs／advance_conditions，不依赖根条件继承。inputed_ 仍由通用输入查询绑定。

## 5. Loadout 和 Move 的选择

~~~text
selected_state_names = [idle, fwalk, bwalk, crouch]
selected_move_ids = [01010001]
entry_state = idle
~~~

Move.state 仍只有一个静态引用：

- 引用叶子定义：直接装配到 root。
- 引用复合定义：装配该组 states 中全部叶子与 transitions 中内部边。
- 单独选中 B，不会因为某个组也引用 B 就自动选入该组。
- 同时选中根 B 与 combo1：创建 root/B 和 root/combo1/B 两个运行实例，允许共享同一静态定义。
- 选择组不自动装备子招式或其指令；输入只注册 selection.moves 的命令。

selection 区分：

| 输出 | 含义 |
| --- | --- |
| root_states | 直接放置到根的已选叶子 |
| compound_states | 已选复合定义 |
| states | 全部根／组依赖的权威叶子定义去重并集，供判定装配等系统使用 |
| moves | 明确选装的招式，供输入注册 |

不能把 states 并集再次全部挂到根；组成员与根位置不同。

## 6. Builder 注册过程

1. root_states 创建根叶子；每个组根据自己 states 创建独立子状态，设置 start_state，挂到 root。
2. 根转换库只给 root；各复合定义的 transitions 只给对应组。
3. 每个容器分别筛除未装配端点，给入口边私有副本合入 Move.prereqs；共享数组和资源不改写。
4. command 非空编译为 FrayInputTransitionSequence；普通边编译为 FrayStateMachineTransition。
5. 各容器分别按命令边优先、priority 小者优先、同值资源顺序注册。

命令运行边 auto_advance=true 只为启用 Fray.advance_conditions 检查；accepts 仍要求对应 sequence，不会空输入自动攻击。输入失败后允许普通移动回退，缓冲器仍沿用原生逻辑。

## 7. 多出口组合技与父收招

~~~text
root：
  A → combo1（合法后续命令，进入 B）
  A → idle（AT_END）
  combo1 → idle（AT_END）
combo1：
  B → C（合法后续输入／取消条件）
  C → D（合法后续输入／取消条件）
~~~

combo1 不设 end_state、不加 done。BasicAttackState 完整恢复后报告完成，插件递归等待当前子状态；父边 auto_advance=true、switch_mode=AT_END、prereqs 留空即可。没有父出口边或没有 advance，不会自动退出。

组内合法接续优先于父收招，IMMEDIATE 取消仍按自己的条件授权。未来若增加合法待提交后续，需另加业务条件；成员装配也不等于独立路线的连接授权。

## 8. 迁移、目录与边界

状态脚本在 scripts/states/fighterstates/；状态定义在 resource/states/；判定定义与场景分别在 resource/combat/hit_states/ 和 scenes/combat/hit_states/。不恢复分类目录。

默认资源没有局部组内容，因此无需重写已有五个状态或根转换库。新增组合技时，在 Inspector 的复合定义里添加 States／Transitions 即可，不在叶子或规则上重复填写归属。

本轮不修改 Fray 插件、动作帧数或场景节点。现有递归完成修复、Move 单入口、单 Matcher 与世界历史行为保留。
