# 统一 HitboxAttribute 与 Matcher 简化边界

> **2026-11-09 单 Matcher 已实施：**每角色仅一个 FraySequenceMatcher，由 Fighter 构建时调用 FighterInput.configure 配置并存于 FighterInput.matcher。三个指令辅助函数已合并为 create_branch(facing)，旧的兼容域分组已移除；前后条件输入转向不重注册，世界历史和完成朝向规则保留。旧描述以[单角色单 Matcher 接入记录](单角色单Matcher接入记录.md)为准。本轮不新增节点、不改插件、不添加配置兜底。

> 2026-11-09。Attribute 合并已经实施；下述指令／Matcher 简化是架构说明，不表示本轮改变了跨转向输入规则。

## 1. 已合并为一个 Attribute

删除 fighter_attack_attribute.gd 及 UID。startup_frames、active_frames、recovery_frames、total_frames()、is_active_at(frame) 合入原有 FighterHitboxAttribute。

- kind=ATTACK 才使用时间窗口；HURT／PUSH 的 total_frames() 返回 0，is_active_at 始终 false。
- BasicAttackState 按“类型为 FighterHitboxAttribute 且 kind=ATTACK”收集框，不能仅检查是否使用同一个脚本，否则 Hurt／Push 也会被当成攻击框。
- 各框独立窗口、最长恢复决定动作完成、退出清框、计时留在状态实例等规则不变。
- 轻攻击场景 Attackbox 改用原有 attribute 脚本，保留 kind=1 和显式 10／4／10 帧。Hurt／Push 原配置不变。
- 所有运行脚本、场景、测试中的旧派生类型引用已移除，未保留兼容别名。Fray 插件本轮未修改。

## 2. 玩家身份、初始站位和当前朝向不同

“P1 默认左、P2 默认右、招式按面朝右编写”是良好的作者约定，但不自动限制后续位置。如果角色可跳过、瞬移或交换位置，前后必须依赖本角色当前合法朝向，不能依赖 P1/P2 或是否 CPU。

若确定整个游戏永远不换边、P1 永远朝右、P2 永远朝左，则方向映射只需初始化一次。若只是开局如此，运行时朝向机制仍有必要。当前没有自动寻找对手系统，不能因为作者约定就声称已实现 P2 站位或 CPU 控制。

## 3. 什么时候可以把三个函数减到一个

如果采用“条件输入已经给出相对前后，序列只解释输入发生当时的前后”的规则，可以直接用 command.steps 构造一个 FraySequenceBranch：

- get_world_steps 可删除，不再编译左右世界路径。
- create_world_branch 可改为 create_branch()，只附加间隔、蓄力和 negative edge 参数。
- 若所有序列使用统一事件域和歧义规则，get_sequence_domain 可删除，所有命名分支放入该角色同一棵树／Matcher。

这不是不能实现，也不是玩家二必须另写一套招式。关键是需要明确改变现行跨转向规则：逐事件的相对前后不会在将来转向时自动重新解释。条件输入只影响后续输入状态，不替 Matcher 改写旧历史。

现行已选规则是“保留世界历史，按最后一步时朝向判断整条指令”。例如原先朝右时输入世界下→左下，随后朝左再输入左＋攻击，整条世界 214 在完成朝左时是向前指令。若前两步已固化为当时的下→后下，简单相对前后 Matcher 就不等价。

因此本轮合并 Attribute，但不悄悄删除世界路径编译。可以选择另一种更简单的输入语义，只是必须作为明确行为改变，并调整相应测试，而不是声称改用 ConditionalInput 后旧规则自然保持。

## 4. 一个角色一个 Matcher 是可行的默认目标

FraySequenceMatcher 原生支持一树多个命名序列，并不是每个招式都需要独立实例。现在的“兼容域”是项目适配选择，不能当成插件必需。

单一 Matcher 可行的条件：

1. 所有指令接受同一套规范化事件；一事件送入一次，不能把同一斜方向重复喂成下、前、斜下前。
2. 不同指令不再有“某组忽略 jump／crouch、另一组把它当步骤”等不同过滤需求，或这些差异已统一进规则。
3. 上下同帧容错使用一致顺序；不能同时为两条相反指令要求不同排序。
4. 相同输入路径／终点不能用两个名字表达冲突规则；完全同指令应共用一个 command，让转换条件决定走哪条边。

不同完整路径可以各自保存不同 max_delay、蓄力等分支要求，**单纯时间数值不同不要求拆 Matcher**。当前 get_sequence_domain 把时间、负边、别名和垂直域一起作为分组键，是保守实现，可在统一规则后简化；不应该为了未来可能有的指令一直扩大分组。

当前最具体的差异是：普通 motion 去重为单一九宫格快照，而下未松再按上必须保留两个独立事件。把两路流无脑都广播给同一 Matcher，会出现重复步骤／额外按下打断；合成统一事件流并通过这两类回归后即可去掉这部分分域。多角色仍各自一个实例，不共用输入历史。

即使保留“世界历史＋完成朝向”规则，也可另外推进一个 Matcher 的统一事件设计；它和是否使用相对方向是两个独立取舍，不要把二者绑为同一开关。
