# 复合状态完成、退出与条件作用域

> 2026-11-11 容器式装配更新：叶子和转换不再保存父组字符串；FighterCompoundStateDefinition.states／transitions 直接持有成员与内部边，TransitionLibrary.transitions 仅持有根边。组内归属由资源放在哪个容器决定，详见[状态机资源配置说明](状态机资源配置说明.md)。旧字段说明及示例已删除，不提供兼容别名。

> 2026-11-11 最新实施：在根目录与 Demo 两份 Fray 中同步修正复合状态完成语义；组递归等待当前子状态。自然收招直接使用父边 AT_END，删除 Fighter.active_leaf_done 及对应资源前置条件。不新增 done、组子类或场景节点。此前“父出口另读叶子完成”方案已被本次插件修复替代。

## 1. 上游 #54／#55 修复了什么

Issue #54（RootState Transition At_End）指出两个旧问题：

1. AT_END 错查管理转换的 RootState 自己，应该查当前被离开的子状态。
2. 旧 _goto 错误退出目标，应该退出当前状态，再进入目标。

对应 PR #55 于 2023-05-24 合并。本次已重新读取 issue、PR 合并记录和上游 main。当前项目的 _can_switch 本来已经检查当前子状态；当前 _goto 则委托给支持层级生命周期的 _transition_to，早已不是 issue 中那个退出目标的旧实现。因此不把相同修复重复套到现有代码，也不使用旧的单层函数替换现有跨层生命周期。

上游 main 的组完成仍为：

~~~gdscript
return _end_state.is_empty() or _current_state == _end_state
~~~

它不等待子状态，所以 #54 的正确 _can_switch 仍可能查询到一个“刚进组就完成”的默认复合状态。**此次真正增加的是组自身的递归完成判断，不是声称只重贴 #54 就能解决多出口。**

## 2. 两份插件的实际补丁

文件：addons/fray/src/state_mgmt/state/compound_state.gd，根目录与 Demo 副本内容完全一致。

~~~gdscript
func _is_done_processing_impl() -> bool:
    var current := get_current_state()
    return (
        current != null
        and (_end_state.is_empty() or _current_state == _end_state)
        and current.is_done_processing()
    )
~~~

| 情况 | 完成结果 |
| --- | --- |
| 没有当前子状态 | false，不把未进入／空组当作执行完毕 |
| 未设置 end_state | 当前子状态完成才为 true；子状态是组时继续递归 |
| 设置 end_state=D，当前是 B/C | false，即便 B/C 已完成 |
| 当前进入 D，但 D 尚未完成 | false，不再只凭进入末状态就提前结束 |
| 当前是 D，且 D 完成 | true |

_can_switch 保持正确检查对象，改为调用公开查询：

~~~gdscript
and get_current_state().is_done_processing()
~~~

FrayState.is_done_processing() 本来就调用虚方法 _is_done_processing_impl()；不是第二套完成算法。IMMEDIATE 逻辑不变，仍可由合法取消条件授权跳过剩余恢复。

## 3. _goto 为何不改成旧版单层函数

当前 _goto 只有：

~~~gdscript
func _goto(path: StringName, args: Dictionary = {}) -> void:
    # The shared lifecycle path exits the old active branch, never the target.
    _transition_to(path, args)
~~~

_transition_to 先求旧活动链和新入口链，保留共同祖先，再逆序退出旧分支，正序进入新分支。

~~~text
idle → combo1（start=B）：idle.exit → combo1.enter → B.enter
combo1/B → combo1/C：B.exit → C.enter，combo1 保持活动
combo1/C → idle：C.exit → combo1.exit → idle.enter
~~~

没有在进入目标之前调用目标 exit。无需再写 get_state(_current_state)._exit_impl() 与之重复清理，否则可能退出两次。

旧版单层改法本身方向正确，但不处理当前已有的深路径、默认叶子、共同祖先和 external self-transition；直接替换会退化。保留既有实现，仅加说明和专门回归。

## 4. A／AB／ABC／ABCD 的配置

~~~text
root : 原生 FrayCompoundState，start=idle
├─ idle : FrayState
├─ light_attack A : BasicAttackState
└─ combo1 : 原生 FrayCompoundState，start=B，end_state 不设
   ├─ B : BasicAttackState
   ├─ C : BasicAttackState
   └─ D : BasicAttackState
~~~


组定义的 states=[B定义,C定义,D定义]，transitions=[B→C,C→D]；根的 A→combo1／combo1→idle 在 TransitionLibrary.transitions。叶子和规则不保存父组字符串，运行父对象由容器 add_state 时确定。

B/C/D 继续复用现有攻击完成协议：

~~~gdscript
func _is_done_processing_impl() -> bool:
    return elapsed_frames >= total_frames()
~~~

total_frames 来自当前判定姿态的攻击 Attribute。叶子完成沿活动组递归传播，不再需要 Fighter 的额外叶子完成条件。

## 5. 转换列表

| owner | from→to | 规则 |
| --- | --- | --- |
| root | A→combo1 | 后续输入＋合法连接条件；进入默认 B |
| root | A→idle | AT_END，auto_advance=true，无重复完成前置条件 |
| combo1 | B→C | 后续输入＋本组连接条件；取消时可用 IMMEDIATE |
| combo1 | C→D | 后续输入＋本组连接条件；取消时可用 IMMEDIATE |
| root | combo1→idle | AT_END，auto_advance=true，无重复完成前置条件 |

父出口资源填写：

~~~text
from_state = combo1
to_state = idle
switch_mode = AT_END
auto_advance = true
prereqs = []
~~~

普通 API 等价配置：

~~~gdscript
var leave := FrayStateMachineTransition.new()
leave.switch_mode = FrayStateMachineTransition.SwitchMode.AT_END
leave.auto_advance = true
root.add_transition("combo1", "idle", leave)
~~~

- B 不接 C：B 完整恢复，combo1 随之完成，父边退出，得到 AB。
- C 不接 D：同理得到 ABC。
- D 完整恢复：得到 ABCD。
- A 没进入组合组：A 完整恢复，经自己的 A→idle 边退出，得到 A。

没有唯一 end_state，也没有空 done。当前子组规则优先：合法 B→C 与父自然出口同时可用时，先执行内部接续。

## 6. 完成不是自动退出

必须保留 combo1→idle 转换，并经 advance 推进。没有边，即便叶子／组返回 true 也留在原活动链上，不自动弹回父级，不自动寻找 idle。

根是否完成也是一次查询，不意味着根节点停止处理。IMMEDIATE 打断／特殊取消仍由自己的条件控制，不需要等自然恢复结束。

## 7. 条件 owner 与未来 pending

组完成已由插件负责，但命令许可、命中、捕获、资源与取消窗口仍是业务条件。全部在实际 owner 显式绑定，不新增根条件继承，也不修复与本任务无关的否定回退逻辑。

当前没有局部 pending／route_session。若未来认领了合法后续、打算延迟提交，父边应额外加“无有效待提交后续”等业务条件；插件只知道状态处理是否完成，不能猜测未提交输入或路线授权。

Fighter.get_active_leaf() 仍保留给转向权限：组不是 FighterState，不能直接 cast 根孩子后调用 can_update_facing。Fighter.active_leaf_done() 和对应条件方法映射已删除。

## 8. 兼容性与验证

这是本项目对 Fray 完成语义的有意变更，不是所有上游版本已有功能：依赖“空 end_state 永远 true”或“进入 end 就 true”的旧用法，需要迁移；循环／等待叶子返回 false 时，父 AT_END 会继续等待，travel 同样会等待。is_persistent 仍保留历史选择；它查询保留子状态，重新进入时叶子 enter 重新初始化进度。

插件层测试：tests/input/test_fray_compound_lifecycle.gd，覆盖未初始化、叶子 AT_END、递归组、可选 end_state、IMMEDIATE、travel、persistent、默认进入、显式深路径、self-transition 与旧／新分支退出顺序。

项目层测试：tests/input/test_compound_exits.gd，覆盖 A／AB／ABC／ABCD、单个复合 Move 的同一真实按键连续接段、转向、资源保存重载；父出口不配置额外完成条件。

测试入口：tests/movement/run_headless.py --suite lifecycle / compound / resources。默认场景节点不变，主场景也参与隔离冒烟。
