# 自定义角色选招约束与战前装配边界

> 2026-11-05 讨论记录。招式直接引用状态定义、统一选择解析、动画必播和 Fray 索引修复已实现；冲突表、解锁树、选招 UI 和双设备双人场景仍是后续设计，不表示已经制作。

## 1. 输入注册不是招式冲突检测

FrayInputMap 是全局映射。两个自定义角色可以注册相同逻辑动作、相同组合键；has_input() 防止重复创建同名映射，不判断两招是否能同时装备。

FrayController 原生导出 device 和 disabled，没有 prefix 字段。device 只有在底层绑定实际按设备读取时才能隔离来源；当前 demo 的 FrayInputBindAction 使用 Input.is_action_pressed(action) / Input.get_action_strength(action)，忽略传入的 device。不能据此声称只改两个 Controller.device 就完成双人隔离。

p1_/p2_ 可作为玩家动作命名空间，但必须配套独立的 Godot Action/物理绑定，并在业务输入适配层统一完成注册、读取、组合输入和事件名过滤/还原。共享招式的 command 仍用 light_attack 等逻辑名，不把玩家前缀写进招式或状态资源。原生 Controller 不能直接填写字符串前缀；未来可用业务包装或子类接入。本轮未实现这套适配，也未修改输入插件。

has_input() 是注册幂等检查，不是设备数量检查；即使有前缀，重生/重新配置同一个 p1 仍可能重复注册，不能用前缀直接替代。冲突约束只作用于同一个角色的装备集合，不应禁止另一角色使用相同指令。

## 2. 拟采用的冲突数据（未实现）

可用独立 .tres 保存 move_id 到互斥 move_id 集合的索引。玩家选择新招时查询该招的冲突集合，并在当前角色的已选 ID 集合中查找；不需要现场解析各招 command，也不需要对已选招式做两两指令比较。

冲突数据应保持对称，招式指令或有效来源变化后由内容制作流程同步更新；可在离线工具/测试中校验，不恢复战斗运行时的全量配置预检。

仅字符串相同或共享前缀不一定冲突。比如同一指令在互斥地面/空中来源使用，或序列与普通单键由已定义的输入归属规则区分，都需要设计时决定是否互斥。第一版可保守限制同角色装备，不把未来语义全部写进运行时 Builder。

## 3. 解锁树与当前装备分离（待确认具体规则）

前置招式关系用于决定某招能否解锁/选择，不属于状态机装配依赖。选招层输出最终 selected_move_ids 和 selected_state_paths；运行层只使用这个结果，不递归选入前置招式。

## 4. 当前已实现的装配

```text
最终 selected_move_ids + selected_state_paths
    ↓ FighterLoadout.resolve_selection()（每个角色战前一次）
已选 MoveDefinition + 去重 StateDefinition
    ├─ FighterInput 配置指令识别
    ├─ FighterSMBuilder 创建运行状态与转换
    └─ FighterHitStateBuilder 创建判定姿态
```

FighterMoveDefinition 保存 state_ids: Array[StringName]，不携带状态定义资源。第一项是入口，其他 ID 仅表示装配状态；数组顺序不生成转换或自动连招。每个 state_id 必须由当前 StateLibrary 解析，库外状态不会被装配。

状态定义仍存为 resource/states/ 下独立 .tres，由状态库统一登记。十位状态 ID 采用“招式八位 ID + 两位序号（00 起）”，非招式使用 00GGNNNNII；详见[命名规范](../方案/命名规范.md#3-身份名称与状态路径)。状态 ID 不是库数组下标，调整目录顺序或状态路径不改变它。

resolve_selection() 在本地直接建立状态 ID/路径索引，已删除 create_id_index()，暂不检查空 ID、重复 ID 或重复路径；配置正确性由内容作者保证。未知引用和无入口招式仍会拒绝，失败不返回部分装配结果。Fighter 收到失败后不挂载判定或状态机，并停用相关处理。基础状态路径也只能从同一个库取得定义。不存在外部资源回退通道。

状态库白名单不等于防作弊：若玩家可篡改本地目录和脚本，或者把另一合法状态 ID 写入招式，单纯查库无法验证内容与授权。未来联机要由可信权威端校验目录版本和装备权限，本轮未实现联网安全机制。

prereqs 是战斗发动条件，不是解锁条件。地面、资源、完成状态等条件即使已在选招阶段通过冲突/解锁校验，战斗时仍会变化，不能一并删除。

解析器不创建运行节点，也不缓存角色进度。两个 Builder 不再分别建立状态/招式索引或合并依赖。共享判定定义仍只创建一个实例，例如 idle/fwalk/bwalk 共用站立判定。

## 5. 动画与插件修复

所有 FighterState 进入时统一播放必填 animation_key，具体状态调用 super(args) 即可，不再判断空键或重复调用播放。未制作素材先使用有效占位动画；不提供自动 fallback。

只修复根目录和 demo 自带 Fray 的 sequence_tree.gd 两个索引判断：0 <= index < size。保留错误提示、空值返回和其他插件行为；clear_hit_state() 的信号屏蔽绕行保持不变。

索引回归入口：

```powershell
python tests/movement/run_headless.py --godot <Godot控制台程序路径> --suite sequence
```

覆盖合法首/中/末分支、移除及负数/等于长度/超过长度/空数组越界。八条 Index out of range 日志是专门测试拒绝非法索引的预期结果；测试启动器仅为该套件精确核对这八条，不忽略其他错误。
