# My Fray Demo：角色装配、状态与运动

> 2026-11-11：叶子和转换只描述自己，不保存父组字符串或分类。复合定义直接持有 states／transitions。当前字段详见[状态机资源配置说明](状态机资源配置说明.md)。

## 1. 战前装配

~~~text
Loadout.resolve_selection()
  ├─ root_states：直接放置在根的叶子
  ├─ compound_states：明确选择的复合定义
  ├─ states：根和组的全部权威叶子定义去重并集
  └─ moves：真正选装的招式
      ↓
HitStateBuilder：按 states 的姿态建立本角色 Manager
SMBuilder：按根／各组的直接成员和边创建原生状态树
FighterInput.configure：只注册 moves 的命令，角色一个 Matcher
      ↓
原生 FrayStateMachine.initialize
~~~

同一 Fighter 模板可以生成多个独立角色。战前确定装配内容，对战中只切换已有状态与姿态，不动态添加招式。静态资源可共享，运行状态、计时、输入历史和判定节点按角色独立。

## 2. 默认状态与局部流程

默认 Demo 根直接包含 idle、fwalk、bwalk、crouch、light_attack。多段内容按实际业务声明局部组：

~~~text
root
├─ idle
├─ A
└─ combo1 : 原生 FrayCompoundState，start=B
   ├─ B
   ├─ C
   └─ D
~~~

combo1 的 states=[B定义,C定义,D定义]，transitions=[B→C,C→D]。根 A→combo1、combo1→idle 等边放在 TransitionLibrary.transitions。归属由容器决定，不由叶子、转换或磁盘目录反向指定。

同一静态 B 可以同时放到根和不同组，各位置创建不同 FrayState 实例。一个运行实例仍只能有一个父对象。

## 3. 招式、身份和入口

| 配置 | 含义 |
| --- | --- |
| state_id | 库内稳定十位叶子身份 |
| state_name | 库内唯一动作名；基础选择与直接端点使用 |
| Move.state 引用叶子 | 将此动作放到根 |
| Move.state 引用组 | 装配组及其全部直接成员与内部边 |
| Compound.start_state | 默认直接子动作，不由成员数组顺序推导 |

选择叶子不会自动选入引用它的组；选择组不会自动装备子招式或注册它们的输入。静态依赖去重与运行位置是两件事。

## 4. 执行职责

- FighterState 从 context 取组件，进入时选择姿态、播放配置动画，退出时清姿态。
- BasicAttackState 从当前姿态攻击 Attribute 读取逻辑帧与窗口，不从 Move 获取帧数。
- FighterMovement 负责运动计算和碰撞移动，不维护第二套行为状态机。
- 原生 CompoundState 管活动子状态、直接转换和生命周期；插件已递归等待子状态完成。
- FighterSMBuilder 创建各容器的运行实例，注册自己的边与本地条件。
- Fighter 准备组件、推进状态、帧末发布转向；get_active_leaf 只用于实际动作权限查询。

组内合法接续优先于父自然退出。父 combo1→idle 用 AT_END 等待当前段完整恢复；不设唯一 end_state，不增加 done。完成只是一项许可，必须有边和 advance 才真正退出。

## 5. 文件与节点

执行脚本平铺在 scripts/states/fighterstates/，状态定义在 resource/states/；判定定义和场景分别在 resource/combat/hit_states/、scenes/combat/hit_states/。没有动作分类目录，也不按文件位置生成运行树。

本轮保留 Fighter.tscn、原生 FrayStateMachine／FrayBufferedInputAdvancer／FighterInput 的节点结构和既有插件修复。输入仍为单 Matcher、世界方向历史及原生缓冲逻辑。

## 6. 未实施范围与验证

容器和多出口机制已实现，默认角色仍只有基础移动和轻攻击内容。完整组合技路线授权、局部 pending、投掷捕获和其他运动业务仍另行实现，不能把装配成员当成连接权限。

测试入口为 tests/movement/run_headless.py。compound 验证容器与多出口，lifecycle 验证插件完成／退出，resources 验证编辑器及新运行进程保存重载。
