# 项目命名规范

> 最终版：项目业务代码及新增资源统一遵循本规范。Fray 插件、Godot 内置接口及其覆写方法保持原名。

## 1. 基础格式

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录、脚本、场景、资源文件 | 英文 `snake_case`；目录按职责命名 | `state_machine/`、`fighter_loadout.gd`、`fighter.tscn` |
| 类、节点名 | `PascalCase`；约定的首字母缩写保持大写 | `FighterState`、`HitFX`、`HitSFX` |
| 函数、变量、参数、信号 | `snake_case` | `build()`、`state_path`、`attack_finished` |
| 常量、枚举成员 | `UPPER_SNAKE_CASE` | `GROUP_PARENTS`、`AT_END` |
| 枚举类型 | `PascalCase` | `AttackPhase` |

- 统一英语术语，中文用于注释和显示文本，不混用拼音和同义缩写。
- 优先使用下表约定的短写；未列出的术语先用完整单词，新增缩写先补充本规范。
- 脚本文件名与类名语义对应：`fwalk_state.gd` 对应 `FWalkState`，`hit_fx.gd` 对应 `HitFX`。
- 内部成员、内部辅助方法用 `_` 前缀；公共接口不加。Godot 回调和 Fray 覆写方法沿用原名。
- 重命名时保留 `.gd.uid`，同步场景、资源、分组路径、默认入口、条件映射和文档引用；大小写变化同样视为路径变更。

## 2. 缩写约定

### 2.1 统一词表

| 含义／完整词 | 文件、变量、运行时标识中的短写 | 类／节点示例 |
|---|---|---|
| 前进 `forward` | 行为前缀 `f`：`fwalk`、`fdash`、`fjump` | `FWalkState`、`FDashState`、`FJumpState` |
| 后退 `backward` | 行为前缀 `b`：`bwalk`、`bdash`、`bjump` | `BWalkState`、`BDashState`、`BJumpState` |
| 状态机 `state_machine` | `sm` | `FighterSMBuilder` |
| 特效 `effects` | `fx` | `FX`、`HitFX`、`FXPlayer` |
| 音效 `sound_effects` | `sfx` | `SFX`、`HitSFX`、`SFXPlayer` |
| 背景音乐 `background_music` | `bgm` | `BGMPlayer` |
| 动画 `animation` | `anim` | `AnimPlayer` |
| 配置 `configuration` | `cfg` | `MoveCfg` |
| 环境 `environment` | `env` | `FighterMoveEnv` |
| 位置 `position` | `pos`，如 `spawn_pos` | `SpawnPos` |
| 速度 `velocity` | `vel`，如 `move_vel` | `MoveVel` |
| 加速度 `acceleration` | `accel`，如 `fwalk_accel` | `WalkAccel` |
| 方向 `direction` | `dir`，如 `facing_dir` | `FacingDir` |
| 距离 `distance` | `dist`，如 `dash_dist` | `DashDist` |
| 索引 `index` | `idx`，如 `state_idx` | `StateIdx` |
| 标识符 `identifier` | `id`，如 `fighter_id` | `FighterID` |
| 界面 `user_interface` | `ui` | `BattleUI` |
| 生命值 `hit_points` | `hp`，如 `max_hp` | `HPBar` |

### 2.2 使用边界与大小写

- `SM`、`FX`、`SFX`、`BGM`、`UI`、`ID`、`HP` 在类名和节点名中保持全大写；在文件、变量、状态和资源键中使用小写。例如 `HitSFX` → `hit_sfx.gd` / `hit_sfx`，不是 `HitSfx`。
- 截短单词按普通单词处理：`anim` → `Anim`、`env` → `Env`、`accel` → `Accel`，不写成 `ANIM`、`ENV`、`ACCEL`。
- 方向前缀与行为直接拼接：`fwalk` / `FWalkState`，不混用 `forward_walk`、`f_walk`、`FwalkState`。`f`、`b` 仅表示相对角色朝向的前后，不代替世界方向 `left`、`right`。
- 不把方向前缀单独用作一般变量名；保持 `facing_dir`、`move_dir` 等含义明确的名称。
- `speed` 表速率标量，不替换成表示速度向量的 `vel`；引擎既有的 `position`、`velocity`、`AnimatedSprite2D` 等名称不改。
- `state`、`transition`、`condition`、`definition`、`library`、`loadout`、`builder` 不缩写，避免 `st`、`tr`、`cond`、`def`、`lib` 等含义不清的短写。
- `cfg` 仅用于一般配置，不替代已有角色明确的 `Definition`、`Library`、`Loadout` 后缀；不同时维护两个含义相同的名称。
- 缩写可按上下文使用，职责目录仍可保留 `state_machine/` 等完整词。避免将多个短写堆叠成难以辨认的名称。

## 3. 状态、分组与路径

- 分组名、运行时状态名统一 `snake_case`：`neutral`、`action/basic_attack`、`fwalk`、`bwalk`。
- 状态名描述行为或阶段，不加 `_state`：`idle`、`jump_start`、`hitstun`；`State` 后缀用于脚本类型，不用于运行时标识。
- 完整路径为 `group_path/state_name`；根层叶子只有状态名，根分组仍用空字符串。
- 同一组内状态名唯一，不同组允许同名；角色选择、跨组引用使用完整路径。
- 变量区分含义：`state_name` 是局部名称，`state_path` 是完整路径，`state` 是运行对象，`state_definition` 是静态定义。不要统称 `state_id`。

例：类 `FWalkState`，脚本 `fwalk_state.gd`，状态名 `fwalk`，完整路径 `neutral/fwalk`；后退对应 `BWalkState`、`bwalk_state.gd`、`neutral/bwalk`。

## 4. 条件与布尔值

- 条件和布尔变量按语义使用前缀：`is_` 表事实，`has_` 表拥有，`can_` 表能力，`inputed_` 表输入意图。
- 示例：`is_grounded`、`has_meter`、`can_cancel`、`inputed_fwalk`。不要把“按了攻击”命名成“能够攻击”。
- 条件键统一 `snake_case`，优先与绑定的无参 bool 方法同名；同一作用域内相同键必须具有相同含义。
- 条件键保存正向名称；取反在规则中写 `!inputed_fwalk`，不再注册重复的反向条件。
- 保留现有字段 `advance_conditions`、`prereqs`、`condition_methods`；不为了命名规范随意更换 Fray 对应术语。

## 5. 转换

- 端点字段继续使用 `group_path`、`from_state`、`to_state`；端点是所属组的直接子状态名，不是跨组深路径。
- 单独保存转换资源时，文件名用 `<from>_to_<to>[_<reason>]_transition.tres`；端点沿用状态短名，同端点多规则必须用原因区分。
- 示例：`idle_to_fwalk_input_transition.tres`、`punch_to_kick_on_hit_transition.tres`。
- 文档、日志或 Inspector 的显示名可写为 `neutral/idle -> fwalk [input]`。
- 当前转换定义没有独立 ID 字段；以上规则用于资源或显示命名，不新增运行时字段。不要使用 Godot 自动生成的子资源 ID 作为业务标识。

## 6. 类型、资源与容器

- 类型后缀固定含义：`State` 是运行状态，`Definition` 是静态条目，`Library` 是可共享候选库，`Loadout` 是角色选择清单，`Builder` 是构建逻辑。
- 项目通用的全局类型使用 `Fighter` 前缀，使用 `FighterState`、`FighterMovement`、`FighterMoveEnv` 等明确名称；具体叶子使用明确行为名，如 `IdleState`、`FWalkState`。
- 配置文件按用途命名：`state_library.tres`、`transition_library.tres`、`<character>_loadout.tres`。
- 数组用复数：`states`、`transitions`、`selected_state_paths`；字典需体现映射含义，如 `state_definition_by_path`、`condition_method_by_name`。
- 避免 `data`、`obj`、`temp` 等模糊命名；配置定义、资源引用和运行实例应能从名字区分。

## 7. 节点、动画、输入、判定与单位

- 场景节点按职责用 `PascalCase`：`Fighter`、`StateMachine`、`HitStateManager`；脚本引用变量用对应的 `snake_case`。
- 动画键、输入动作、标签统一 `snake_case`。动画可用 `fwalk`、`fdash`；输入表达意图，如 `move_left`、`light_attack`，不要绑定具体键名或具体招式名。
- 动画键可与状态同名，但不强制一一对应；使用 `anim_key`、`input_action`、`state_path` 区分概念。
- 特效统一使用 `FX` / `fx`，音效统一使用 `SFX` / `sfx`：如节点 `HitFX`、`HitSFX`，文件 `hit_fx.tscn`、`hit_sfx.tres`，变量 `hit_fx`、`hit_sfx`。特效不另用 `VFX`，音效不混写为 `FX` 或泛称 `sound`。
- 背景音乐使用 `BGM` / `bgm`，不要归入 SFX；一般音频服务仍可叫 `AudioManager`，不强行按音效命名。
- 明确区分物理碰撞体、攻击框（`hitbox`）、受击框（`hurtbox`）和判定配置（`hit_state`），不要都叫 `collision` 或 `state`。
- 信号描述已发生的事件，如 `attack_started`、`attack_finished`；事件处理方法用 `_on_<source>_<event>`。
- 数值单位统一使用 `_frames`（帧数）、`_s`（秒）、`_ms`（毫秒）、`_px`（像素），如 `startup_frames`、`duration_s`、`delay_ms`、`dash_dist_px`。帧数不缩成 `_f`，避免与前进方向混淆。
- 与物理量组合时明确单位，如 `fwalk_speed_px_per_s`、`fwalk_accel_px_per_s2`；同一模块已经明确约定统一单位时，可保留 `fwalk_speed`、`fwalk_accel` 等简写并在配置类型中注明。
