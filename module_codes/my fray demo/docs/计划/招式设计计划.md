# 招式设计计划

> 记录日期：2026-10-25；本次经资料核对，改为 MK 风格预输入：接收窗口、接续缓冲与规定衔接帧分离。
> 本文定义目标设计，不表示攻击、取消窗口或方向候选接入已经完成；本次只改文档，不改脚本。
> 配套阅读：[资源关系设计](../说明/状态、招式、输入指令与判定资源关系说明.md)、[招式参与角色构建方案](../方案/招式参与角色构建方案.md)、[动态判定装配](../方案/判定系统动态装配方案.md)、[此前疑难解答](../说明/招式装配与判定时序疑难解答.md)。
> **修订结论：**统一使用 composite_attack（组合技）。在输入接收窗口内记录后续攻击键／合法路线，不立即切换攻击；当前段到达规定衔接帧才重新校验、消费待执行接续并转入下一段。每段仍是独立状态，内部处理三阶段。允许在 A 执行期间快速预输入 M、H。下→上仅用于 special_attack，继续使用 Fray matcher。资料与证据边界见第 12 节；以下队列、字段和示例帧数是本项目设计，不是 MK 源码事实。

## 1. 已确定的范围与命名

| 类型 | 统一标识／状态组 | 内容与输入 |
| --- | --- | --- |
| 基础攻击 | basic_attack／action/basic_attack | 轻、中、重，单个攻击键或方向快照＋攻击键 |
| 组合技 | composite_attack／action/composite_attack | 窗口内预输入固定后续攻击键，缓冲接续；到规定衔接帧才转下一段 |
| 特殊技 | special_attack／action/special_attack | 固定方向指令，通常方向＋指定攻击键；也允许下→上这样的纯方向指令 |

TC 仅作为“组合技”的术语对照，不另设 tc 类型、tc 分组或另一套执行系统。首期不计划投技第四大类；现有空 throw 分组不在本次代码修改范围。

每招由作者固定逻辑输入。基础攻击轻中重可以是不同招式；特殊技不因把终结按钮换成轻／中／重而自动改变帧数、伤害。下→上只作为特殊技示例，不作为基础攻击或组合技的输入。

默认每招／每段拥有独立状态路径和状态实例；若执行协议相同，可由多个路径复用同一状态脚本类，各自读取本招只读动作配置。协议差异明显时采用专用脚本或机制组件。公共 FighterState、Movement、计时和清理工具仍可复用；脚本复用与强度版本是两个独立问题。目标资源接线见[招式参与角色构建方案](../方案/招式参与角色构建方案.md)。

## 2. 核心区分：三阶段不等于三段攻击

**每一段攻击的 startup（起手）→active（有效）→recovery（恢复）在该段自己的 FrayState 内部处理。**

而组合技的 A→B→C 是不同攻击段／状态之间的合法转换：

    action/basic_attack/light_punch（A）
      └─ 接收窗口内预输入 M，A 到规定衔接帧且 A→B 合法
           → action/composite_attack/string_lmh/second_hit（B）
                └─ H 已合法预输入或在允许区间输入，B 到其衔接帧且 B→C 合法
                     → action/composite_attack/string_lmh/third_hit（C）

A、B、C 各自有起手、有效、恢复、伤害和判定。A→B 不代表 startup→active。取消可以跳过 A 剩余恢复，但不省略 A 未取消时的恢复数据与结束路线。

保持“每段一个状态”，但撤销上一版“窗口内按键合法即刻转状态、首版不做预输入”的结论。为支持真人快打式连续拨入，需要本次组合技局部的有界接续缓冲与输入路线进度；不需要让完整串 matcher 再启动第一拳，也不恢复已经消费的基础起手键。

## 3. 基础攻击

### 3.1 固定输入

L／M／H 对应现有 light_attack／medium_attack／heavy_attack 逻辑按钮；不是键盘字符。方向相对面向，2 下、6 前、8 上。

| 输入示意 | 招式示意 |
| --- | --- |
| L／M／H | 各自固定的轻／中／重基础攻击 |
| 6＋M | 指定方向基础攻击 |
| 2＋L | 指定下方向／蹲姿基础攻击 |

方向＋攻击建议采用“攻击按下时检查当前方向快照”：可以先按住前再按 M，不要求两个键严格同帧，也不解释成先前后 M 的特殊技序列。若某招要严格同步容错，需另写规则。

M 与 6＋M 重叠时，明确方向、装备、姿态和回退关系，不按装备数组顺序偶然选中。方向快照约束是待实现的游戏层输入规则，不冒称当前 SINGLE 已具备。

### 3.2 执行与出口

每招保存明确的起手／有效／恢复帧，逻辑帧控制攻击框、取消窗口、位移和完成。FrayState 默认完成为 true，攻击脚本必须覆盖 _is_done_processing_impl()，正常恢复结束才报告完成。

大部分基础攻击计划可取消为已装备且兼容的 composite_attack 或 special_attack；不等于任意招式在全部动作帧都可取消。

## 4. composite_attack（组合技）：预输入，按规定衔接帧执行

### 4.1 资料能支持什么，不能断言什么？

MK1 官方 2023-10-02 补丁明确修复过“已缓冲组合技串”未执行的问题，[S1] 证明组合技输入可以先缓冲，而非收到按钮必然立即执行。官方 July Update 又把 Li Mei 某攻击的取消帧前移一帧，[S2] 说明取消时点是可按攻击调整的数据；这不是全部组合技同一个取消帧的证据。

一位玩家对亲身体验的描述是：快速输入预定顺序后，角色依次执行动作。[S3] 这是 dial-a-combo 的输入体验佐证，不是引擎实现文档。

因此，本项目采用“先接收／缓冲，后按动作时间提交”的规则。**没有公开证据可以据此还原所有 MK 作品、所有角色、每条串的内部窗口、队列结构和帧数。** 特定招式可有不同的延迟或条件设计；这些需要逐招配置，不武断声称全部 MK 串都采用同一种单帧实现。

### 4.2 区分三个概念

| 概念 | 用途 | 会立即换状态吗？ |
| --- | --- | --- |
| 输入接收窗口 input_window | 允许后续按钮成为本次组合技的有效输入；可在起手期间较早开启 | 不会 |
| 待执行接续 pending_followups | 保存已认领的新事件、固定连接和顺序，可包含多个后续段 | 不会 |
| 动作衔接点 commit_frame | 当前攻击达到该逻辑帧且条件满足，才真正取消剩余部分、进入下一击 | 会在统一安全提交点执行 |

至少需要一个明确的组合技输入窗口；不能只写一个 cancel_window_open 布尔值，同时把“收输入”和“执行转换”当成一件事。

首版每条连接使用一个固定 commit_frame，输入窗口可以早于它关闭；已接受的接续不会因为输入窗口关了就消失。若将来确需延迟接段，可显式扩展 commit_window=[start,end) 与最早／最晚提交策略；本次默认不做“迟按也立即切”的自由延迟模式。

这三个名字是本项目拟新增语义，不是 Fray 的现成字段，也不声称 MK 内部使用这些名字。固定模式必须保证接收截止不晚于该连接的实际提交边界；超过已失效连接的输入不再接受，也不能因缓冲记录尚在就跳过规定时点补执行。不同接收／执行时钟先映射再比较，不直接比较数值。

### 4.3 一条 L→M→H 的运行过程

1. L 当下发动基础攻击 A，不等待整串完成。
2. A 的组合技输入接收窗口开启。新 M 若能沿已装备路线接到 B，就认领该事件并记录 A→B；A 继续执行原动作，不退出、不提前关有效框。
3. 如果随后 H 也在本路线允许的预输入区间／间隔内，且已记录的 B 后有合法 C，则继续记录 B→C，即使 B 此时还没有进入。
4. A 到自己的 commit_frame，统一入口校验实际源仍是这次 A、路线已装配、动态条件合法、有正确的队首 A→B，才消费该接续并 A.exit()→B.enter()。
5. B 从自己的第 0 帧开始，正常执行其起手与有效；已记录的 H 不因 B 刚进入就立即跳到 C。
6. B 到自己的 commit_frame，再校验并消费 B→C，进入 C。
7. 没有合法后续时走当前段完整恢复。被受击、取消到特殊技、死亡、脱离本路线等打断时清掉未执行接续，不在未来自动补出。

**按键较早或较晚，只要仍被同一输入规则接收，固定模式的下一击开始时点相同；玩家输入速度不能把动作动画和伤害有效帧加速。**

### 4.4 用两个进度支持“先按完整后缀”

仅在 A 中缓存 M、等 B 开始才接 H，只支持单步预输入，不能完整支持本项目要的快速拨入体验。需要分开：

- 执行进度：现在真正执行 A，尚未到 B。
- 输入路线进度：已经合法接收了 M、H，待执行路线是 B、C。

不要求一个通用全局组合技图引擎。可以在现有 FighterInput 内增加一个每角色、本次连续动作专用的有界缓冲和路线游标；最多保存当前已装备路线剩余长度，显式限制循环，不能无限排队。

向尚未执行的 B→C 预输入 H 时，接收时间不能使用“B 当前第几帧”：B 尚未开始。连接要明确允许的时钟，例如本次组合技起手以来的逻辑时间区间，或当前实际执行段的接收区间＋按钮最大间隔。未来段的源局部执行时钟只在它实际进入后才从 0 计数。

本阶段建议以组合技起手为 0 的逻辑时钟配置拨入区间，并限制后续键的间隔；个别要求进入该段后才可输入的连接可显式设 source_local 接收时钟。它们都不能由一个全局固定 buffer_frames 猜出来。

输入路线只从当前实际合法起手或已接受的路线末端延长，不能因为按了 H 就凭空越过没有 M 的 B。共享前缀的多条路线可在新键到来时选择分支；同源同键却要求执行不同 B，必须预先消除歧义，不等待未来输入再倒改已执行动作。

### 4.5 本项目示例时间线（不是 MK 实测帧表）

假设 A 起手 5、有效 3、恢复 12，总计 20 帧；组合技起手时钟等于 A 的局部逻辑帧。A→B 的输入区间为 [0,9)，commit_frame=12；这条示例路线还允许在同一拨入区间提前录入 B→C 的 H，并要求与 M 的间隔不超过作者配置。

| 时刻 | 输入与缓冲 | 实际执行 |
| --- | --- | --- |
| A 帧 0 | L 发动 A，拨入窗口开启 | A 起手 |
| A 帧 2 | M 被认领，记录 A→B | 仍是 A |
| A 帧 3 | H 被认领，记录 B→C | 仍是 A，不要求等 B 出现 |
| A 帧 5..7 | 无需再按键 | A 有效段照常执行 |
| A 帧 9 | 拨入窗口已关闭，B、C 待执行记录仍有效 | A 恢复 |
| A 到达帧 12 边界 | 校验、消费队首 A→B | 退出 A，进入 B 第 0 帧 |
| B 到它自己的衔接帧，例如 10 | 校验、消费 B→C | 退出 B，进入 C 第 0 帧 |

此处“到达帧 12”指完成 A 的 0..11 逻辑帧后，在下一帧边界提交；不先执行 A 第 12 帧再又对 B 做一次完整物理推进。初帧、状态转换和移动的处理顺序在实现时统一，保证同一物理步不重复移动或加速计时。

M 若在同一合法拨入区间的其他帧输入，A→B 仍在 12 提交；输入晚于截止则不接受，也不在 13 或恢复结束时补执行。首版固定点到期缺输入／条件不满足，就放弃该连接及依赖后缀，继续当前段正常恢复。

### 4.6 事件认领、接续执行与失效

必须区分“防重复的输入认领”与“真正执行一击”：

- 接收时：核对输入窗口、来源、固定按法与装备路线。事件由该路线独占，移出可被普通攻击／其他路线重复使用的候选，转换为 pending 记录；可以标记输入已认领，但不代表已经换状态或扣费。
- 提交时：到 commit_frame 重新校验实际源和前驱、目标、命中／防御／挥空政策、资源及未中断状态；成功才弹出对应 pending、转换、支付一次资源及建立新伤害身份。
- 正常 A→B：移除已执行队首，保留已合法排好的 B→C；不能旧状态一退出就无差别清掉剩余后缀。
- 非正常脱离／受击／新特殊技／整条路线失效：清空 pending 与路线输入进度。已认领旧输入不回灌普通候选，也不退还成未来可自动发动的按键。
- 晚按、错误键、持续 held 不自动匹配。首版建议错误键不入队且不刷新已有记录的期限，保留此前已接受的部分；若内容需要“错键断串”，另做显式策略。
- 同时按下与明确的顺序按下不能靠按钮枚举顺序混同；有歧义的同帧输入按明确规则拒绝或选择，不替玩家伪造整条顺序。

不能仅在接收瞬间调用 Fray get_next_state()/advance()，因为此时尚不该转换，且命中等动态结果可能尚未知。接收检查的是可记录路线，提交检查的是当前真正可执行的转换。

### 4.7 组合技串、特殊技取消与普通恢复缓冲不是一回事

- composite_attack 串内接续：固定按法先缓冲，到各段固定衔接点执行。
- special_attack 取消：Fray matcher 识别独立方向指令，再由源招的特殊技取消规则决定接收和提交；可以不同于组合技串内时点。
- 正常恢复后接普通动作：可能有“恢复结束前几帧预输入、恢复结束后执行”的一般输入缓冲，不属于跳过恢复的串内接续。

MK11 官方 PC 版 2020-11-17 更新曾明确增加许多基础／组合攻击在恢复末 4 帧的按钮缓冲，[S4] **不能据此把所有组合技拨入窗口统一设为 4 帧**。MK1 补丁还调整过具体特殊技取消的输入窗口，[S5] 也不能反推全部组合技共用该窗口。

固定串是否在挥空／被防御时继续，由作者按连接配置；不是一律要命中才接下一段，也不能把任何重叠都当命中确认。输入被记录不代表随后必然执行成功。

### 4.8 Fray 怎么接，哪里仍需业务层实现？

每段一个 FrayState 保持不变。B→C 同组可用原生转换，跨 basic_attack／composite_attack／special_attack 的合法路线仍用统一验证后的 external 桥接，不把跨层完整路径塞进仅支持直接子端点的普通 add_transition。

首版以游戏层 pending＋commit_frame 决定何时提交给 Fray。若用 FrayInputTransitionPress，可在到期时提交携带原事件身份的已缓冲按钮数据，而不是伪造一次物理按下；窗口条件须区分“原输入被接收的时间”与“当前已到执行点”。也可使用显式待执行连接转换，二者只选一个消费路径。

IMMEDIATE 只表示**被提交且通过规则时不再等待源状态 done**，不是“采样到按键就立刻切”。仅 IMMEDIATE 不能实现调度；仅 AT_END 又可能拖到整段恢复结束。无需为打开衔接点而让源状态提前报告正常完成。

当前 advance_conditions 仅在 auto_advance=true 时检查，必要提交条件应在 prereqs／每次都执行的业务准入中；普通 advance({}) 不得无输入触发待执行连接。同帧最多一个控制结果，不能 B 刚进入就再次消费 H 跳 C。

当前 Demo 的 FighterTransitionDefinition、Builder、FighterInput 与 advance_commands 尚无上述缓冲、路线游标、衔接时点和提交生命周期；Fray 的原生 Advancer 也不会自动替业务完成这些语义。保持 MANUAL 单入口与 paused Advancer，不改 matcher 来实现组合技串。

## 5. special_attack（特殊技）：复用 Fray matcher

### 5.1 下→上可以由插件识别

**FraySequenceMatcher 没有要求最后一项必须是攻击按钮。** FraySequenceBranch 的 then() 接收 StringName 输入，matcher.read() 读取 FrayInputEvent，所以经过方向归一化的 dir_2→dir_8 可以构成特殊技序列。

下面是插件原生配置关系，seq_reader 是示例局部变量，不是要求新增的节点：

    var tree := FraySequenceTree.new()
    tree.add(&"vertical_special", FraySequenceBranch.builder()
        .then(&"dir_2")
        .then(&"dir_8")
        .build())
    var seq_reader := FraySequenceMatcher.new()
    seq_reader.initialize(tree)
    # 按实际采样顺序向 seq_reader.read(event) 送入方向事件，
    # 通过 match_found 信号得到 vertical_special。

这只是源码能力说明，本次没有新增或运行特殊技示例。matcher 不会自己采样键盘、推断朝向、消费游戏候选或切换攻击状态。

### 5.2 现有接入层要补什么？

当前 FighterInput 已合成方向事件并送给 matcher。问题在 matcher 返回匹配之后：_feed_direction() 携带空 source_ids，_add_candidate() 拒绝空数组，导致纯方向匹配不能进入当前候选执行链。

所以后续应**保留 Fray matcher，补齐方向终结事件的来源／一次消费标识与候选转接**，不重写下上识别算法，也不增加“必须按攻击键确认”的限制。

方向按住不应每帧重新发动；方向输入的时限、斜方向容错、换向和回中规则要明确。下→上与普通跳跃共用上方向时，在离散执行前处理竞争，避免同次输入既执行特殊技又起跳。不能重复把 jump／crouch 别名当作另一份方向历史。

### 5.3 特殊技与组合技的输入分工

| 内容 | 识别／请求 | 取消准入 |
| --- | --- | --- |
| 下一段 composite_attack | 当前窗口内的攻击键按下事件 | 当前攻击到目标段的合法连接 |
| special_attack | FraySequenceMatcher 匹配固定方向指令 | 中立发动规则，或当前攻击开放的特殊技取消窗口 |

组合技可取消为特殊技，仍由 matcher 识别，再按源招的特殊技取消时序提交。被接受的特殊技取消会终止原组合技未执行后缀；不能与队列中的下一击在同一帧分别执行。

特殊技固定自己的输入和数值，不因替换轻中重终结键自动变体。未来不同指令可对应类似／相同内容，但当前不新增多指令别名系统。

## 6. 强化保留独立语义

特殊技可有起手开始或恢复开始附近的强化窗口。强化键、资源与效果尚待逐招确定，不预设为 H、格挡或轻中重强度版本。

- 就地强化：修改尚未执行、允许修改的后续配置，不重放已经发生的攻击。
- 内部追加段：有自己的帧数、判定和次数上限。
- 转入强化攻击状态：确有独立执行协议时，按窗口和固定派生输入走合法转换。

强化可以复用“窗口内请求＋条件＋统一提交”的准入思想，不代表必须与组合技采用同一种状态组织。恢复强化不能追溯修改已经结算的伤害；已经生成的投射物如何变化需显式定义。资源在一次成功提交时扣除，不能反复重试重复支付。

## 7. 静态资源、判定与运行时

### 7.1 不增加整串组合技 matcher

- 基础攻击：固定单键／方向快照，专用攻击状态。
- composite_attack：装备包声明起手依赖、后续状态、固定按键连接、接收时钟／窗口与衔接点；运行时区分路线输入进度、pending 和实际攻击状态。
- special_attack：固定 command 使用 Fray matcher。
- 每段状态：自己的三阶段、窗口、完成判断和判定绑定。

当前 command 必填，FighterInput.configure() 会为 selected_moves 一律配置输入；后续需要显式区分组合技装备包与主发动输入，不将组合技全串误注册为特殊技式全局 SEQUENCE。拟新增字段／分类尚未实现，也不把 command 随便设 null 当作现成方案。

### 7.2 装配关系

    Loadout
      → 基础状态及所选攻击／组合技／特殊技
          → 各段 FighterStateDefinition
              → 判定定义 → PackedScene → 每角色独立 HitState
          → 仅所选内容的合法连接与准入条件

每段一个完整姿态优先满足首版，不为组合技强制引入单叶子多姿态集合。某段确需变化身体布局，再设计明确的姿态数据；不能靠固定预建全部招式或运行时随意查节点。

一角色一个 FrayHitStateManager2D，姿态包含当前需要的 Hurt／Attack／Push；取消退出关闭旧攻击，下一状态选择完整姿态。构建与 Manager ready 的顺序遵守动态装配方案。

### 7.3 最小运行数据（本次新增必要缓冲）

当前攻击状态／实例、该段局部逻辑帧、组合技起手逻辑时钟、合法输入路线游标、有限 pending、各事件认领身份、已执行进度与代次都按角色独立。pending 保存连接、预期前驱、原输入时间／顺序，不能只存一个全局 next_button。

普通 A→B 保留本路线后缀并初始化 B 的局部帧与伤害身份；打断／特殊技取消清掉剩余记录。每段自己的延迟结果验证段代次；路线代次在正常接段保留，真正结束或被打断才失效。

不需要恢复已经发动 A 的 L 或让完整串 matcher 再播放第一拳，但必须保留“已接受但尚未执行”的后缀，这与上一版只看活动状态的无缓存模型不同。需要 UI 时再增加统计，不为此建设全局通用组合技引擎。

## 8. 时序和取消的共同边界

逻辑帧唯一控制阶段／窗口／判定，AnimatedSprite2D 只显示，不恢复 AnimationPlayer 节点。每帧只由叶子提交一次实际移动。

同帧可能收到组合技按钮、特殊技匹配、强化和受击结果，应由唯一安全入口选择一次控制结果。不能同时保留三套监听入口分别 goto。需要命中确认的窗口先获得本帧战斗结果，再按明确顺序提交。

保留 MANUAL 单入口与 paused Advancer。接收时把原事件映射到明确的组合技／段逻辑时钟，记录而不转换；推进到衔接帧后再在安全点提交。Engine 物理帧、动作逻辑帧和 matcher 毫秒不能直接混算。

本项目建议 Hitstop 冻结段／路线逻辑时钟和衔接提交；停顿期是否收按钮必须显式选择。若收，保留事件实际顺序并映射到冻结逻辑时刻，不能让停顿期间经过墙钟就错过拨入截止，也不能让输入到达时推进动作。本次未实现 Hitstop 或回滚确定性。

## 9. 当前实现与后续步骤

| 事项 | 当前能力 | 后续工作 |
| --- | --- | --- |
| 下上特殊技识别 | Fray matcher 支持任意已命名输入序列，含方向终结 | 补 demo 的方向来源及匹配后候选接入，不重写 matcher |
| 基础方向＋按钮 | 当前 SINGLE 无方向快照限制 | 明确方向约束、装备及与普通按钮竞争 |
| 组合技预输入与逐段转换 | Fray 有转换执行能力，不自带本项目接续时序 | 扩展接收窗口、路线游标、有界 pending、规定衔接帧及两阶段提交 |
| 同组／跨组路线 | 原生普通边仅支持直接子端点 | 同组原生边；跨组统一验证后 external 执行，不无条件 goto |
| 装备选择 | Builder 已收集 states／transitions | 仅注册已装备组合技的路线；起手依赖与 command 分类待实现 |
| 判定／强化／伤害 | 缺完整业务闭环 | 按段接入判定、结算和明确强化规则 |

建议顺序：单招三阶段与判定闭环→A 早按 M 先缓存、到固定帧转 B→A 期间 M、H 连续拨入但 B、C 各到期才执行→分支／中断清队列→特殊技取消→下上候选接通→强化。不把必要接续缓冲误删为“过度设计”。

## 10. 单招／连接制作模板

| 项目 | 要明确的内容 |
| --- | --- |
| 类型与身份 | basic_attack／composite_attack／special_attack，move_id／装备归属 |
| 输入 | 基础单键或方向快照；组合技每条边的固定攻击键；特殊技固定 matcher 序列 |

| 连接与执行 | commit_frame（相对实际源状态）、提交时动态条件、失败／失效路线 |

| 判定与数值 | 完整姿态、伤害段和唯一数值来源，不重复配置 |
| 强化（如有） | 固定派生输入、窗口、资源、效果及不可逆事件边界 |

## 11. 验收问题

- [ ] 命名仍为 composite_attack，每段一状态、三阶段内部处理；输入路线缓冲不是把全部攻击合并成一个叶子。
- [ ] L 立即启动 A；早按 M 只缓存，A 的动画／有效段不会被提前截断。
- [ ] M 在不同合法输入帧到来时，A→B 都发生在相同规定衔接帧。
- [ ] A 期间连续按 M、H 能记录 B、C；B 未进入时 H 不丢失、不依赖虚构的 B 局部帧。
- [ ] 拨入窗口关闭不清掉已接受 pending；晚于截止的新输入不录入、不重置期限。
- [ ] A→B 只消费对应队首，保留 B→C；B 刚进入不会同帧又跳 C，而在其规定帧提交。
- [ ] held、重复事件、歧义同时键不自动变成多次顺序输入，队列不能无限增长。
- [ ] 缺输入或提交条件不满足时有明确恢复／失效路线，不等待任意未来输入补串。
- [ ] 受击、特殊技取消、死亡、换设备／失焦等明确清掉未执行接续；已认领事件不回灌普通攻击。
- [ ] 正常恢复缓冲、串内接续、特殊技取消与强化没有误用同一默认时长；绝不把 MK11 恢复末 4 帧当通用组合技窗口。
- [ ] IMMEDIATE 仅在到期提交使用，接收按钮时不直接调用转换；AT_END 不额外等待已被合法取消的剩余恢复。
- [ ] 跨组合法桥接、每段判定与伤害去重、动态条件复核、单帧一次移动／控制提交均有验证。
- [ ] Hitstop 冻结逻辑衔接且明确收输入政策，原事件时钟映射与顺序不丢失。
- [ ] 下上只用于特殊技且保留 Fray matcher；接续缓冲不伪造方向或按钮事件。
