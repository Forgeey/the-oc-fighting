# 招式编号模板与登记表

> 2026-11-11 容器式装配更新：叶子和转换不再保存父组字符串；FighterCompoundStateDefinition.states／transitions 直接持有成员与内部边，TransitionLibrary.transitions 仅持有根边。组内归属由资源放在哪个容器决定，详见[状态机资源配置说明](../说明/状态机资源配置说明.md)。旧字段说明及示例已删除，不提供兼容别名。


> **2026-11-10 最新组织目标：**多数动作仍同根；无方向单键、方向＋攻击组合、MK 风格顺序／取消组合技、快速序列特殊技分开。方向＋攻击按复合输入注册；组合技后续／投掷用真正局部流程 CompoundState，不按分类机械建组。当前运行代码尚未装配这些组，旧的全部扁平永久限制／分类多层骨架／不做投技描述均以[角色动作与复合状态组织方案](角色动作与复合状态组织方案.md)为准。本轮仅整理文档和审查插件，未回退源码。

> 修订日期：2026-11-05。适用于公共 MoveLibrary 中可装备的招式身份，不替换状态路径、输入按钮、动画键或转换 ID。配套规则见[命名规范第 3 节](命名规范.md#3-身份名称与状态路径)。

## 1. 字段职责

| 字段 | 类型 | 用途 |
|---|---|---|
| move_id | StringName | 八位数字字符串，库内唯一；用于目录、装备、解锁和以后存档引用；不作为运行输入或转换分派键 |
| move_name | String | 面向玩家的显示名称，可用中文、可改、可重复；不作任何身份匹配 |
| state | 静态 Resource 引用 | 单段引用库中叶子定义，多段引用库中复合组定义；不保存状态数组 |

当前不新增三个重复的导出分类字段：大类、小类、流水号已经编码在 move_id 中。下方分类和登记表用于内容制作与分配，不表示运行时自动分类 API 或菜单已实现。若未来需要可变 UI 分类，应新增明确元数据，不以改 ID 实现分类调整。

## 2. 固定编号结构

```text
CC SS NNNN → CCSSNNNN
│  │  └── 四位流水号，0001～9999
│  └───── 两位小类码，按所属大类解释
└──────── 两位大类码

01 01 0001 → "01010001" → 轻攻击
```

- 存储形式为 `&"01010001"`，不是整数 `1010001`。文档、表格和导入导出均按文本处理，保留前导零。
- 无空格、无下划线、无连字符，严格 8 位；分隔符只用于文档示意。
- `00` 大类、`00` 小类和 `0000` 流水号保留，不分配实际招式；未登记编码不可自行猜测使用。
- 每个 CCSS 前缀独立分配流水号；完整编号在全游戏 MoveLibrary 唯一。同一个小类最多 9999 个条目，接近容量前先修订编号方案，不临时加位或绕回重用。
- 新招式取登记表中该前缀最大的已发流水号 + 1；有作废号也不填洞。多人制作先登记占号，避免各自从 0001 开始。

## 3. 大类及首批小类字典

以下是编号分配约定，不是靠编号触发的业务行为，也不是这些内容已经实现的功能清单。类别不足时先扩充字典，再分配 ID。

| 大类码 | 大类 | 小类码 | 小类 | 前缀 |
|---|---|---|---|---|
| 01 | 基础攻击 basic_attack | 01 | 单键基础攻击 | 0101 |

| 01 | 基础攻击 basic_attack | 99 | 其他基础攻击 | 0199 |
| 02 | 特殊技 special_attack | 01 | 地面特殊技 | 0201 |
| 02 | 特殊技 special_attack | 02 | 空中特殊技 | 0202 |
| 02 | 特殊技 special_attack | 99 | 其他特殊技 | 0299 |

大类 05～98 以及各大类未登记的小类预留。不要把 idle、受击或其他纯行为状态也为了统一编号包装成 Move；只给实际招式条目发号。流水号不编码轻/中/重、按钮、伤害、阶段或角色；不会因为一个特殊技支持不同按钮就自动生成多份招式。

## 4. 稳定性规则

1. 分类前缀只记录首次分配时的归属。运行代码不通过切片 ID 决定状态分组、输入指令、地空条件、取消权限或伤害。
2. 改 move_name、翻译、动画、入口分组不改 move_id；分类重审也不机械改号。需要反映当前分类时使用独立元数据，保留既有身份。
3. 修改现有招式的数值不自动产生新身份；真正新增可装备条目才另分配号码。删除的号标作废，永不复用。
4. move_name 可以相同，最好在制作界面同时显示“01010001 · 轻攻击”帮助辨认；这里是显示建议，不新增 UI 实现。
5. 不由数组位置、文件名或 Resource.resource_name 自动发号。业务 ID 明确填写；文件改名不隐式改业务 ID。

## 5. 已分配登记表

该表只登记已发号码，规划示例不算已分配。新增条目时同步本表、资源和 MoveLibrary。

| 大类码 | 小类码 | 流水号 | 完整 move_id | move_name | 状态 | 资源 |
|---|---|---|---|---|---|---|
| 01 | 01 | 0001 | `01010001` | 轻攻击 | 已实现 | `resource/moves/01010001_move.tres` |

各前缀后续可申请号：0101 的下一号为 `01010002`；其余字典前缀暂无已分配号，从 0001 开始。比如 `02010001` 仅作为文档中的火球制作示例，当前不代表已有招式或已占号。

## 6. 新增招式的填写模板

先从字典选定大类、小类并登记占号；下面占位符不是合法资源值：

```text
大类码：CC
小类码：SS
流水号：NNNN
完整 move_id："CCSSNNNN"
move_name：玩家看到的名称
资源路径：resource/moves/CCSSNNNN_move.tres
state：本招式的静态执行定义，单段叶子或多段复合组
state_id：招式状态按 move_id 加 00～99 分配，先登记到状态库
command：固定输入资源
对应 StateDefinition.animation_key：状态动画语义（不填在 Move 资源）
```

实际已实现的轻攻击资源片段：

```ini
move_id = &"01010001"
move_name = "轻攻击"
state = ExtResource("3_state")
# 3_state 指向 res://resource/states/light_attack_state.tres
```

轻攻击状态资源填写 `state_id = &"0101000100"` 并登记进 StateLibrary，再填写 `animation_key = &"light_attack"`；MoveDefinition 不再保存动画键。

接线检查：

- 资源文件名使用 `<move_id>_move.tres`，MoveLibrary 引用对应资源。
- Loadout.selected_move_ids 填写数字 ID，如 `[&"01010001"]`，不是显示名称。
- 招式发动转换的 move_id 使用同一数字 ID，from_state/to_state 仍为完整状态路径。
- command 的按钮继续使用 light_attack 等逻辑输入名，绝不批量替换为数字 ID。
- 纯普通转换的 move_id 继续留空；transition_id 和状态局部名继续遵守各自命名规则。
- 改显示名无需修改 Loadout 或转换；改业务 ID 属于迁移，需同步工程引用及已有外部存档。

## 7. 当前实现边界与验收

保留 move_id 的 StringName 类型并由 FighterMoveDefinition 提供 move_name；动画键现由 StateDefinition 提供。没有增加运行时分类字段、自动发号器、格式预检、分类筛选 UI 或旧 ID 回退兼容层；内容作者按表维护有效且唯一的编号。

默认轻攻击已由旧 ID light_attack 迁移为 01010001，资源重命名保留原资源 UID。Fighter、Builder 和输入候选处理仍精确比较数字 StringName；动画归属已另按状态动画方案迁移到 StateDefinition，不改变旧 ID 迁移边界。旧 ID 的输入按钮、动画和状态路径不是迁移目标。

状态编号统一十位：招式状态为八位 move_id 加两位序号，从 00 开始；非招式使用 00GGNNNNII。命名规范第 3 节保存状态组码与已发登记表。状态编号只用于库内引用，不决定路径、动画或执行阶段，不是完整反作弊凭据。

当前默认轻攻击引用 0101000100。格式、库内唯一性和保存重载由状态目录/资源测试覆盖；具体命令见状态机接入说明。历史测试项数不作为当前验收依据。

## 8. 组合技前缀条目与动作复用

A、AB、ABC、ABCD 可以在招式表分列为四个显示／解锁条目，也可以同属一个路线族下的前缀输出。只有产品确定需要独立持久身份时才分别分配条目 ID；本次示例不发号、不登记四个已实现招式。

无论表中列几行，combo1 的 B/C/D 都可共享同一组内的普通 FrayState 和只读动作定义；条目 ID 不传给状态决定当前播放哪一击，也不要求为 AB／ABC／ABCD 重复注册整串输入 Matcher。

独立装备时需明确前缀依赖与连接授权：长串可以自然停在短前缀，短串不能因其他内容装配了 C/D 就自动获得 B→C／C→D。当前 Move.state 只表达执行入口与组装配，路线条目／连接授权是待实现协议，见[组合技路线条目与多出口设计方案](组合技路线条目与多出口设计方案.md)。
