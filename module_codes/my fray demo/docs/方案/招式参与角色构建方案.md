# 招式参与角色构建方案

> 修订日期：2026-10-26。本文为角色构建方案。MoveLibrary、按 ID 选招、状态依赖收集、按端点自动选择转换以及 J 轻攻击闭环已落地；后文阶段列表保留作为设计与扩展参考。
>
> 当前约定：所有角色使用同一模板，装配决定能力是否存在；转换库决定来源、条件与完成模式。状态和招式不声明转换 ID 清单，转换自身的 `transition_id` 保留为稳定标识，不参与装配筛选。本次不改 Fighter 的 external 执行部分。
>
> 本阶段**不实现判定框、自定义外貌映射或战斗中换招**。已接入最小单段逻辑帧执行与现有素材的轻攻击显示。判定资源只预留给招式定义或状态定义的扩展位置，不创建 HitState 场景或节点。
>
> 配套阅读：[状态机资源配置说明](../说明/状态机资源配置说明.md)、[状态/招式/输入/判定资源关系](../说明/状态、招式、输入指令与判定资源关系说明.md)、[招式装配与判定时序疑难解答](../说明/招式装配与判定时序疑难解答.md)。

## 1. 目标

使招式成为 Fighter 构建输入的一等配置：游戏有一个集中、可查找的招式库；角色 Loadout 从库中选择要装备的招式与基础状态；构建器解析二者的依赖，收集所需状态和转换，创建该角色独立的状态机，并让输入层只注册已装备招式的指令。

目标数据流：

```text
FighterMoveLibrary（全游戏招式定义目录）
        ↓ Loadout 按 move_id 选择
FighterLoadout.selected_move_ids + selected_state_paths
        ↓ FighterSMBuilder 合并状态依赖，建立可进入分组
已选状态 + 已选招式依赖状态
        ↓ 扫描公共转换库，筛选可用端点及已装备 move_id
selected_transitions（保留转换库顺序）
        ↓
角色独立 Fray 状态机；输入层仅配置已选招式
```

MoveLibrary 是静态内容目录，不代表角色全部拥有这些招式。Loadout 是本场角色构建选择，不直接保存状态进度。Builder 每次为 Fighter 创建独立状态实例。

## 2. 调整前实现基线（历史对照）

以下记录调整前的代码结构，不能作为当前字段/API 使用：

- `FighterMoveDefinition` 已有 `move_id`、`command`、`entry_path`、内嵌 `states` / `transitions`、发动源状态、前置条件和转换模式，但没有公共 MoveLibrary。
- `FighterLoadout` 目前直接保存 `selected_moves: Array[FighterMoveDefinition]`，并引用状态库与转换库。
- `FighterSMBuilder` 从 StateLibrary 建索引，再将选中 Move 内嵌的状态和转换合并；用完整状态路径去重；普通转换库规则按端点是否可用筛选。
- `Fighter._initialize_state_machine()` 从 `loadout.selected_moves` 配置 `FighterInput`；`Fighter._try_move()` 根据候选 Move 检查允许源状态、前置条件和完成状态，再请求 `entry_path`。
- `FighterStateDefinition` 目前只有 `state_name`、`group_path`、`state_script`，没有转换依赖或判定引用。
- 转换库有转换数组及条件名到 Fighter 方法的映射；转换定义没有稳定 `transition_id`。

重要边界：Move 资源是静态定义，Move 不是每帧执行对象；State 脚本是执行协议。多个招式可保留不同状态路径和状态实例，同时在执行协议相同时引用同一个脚本类。每个状态实例应独立读取自己对应的只读动作配置，不能把计时、命中记录或其它可变运行态放进共享 `.tres`。

## 3. 目标资源模型

### 3.1 公共招式库与 Loadout 选择

新增 `FighterMoveLibrary extends Resource`，持有全游戏可装备招式的 `moves: Array[FighterMoveDefinition]`。`move_id` 是八位数字字符串（如 `&"01010001"`），作为库内稳定唯一键；`move_name` 保存可改、可重复的显示名称，不参与匹配。Builder 建立 `move_id → MoveDefinition` 索引；配置作者保证 ID 唯一，当前不新增重复 ID 预检。

Loadout 改为引用该库，并按 ID 选择招式：

```gdscript
@export var move_library: FighterMoveLibrary
@export var selected_move_ids: Array[StringName] = []
```

不建议 Loadout 再复制一份 MoveDefinition，也不建议用显示名称、输入按钮或资源数组顺序充当身份。UI 可显示库内名称，但保存稳定 ID。角色是否可装备、槽位限制等更高层规则以后再加，不阻塞第一版构建闭环。

### 3.2 招式引用状态，不复制状态定义

MoveDefinition 保留动作入口和输入/发动规则，但将当前内嵌状态数组收敛为完整状态路径依赖，例如 `required_state_paths: Array[StringName]`。Builder 用这些路径到 `FighterStateLibrary` 解析唯一的 `FighterStateDefinition`。

这样状态库是状态定义的唯一目录，MoveLibrary 是招式定义的唯一目录；招式声明“需要哪些状态”，而不是再携带可能与公共库同路径但内容不同的状态副本。角色显式选中的基础状态与所选招式需要的状态做有序并集，按完整路径去重。相同路径若来自多个来源，只允许解析到同一个库定义；禁止按后写覆盖来暗中替换脚本。

每个 Move 的 `entry_path` 必须出现在该招式依赖状态或明确允许的共享状态集合中。依赖路径存在、路径唯一和入口已装配由配置作者保证，当前不增加构建前验证或错误收集。

### 3.3 转换目录与按端点自动选择

保留 `FighterTransitionLibrary` 作为全局转换目录与条件方法表。每条 `FighterTransitionDefinition` 直接配置完整 `from_state` / `to_state`，保留自己的稳定 `transition_id`，用于资源标识、调试和测试定位。状态与招式定义不再包含 `transition_ids`，也不维护转换资源引用清单。

构建顺序是先确定最终状态集合，再从库中自动选择连接这些状态的规则，而不是让状态以转换清单为装配前提：

- 合并 Loadout 显式状态与已装备 Move 的 `required_state_paths`，只实例化这些叶子。
- 状态的 `group_path` 决定所属分组；转换不重复声明分组，端点使用完整路径。
- 已装配叶子和具有有效默认入口的父分组是可用端点；未装配叶子、空分组不是。
- 按转换库数组顺序扫描，两端均可用时纳入候选；带 `move_id` 的规则还要求该 Move 已装备。
- 不按端点对或 `transition_id` 合并规则，保留同一对端点的多条规则和自身转换；不生成库中不存在的连接。
- 装配只决定能力存在，活动源、输入候选、条件和完成模式决定运行时能否使用；没有合法入口的状态不会因已装配就自动可达。
- `action → neutral` 等分组端点同样参与筛选，不仅检查叶子两两组合；直接扫描转换库即可，不必枚举状态对。

当前继续保留混合执行：同组普通转换注册到 Fray，跨组普通转换及招式转换交给 Fighter external 桥接。本次只简化转换选择，不统一执行入口，不修改执行顺序或 `auto_advance` 语义。

### 3.4 执行脚本复用、动作数据与判定预留

- 保留每招独立 `move_id`、入口完整路径和通常独立状态定义；不同路径可以指向同一 `state_script`，由 Builder 各自 `.new()`。
- 给通用执行协议需要的招式数据保留一个只读动作配置引用位置（可后续新增 `FighterActionDefinition`，或先由状态定义接收经 Move 传入的定义）。在本轮只规定引用边界，不实现计时/伤害/动画逻辑。
- 将来动画以语义 key 进入动作配置，外观资源解析 key 为素材；换皮不隐式改变战斗数据。
- 在 MoveDefinition 或 StateDefinition 预留可空判定定义引用的扩展点，最终只选一个权威依赖路径，避免两处重复维护同一 HitState。当前不加载 PackedScene，不实例化框，不接信号，也不改 `FrayHitStateManager2D`。

## 4. 角色构建职责与顺序

当前 Builder 按以下顺序构建，不新增构建计划类或资源合法性预检：

1. 读取 StateLibrary、MoveLibrary、TransitionLibrary，为状态路径和 move_id 建立查找表；配置作者保证资源有效。
2. 按 `selected_move_ids` 解析已选 MoveDefinition，输入层使用同一份 `selected_moves`。
3. 合并 `selected_state_paths` 与已选 Move 的 `required_state_paths`，按完整路径去重。
4. 创建固定分组骨架及状态路径需要的分组，为每个最终叶子创建独立状态实例。
5. 自底向上配置分组默认入口，收集可用叶子及可进入分组。
6. 按库顺序筛选两端可用的转换；非空 `move_id` 还必须已装备，结果保存为 `selected_transitions`。不再收集或查询转换依赖 ID。
7. 同组普通转换注册给 Fray；其余规则继续交给 Fighter external 桥接，并绑定各自条件；只读取入选规则的条件映射。
8. 绑定已选 Move 的公共 `prereqs`，向 FighterInput 提供已选招式。
9. 初始化状态机，进入 Loadout 指定的 `entry_path`。

MoveLibrary 只负责内容查找，不能绕过游戏层的来源、候选、前置条件及完成模式检查。本次不修改 Fighter。

## 5. 计划实施阶段

### 阶段 A：目录与引用模型

1. 新增 `FighterMoveLibrary` 脚本及 `resource/state_machine/move_library.tres`（或项目最终确定的 `resource/moves/` 路径）。
2. Loadout 改为引用 MoveLibrary 并选择 `move_id`；更新 demo Loadout 与 Inspector 资源。
3. 明确状态唯一来源：Move 改为状态完整路径依赖，Builder 从 StateLibrary 解析，不再由 Move 内嵌状态副本覆盖索引。
4. 先将现有 demo move 放入库并维持零招式时角色可启动；若当前 demo 没有已配置招式，补一个最小测试招式资源而不改变默认装备。

### 阶段 B：转换端点自动筛选

1. 保留转换自己的 `transition_id`，但不把它作为装配许可。
2. 删除 StateDefinition、MoveDefinition 的 `transition_ids` 和 `.tres` 中对应赋值。
3. Builder 不再收集 `selected_transition_ids`；先构建可用状态集合，再顺序扫描 TransitionLibrary。
4. 以两个端点可用且关联招式已装备作为筛选条件，继续使用 `condition_methods` 绑定入选规则条件。
5. 不改 Fighter external 桥接或同组普通转换的 Fray 注册路径。

### 阶段 C：构建器与运行时接线

1. Builder 从 Loadout 解析选招和状态，合并状态依赖；配置作者保证库定义唯一，不使用同路径覆盖表达角色差异。
2. 更新 Fighter 初始化，使状态机构建、输入候选注册都使用同一份已解析的已选招式集合，避免两边各自按不同来源查找。
3. 保持现有命令识别、候选消费、`_try_move()` 发动规则和 MANUAL 推进次序；本阶段不扩写输入指令类型。
4. 若增加构建期计划对象，确认其中只保存静态解析结果，不让多个 Fighter 共享可变运行状态。

### 阶段 D：回归与配置验收

1. 用不同 Loadout 构建角色，验证选中招式才会装配其专属状态、转换和输入指令。
2. 验证共享状态按路径去重、转换库只扫描一次，不同 Move 选择次序不改变最终规则集合或库顺序；不合并同端点的不同规则。
3. 验证只装 idle、idle 加轻攻击、空分组、未装备招式但两端存在、同端点多规则和自身转换；配置有效性仍由作者负责，不新增预检。
4. 验证没有选择招式时 Fighter 仍能以 idle 构建并运行；选择一个基础攻击后可识别输入并走现有请求路径。
5. 验证两个 Fighter 共用同一 Loadout/库资源时，Fray State 实例互相独立。
6. 更新 `tests/neutral` 和状态机资源配置说明，执行 headless 测试及 Godot 项目导入/运行检查。

## 6. 首期范围与明确不做

首期完成：MoveLibrary、以 ID 选招、状态依赖合并、转换端点自动筛选、状态机构建、输入层已选招接线与自动化测试；不新增配置合法性预检。

首期不做：

- 动画资源、AnimatedSprite2D 选帧、皮肤编辑器或自定义外貌工作流；仅确认动画语义 key 的架构方向。
- 战斗内热换装、运行中重建状态机、角色槽位/解锁/平衡规则。

- 新输入 matcher、连招缓冲和取消机制；维持独立的输入系统计划。

## 7. 完成标准

- MoveLibrary 是全游戏招式目录；Loadout 通过稳定 move_id 明确选择，不再直接持有任意 MoveDefinition 列表。
- Builder 只从已选状态与招式解析其依赖，不隐式装配未选 Move 的内容。
- 最终状态按完整路径去重；转换按库顺序筛选，不因状态选择顺序改变规则顺序。
- 状态与 Move 不维护转换依赖清单；两端可用的规则自动纳入，关联的 Move 必须已装备，未装配端点正常筛除。
- FighterInput 与 Builder 使用同一组解析后的已选招式。
- 同协议招式可以复用脚本类而仍拥有独立路径和状态实例；动作运行态不会写回共享资源。
- 判定框尚未实现，未来可从 Move 或 State 预留定义接入，且文档明确不重复维护依赖。

当前实现以本节为准；前文新增动作资源、严格校验等条目仅作历史设计参考：

- 删除 `FighterActionDefinition` 及 UID、StateDefinition 的 `action_definition` 字段；不再为单段动作额外增加一层资源。

- 删除 `show_action_frame()`；进入攻击只调用现有 `play_animation()`。动画自主播放，逻辑帧独立决定阶段和结束。后续 Hitstop/变速如有需要再协调二者，不声称已具备严格逐帧同步。
- 保留 `elapsed_frames`，它是单次普通攻击进度，不是组合技队列。
- 删除游戏脚本中的断言、重复/缺失 ID 预检和仅服务校验的转换索引；内容作者保证配置有效。
- 保留依赖去重、未装备转换端点筛选、发动源/接地/完成检查：这些是构建和游戏规则，不是额外防御层。

## 11. 发动许可统一进入转换库（2026-10-26）

本节取代历史的 Move 来源白名单方案：

- 保留 Move 的 `entry_path`、`required_state_paths`；删除 `allowed_from_paths`。

## 默认转换资源条件修复（2026-10-26，当前配置）

### 根因与修复边界

默认 `transition_library.tres` 的普通移动边没有填写条件。项目转换定义默认 `auto_advance=true`，Fray 对空条件数组返回 true，基础移动状态沿用默认完成判断，所以每帧 `advance()` 都会选中第一条可走的边，出现 idle → crouch → fwalk → crouch 的无输入循环。

依据插件文档 [Controlling State Transitions](../../../../addons/fray/docs/state-management/controlling-state-transitions.md) 的条件及完成模式说明，并核对当前插件 `_get_next_transition()`、`_can_advance()` 和 `_is_all_conditions_true()`：业务限制应配置在转换资源，不能用恢复转换依赖 ID、关闭推进或把基础状态改成永不完成来掩盖。

本次只修改公共转换资源的条件，不改 Fighter、Builder、状态执行脚本或 Fray 插件。原来的按端点自动选边、同组原生推进及 external 桥接保持不变。

### 实际条件

- 所有指向 crouch 的基础边：`advance_conditions=["inputed_crouch"]`。
- 所有指向 fwalk 的基础边：`advance_conditions=["inputed_fwalk"]`。
- 所有指向 bwalk 的基础边：`advance_conditions=["inputed_bwalk"]`。
- fwalk → idle：`advance_conditions=["!inputed_fwalk"]`。
- bwalk → idle：`advance_conditions=["!inputed_bwalk"]`。
- crouch → idle：`advance_conditions=["!inputed_crouch"]`。
- action → neutral：`prereqs=["active_leaf_done"]`，继续使用 AT_END。
- 三条轻攻击发动边：`prereqs=["grounded"]`，继续保持 `auto_advance=false` 且要求对应招式候选。

基础边保持 `auto_advance=true`。当前原生 Fray 按库注册顺序选择第一条满足的规则，因此每个来源的具体目标边排在返回 idle 的边之前；不能依赖尚未实现的 priority 排序。返回 idle 只检查源意图结束，而不要求所有其他意图也结束：这样只装 idle/fwalk 时，改按未装备的后退也能退回 idle，不会困在 fwalk。下蹲优先由 FighterInput 中前后走意图排除下蹲实现。

### 回归约束

新增 `tests/neutral/test_transition_resources.gd` 与 `--suite resources`：直接使用默认 Loadout 和真实转换资源，不复制/补写条件；仅注入采样后的方向意图，隔离已知输入插件采样错误。验证无输入、持续输入、所有基础有向转换、斜下蹲、换面向、精简装配回退、接地发动及动作完成返回。

同时移除旧招式测试夹具替转换资源补条件的步骤，避免实际配置错误被测试修复后再验收。输入采样链与 `ispressed` 拼写错误仍是独立问题，本次不修改输入插件。
