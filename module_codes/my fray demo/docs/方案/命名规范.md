> 修订日期：2026-11-11。项目业务代码及新增资源统一遵循本规范；Fray 插件、Godot 内置接口及其覆写方法保持原名。

## 1. 基础格式

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录、脚本、场景、资源文件 | 英文 `snake_case`；目录按职责命名 | `state_machine/`、`fighter_loadout.gd`、`fighter.tscn` |
| 类、节点名 | `PascalCase`；约定的首字母缩写保持大写 | `FighterState`、`HitFX`、`HitSFX` |
| 函数、变量、参数、信号 | `snake_case` | `build()`、`state_path`、`attack_finished` |
| 常量、枚举成员 | `UPPER_SNAKE_CASE` | `GROUP_PARENTS`、`AT_END` |
| 枚举类型 | `PascalCase` | `AttackPhase` |

- 统一英语术语，中文用于注释和显示文本，不混用拼音和同义缩写。
- 优先使用下表约定的短写；未列出的术语先用完整单词，新增缩写先补充本规范。
- 脚本文件名与类名语义对应：`fwalk_state.gd` 对应 `FWalkState`，`hit_fx.gd` 对应 `HitFX`。
- 内部成员、内部辅助方法用 `_` 前缀；公共接口不加。Godot 回调和 Fray 覆写方法沿用原名。
- 重命名时保留 `.gd.uid`，同步场景、资源、分组路径、默认入口、条件映射和文档引用；大小写变化同样视为路径变更。

## 2. 缩写约定

### 2.1 统一词表

| 含义／完整词 | 文件、变量、运行时标识中的短写 | 类／节点示例 |
|---|---|---|
| 前进 `forward` | 行为前缀 `f`：`fwalk`、`fdash`、`fjump` | `FWalkState`、`FDashState`、`FJumpState` |
| 后退 `backward` | 行为前缀 `b`：`bwalk`、`bdash`、`bjump` | `BWalkState`、`BDashState`、`BJumpState` |
| 状态机 `state_machine` | `sm` | `FighterSMBuilder` |
| 特效 `effects` | `fx` | `FX`、`HitFX`、`FXPlayer` |
| 音效 `sound_effects` | `sfx` | `SFX`、`HitSFX`、`SFXPlayer` |
| 背景音乐 `background_music` | `bgm` | `BGMPlayer` |
| 动画 `animation` | `anim` | `AnimMap` |
| 配置 `configuration` | `cfg` | `MoveCfg` |
| 环境 `environment` | `env` | `FighterMoveEnv` |
| 位置 `position` | `pos`，如 `spawn_pos` | `SpawnPos` |
| 速度 `velocity` | `vel`，如 `move_vel` | `MoveVel` |
| 加速度 `acceleration` | `accel`，如 `fwalk_accel` | `WalkAccel` |
| 方向 `direction` | `dir`，如 `facing_dir` | `FacingDir` |
| 距离 `distance` | `dist`，如 `dash_dist` | `DashDist` |
| 索引 `index` | `idx`，如 `state_idx` | `StateIdx` |
| 标识符 `identifier` | `id`，如 `fighter_id` | `FighterID` |
| 界面 `user_interface` | `ui` | `BattleUI` |
| 生命值 `hit_points` | `hp`，如 `max_hp` | `HPBar` |

### 2.2 使用边界与大小写

- `SM`、`FX`、`SFX`、`BGM`、`UI`、`ID`、`HP` 在类名和节点名中保持全大写；在文件、变量、状态和资源键中使用小写。例如 `HitSFX` → `hit_sfx.gd` / `hit_sfx`，不是 `HitSfx`。
- 截短单词按普通单词处理：`anim` → `Anim`、`env` → `Env`、`accel` → `Accel`，不写成 `ANIM`、`ENV`、`ACCEL`。
- 方向前缀与行为直接拼接：`fwalk` / `FWalkState`，不混用 `forward_walk`、`f_walk`、`FwalkState`。`f`、`b` 仅表示相对角色朝向的前后，不代替世界方向 `left`、`right`。
- 不把方向前缀单独用作一般变量名；保持 `facing_dir`、`move_dir` 等含义明确的名称。
- `speed` 表速率标量，不替换成表示速度向量的 `vel`；引擎既有的 `position`、`velocity`、`AnimatedSprite2D` 等名称不改。
- `state`、`transition`、`condition`、`definition`、`library`、`loadout`、`builder` 不缩写，避免 `st`、`tr`、`cond`、`def`、`lib` 等含义不清的短写。
- `cfg` 仅用于一般配置，不替代已有角色明确的 `Definition`、`Library`、`Loadout` 后缀；不同时维护两个含义相同的名称。
- 缩写可按上下文使用，职责目录仍可保留 `state_machine/` 等完整词。避免将多个短写堆叠成难以辨认的名称。

## 3. 身份、名称与状态路径

### 3.1 职责划分

公共库身份使用稳定业务 ID，局部技术名使用 name，层级地址使用 path，显示文字使用明确显示字段。ID 不是数组下标、资源文件路径或 Godot UID。

| 字段 | 类型／范围 | 职责 |
|---|---|---|
| move_id | StringName，8 位数字，全招式库唯一 | 装备、输入候选及转换关联 |
| move_name | String，可改可重复 | 玩家显示文字，不参与匹配 |
| state_id | StringName，10 位数字，全状态库唯一 | 状态目录中的稳定身份 |
| state（Move） | Resource，Inspector 限定叶子／复合组静态定义 | 单一执行入口；单段引用叶子，多段引用组，不保存运行实例 |
| state_name | StringName，当前状态库全局唯一 | Fray 直接子状态技术名，基础选择按此名称解析 |
| states（复合定义） | Array[FighterStateDefinition] | 本容器的直接叶子引用；按 ID 解析到权威库 |
| transitions（复合定义） | Array[FighterTransitionDefinition] | 本容器的内部边；端点是该容器直接孩子 |
| transition_id | StringName，转换库唯一 | 转换规则身份，保留可读名称 |
| from_state/to_state | StringName | 转换 owner 的直接孩子，可指向叶子或显式组 |

同一状态定义可供多个角色共用，运行对象仍独立创建。编号决定引用身份，不决定动画、输入、分组、战斗阶段或转换权限。

### 3.2 招式 ID：8 位

沿用 `CC SS NNNN` → `CCSSNNNN`，如 `01 01 0001` → `&"01010001"`。

大类/小类各两位，流水号 0001～9999；00 大类、00 小类、0000 流水号不分配招式。完整分类及招式登记见[招式编号模板](招式编号模板.md)。编号以文本保存，禁止转整数或丢失前导零。

### 3.3 状态 ID：统一 10 位

#### 招式所属状态

```text
CC SS NNNN II → CCSSNNNNII
└─ move_id ─┘ └ 两位状态序号，00～99

01010001 + 00 → 0101000100  轻攻击首个状态
01010001 + 01 → 0101000101  同招式后续新状态（仅示例，未登记）
```

- 按所属招式的八位 move_id 加两位状态编号分配，第一份从 00 开始，后续 01～99。
- 两位序号是稳定身份的一部分，不表示起手/有效/恢复阶段、自动执行顺序或数组位置；运行时不通过截取 ID 推导路径或转换。
- 00 是首次分配的叶子序号，不表示执行入口；单段由 Move.state 指定，多段由组的 start_state 指定，不硬编码后缀或数组顺序。
- 多个招式可显式引用同一个已登记状态 ID；编号前缀记录首次归属，不要求每个引用者复制、重新编号，也不作为反作弊授权凭据。

#### 非招式状态

保留招式不能使用的 00 大类，使用 `00 GG NNNN II` → `00GGNNNNII`。

| GG | 非招式行为组 | 编号用途，不是已实现功能清单 |
|---|---|---|
| 01 | 基础地面行为 | 待机、前后走、下蹲 |
| 02 | reaction 受击反应 | 受击、倒地、起身 |
| 03 | common 通用流程 | 出生、回合开始/结束 |
| 04 | airborne 空中移动 | 起跳、空中移动、落地 |
| 05 | defense 防御行为 | 格挡、通用防御动作 |
| 99 | 其他已明确的非招式行为 | 无现有分类可归属时登记 |

NNNN 为组内条目流水号 0001～9999，II 为条目内状态序号 00～99。每个新条目从 00 开始，单状态行为只使用 00。未登记组码保留，新增类别先更新本表。

#### 已分配状态 ID

| state_id | 状态路径 | 资源 |
|---|---|---|
| `0001000100` | idle | resource/states/idle_state.tres |
| `0001000200` | fwalk | resource/states/fwalk_state.tres |
| `0001000300` | bwalk | resource/states/bwalk_state.tres |
| `0001000400` | crouch | resource/states/crouch_state.tres |
| `0101000100` | light_attack | resource/states/light_attack_state.tres |

表内以外的号码只是预留/示例，不代表已实现或已发号。首个基础移动新条目可申请 0001000500，轻攻击后续新状态可申请 0101000101。

### 3.4 注册与装配边界

- 每个状态资源显式填写 state_id，并登记进当前权威 StateLibrary；资源文件继续使用语义 snake_case 名称，改文件名不自动改 ID。
- Loadout 的基础状态暂保留 selected_state_paths，但也只能从当前状态库取得定义；招式按 state_id 从同一库查找。
- 状态库顺序变化不改变合法 ID 引用。当前直接在 Loadout 中建立索引，暂不检查空 ID、重复 ID 或重复完整路径，内容作者须保证这些约定；错误的重复项可能发生字典覆盖，不能把当前行为当成冲突诊断。未知状态 ID 仍会拒绝整个选择，不补入外部资源。
- 改状态局部名或分组不改 state_id；仍需同步转换端点、初始路径和分组入口。状态 ID 与状态路径职责不同，不能因新增 ID 就删除 Fray 路由字段。
- ID 发放后不重用、不自动重排；新增状态先登记占号，删除状态的号码作废。超过两位状态容量前修订规范，不能绕回 00 或临时加位。
- 格式/登记表的一致性放在内容制作和测试中检查，不靠编号切片驱动游戏逻辑，不自动发号。

### 3.5 安全与稳定性

目录白名单是内容引用边界，不是完整反作弊系统。客户端可修改 state_id、状态库、脚本或招式数据时，编号不能证明内容可信；仅限制“必须在当前库中”也不证明该状态获准用于某一招式。未来联机需要由权威端使用可信内容、验证装备/解锁权限和内容版本，不能信任客户端提交的 Resource 或自定义状态库。本轮未实现联网、防篡改、签名、解锁树或冲突表。

move_id/state_id/transition_id 属于不同业务域，不能以 Godot UID、sub_resource ID 或 resource_name 替代。修改业务 ID 必须迁移所有引用及已有存档；修改显示名不改 ID。动画键、逻辑按钮和状态局部名继续使用语义名称，不批量数字化。

## 4. 条件与布尔值

- 条件和布尔变量按语义使用前缀：`is_` 表事实，`has_` 表拥有，`can_` 表能力，`inputed_` 表输入意图。
- 示例：`is_grounded`、`has_meter`、`can_cancel`、`inputed_fwalk`。不要把“按了攻击”命名成“能够攻击”。
- 条件键统一 `snake_case`。`inputed_<intent>` 保留为通用输入意图查询，例如 `inputed_fwalk` 绑定 `FighterInput.has_intent(&"fwalk")`，不要求存在同名函数，也不写入 condition_methods。其他条件仍由 condition_methods 映射到无参 bool 方法；同一作用域内相同键必须具有相同含义。
- 条件键保存正向名称；取反在规则中写 `!inputed_fwalk`，不再注册重复的反向条件。
- 保留现有字段 `advance_conditions`、`prereqs`、`condition_methods`；不为了命名规范随意更换 Fray 对应术语。

## 5. 转换

- from_state、to_state 使用所属 owner 的直接孩子名；例如根的 light_attack→combo1、组内 B→C、根的 combo1→idle。
- transition_id 保留为全库唯一规则标识，不参与选装许可筛选。
- command 非空为逻辑输入边，空为普通条件边；不以 move_id 将命令一对一绑定到转换。
- 自然组出口配置 AT_END；修正后的插件负责递归等待当前子状态，不再重复配置 active_leaf_done。

## 6. 类型、资源与容器

- 类型后缀固定含义：`State` 是运行状态，`Definition` 是静态条目，`Library` 是可共享候选库，`Loadout` 是角色选择清单，`Builder` 是构建逻辑。
- 招式条目使用八位数字 `move_id` 和显示用 `move_name`：前者稳定唯一，后者可改可重复，不承担相同作用。入口、状态依赖、按钮和动画键分别保留，边界与编号模板见第 3 节。
- 项目通用的全局类型使用 `Fighter` 前缀，使用 `FighterState`、`FighterMovement`、`FighterMoveEnv` 等明确名称；具体叶子使用明确行为名，如 `IdleState`、`FWalkState`。
- 配置文件按用途命名：`state_library.tres`、`transition_library.tres`、`<character>_loadout.tres`。
- 数组用复数：`states`、`transitions`、`selected_state_paths`；字典按用途表达键值关系，如 `state_definition_by_path`、`condition_methods`。
- 避免 `data`、`obj`、`temp` 等模糊命名；配置定义、资源引用和运行实例应能从名字区分。

## 7. 节点、动画、输入、判定与单位

- 场景节点按职责用 `PascalCase`：`Fighter`、`StateMachine`、`HitStateManager`；脚本引用变量用对应的 `snake_case`。
- 动画键、输入动作、标签统一 `snake_case`。动画可用 `fwalk`、`fdash`；输入表达意图，如 `move_left`、`light_attack`，不要绑定具体键名或具体招式名。
- 动画键可与状态同名，但不强制一一对应；`animation_key` 唯一保存在 FighterStateDefinition，Move 不再复制该字段，也不再并存同义 anim_key。所有状态通过 play_state_animation() 请求播放，表现入口在 Fighter，未来映射只预留解析函数。
- 特效统一使用 `FX` / `fx`，音效统一使用 `SFX` / `sfx`：如节点 `HitFX`、`HitSFX`，文件 `hit_fx.tscn`、`hit_sfx.tres`，变量 `hit_fx`、`hit_sfx`。特效不另用 `VFX`，音效不混写为 `FX` 或泛称 `sound`。
- 背景音乐使用 `BGM` / `bgm`，不要归入 SFX；一般音频服务仍可叫 `AudioManager`，不强行按音效命名。
- 明确区分物理碰撞体、攻击框（`hitbox`）、受击框（`hurtbox`）和判定配置（`hit_state`），不要都叫 `collision` 或 `state`。
- 信号描述已发生的事件，如 `attack_started`、`attack_finished`；事件处理方法用 `_on_<source>_<event>`。
- 数值单位统一使用 `_frames`（帧数）、`_s`（秒）、`_ms`（毫秒）、`_px`（像素），如 `startup_frames`、`duration_s`、`delay_ms`、`dash_dist_px`。帧数不缩成 `_f`，避免与前进方向混淆。
- 与物理量组合时明确单位，如 `fwalk_speed_px_per_s`、`fwalk_accel_px_per_s2`；同一模块已经明确约定统一单位时，可保留 `fwalk_speed`、`fwalk_accel` 等简写并在配置类型中注明。


## 8. 招式与内部阶段（2026-10-25 补充）

- 每个特殊技固定方向序列＋指定逻辑攻击按钮，不为同一招自动生成 _light／_medium／_heavy 三份数值版本；现有 light_attack 等仍是按钮名，不要求重命名。
- 默认每招有自己的 `move_id`、完整叶子路径和独立状态实例；相同执行协议可复用脚本类，例如多条路径复用 `BasicAttackState`，不要求每招复制脚本。
- 普通 startup／active／recovery 是本叶子内部阶段，使用 AttackPhase 枚举与明确单位的帧数字段，不默认命名为三个 Fray 状态路径。
- 当前显示节点为 AnimatedSprite2D，不添加无用途的 AnimationPlayer／AnimPlayer 节点；AnimMap 等仅为命名示意，不代表新增实现。
- 判定场景使用 <move>_hit_state.tscn，判定定义使用 <move>_hit_state.tres；引用 PackedScene／静态定义，不把运行节点实例命名成 Definition。


## 9. 角色选择与构建结果：统一使用 selected

### 9.1 前缀与数据范围

- `selected_` 表示本角色配置选中或按依赖收集后的内容，不表示当前活动、全局可选或界面临时焦点。
- Loadout 保存作者或玩家的选择；Builder 解析选择并补齐依赖，构建结果仍使用 `selected_`，注释写清范围。
- 后缀表达实际数据：ID 用 `_ids`，完整状态路径用 `_state_paths`，定义集合用具体对象复数，不用一个 `selected` 同时表示多种数据。
- Builder 的 `selected_moves: Array[FighterMoveDefinition]`、`selected_transitions: Array[FighterTransitionDefinition]` 是只读定义集合，不是正在执行的实例。
- `selected_transitions` 必须包含本角色所有入选且端点可用的转换，不能只保存跨组或桥接子集；若确需子集，名称必须补充范围。
- 私有成员保留 `_` 前缀，例如 Fighter 的 `_selected_transitions`，与公共构建结果 `selected_transitions` 含义一致。
- `active_` / `current_` 表示当前运行状态，`candidate_` 表示待裁决输入，`draft_` 表示未确认配置；不要把它们都叫 `selected_`。
- `available_` 表示可用候选，`required_` 表示依赖，`selected_` 表示最终选择，三者不能混用。

### 9.2 当前业务字段

| 含义 | 名称 | 保存内容 |
|---|---|---|
| 角色显式选择的基础状态 | `FighterLoadout.selected_state_paths` | 完整状态路径数组 |
| 装备的招式选择 | `FighterLoadout.selected_move_ids` | 全局招式 ID 数组 |
| 基础状态加招式依赖 | Builder 局部 `selected_state_paths` | 去重后的完整状态路径数组 |
| 解析后的已选招式 | `FighterSMBuilder.selected_moves` | 招式定义数组 |
| 端点可用的全部已选转换 | `FighterSMBuilder.selected_transitions` | 转换定义数组 |
| 角色使用的全部已选转换 | `Fighter._selected_transitions` | 构建器输出的转换定义数组 |

State 与 Move 不再维护 `transition_ids`，Builder 不再收集 `selected_transition_ids`；转换自己的 `transition_id` 继续作为稳定标识保留，不参与装配筛选。

当前没有新增 `selected_states` 字段；目前保存的是路径，因此使用 `selected_state_paths`。以后若确实暴露 `Array[FighterStateDefinition]`，使用 `selected_state_definitions`；若保存运行时 `FighterState` 实例才使用 `selected_states`，避免把定义、路径和实例混为一谈。

## 10. 自定义角色外形与部件（未来约定）

本节是未来业务命名，不代表已实现这些类型、字段或编辑器。

### 10.1 外形、部件与槽位

- 角色外形统一使用 `appearance`；`skin` 仅指具体皮肤或贴图方案，不统称所有外形部件。
- 可组合的视觉部件使用 `appearance_part`；节点组件继续称 `component`，不要将头发素材与逻辑组件混称。
- 部件位置使用 `slot`，可选素材使用 `part_id`；例如 `hair_front` 是槽位，`hair_short_01` 是部件 ID。
- 槽位标识使用 `snake_case`：`body`、`head`、`hair_front`、`hair_back`；确有独立选择需求时再新增，不预设全部槽位。
- `front` / `back` 表示发型等视觉层次时写全词，不使用表示移动方向的 `f` / `b` 前缀。
- 部件 ID 在所属 AppearancePartLibrary 中稳定唯一，不使用显示名称、贴图文件名或数组序号代替。

### 10.2 类型与选择字段

| 职责 | 未来建议名称 | 内容 |
|---|---|---|
| 单个外形部件定义 | `FighterAppearancePartDefinition` / `fighter_appearance_part_definition.gd` | part_id、槽位和视觉资源 |
| 全游戏可选外形部件库 | `FighterAppearancePartLibrary` / `appearance_part_library.tres` | 只读部件定义集合 |
| 外形部件目录引用 | `appearance_part_library` | 全局部件库资源 |
| 按槽位保存的部件选择 | `selected_appearance_part_ids` | 槽位到 part_id 的字典 |
| 解析后的部件定义 | `selected_appearance_parts` | 槽位到部件定义的字典 |
| 配置界面未确认的外形选择 | `draft_appearance_part_ids` | 槽位到 part_id 的草稿字典 |

因为外形有多个有语义的槽位，字典名称和注释必须说明键值，例如 `selected_appearance_part_ids: Dictionary[StringName, StringName]` 的键是槽位，值是部件 ID；不要只用无上下文的 `selected_parts` 或单个 `selected_skin`。

示例仅表示配置关系：

```text
selected_appearance_part_ids:
    body       -> body_base_01
    hair_front -> hair_short_front_01
    hair_back  -> hair_short_back_01
selected_move_ids:
    "01010001" # 轻攻击，已实现
    "02010001" # 地面特殊技编号示例，尚未创建资源
```

### 10.3 外形与招式的边界

- 招式目录仍叫 `move_library`，装备选择仍叫 `selected_move_ids`，不与 `appearance_part_ids` 混在同一数组。
- 玩家自定义角色招式配置是选择已定义招式，不等于自定义状态脚本或任意修改输入指令。
- 招式进入的状态通过 StateDefinition.animation_key 请求动画语义，角色表现层将来解析为当前外形各部件的显示；当前仅预留原样返回的解析入口，不把身体或头发贴图塞入 MoveDefinition，也不重复保存动画键。
- 外形部件默认只改变表现；若以后体型、武器长度影响战斗，另设明确战斗配置，不根据贴图尺寸暗改判定。
- 只有外形或只有招式的清单应分别命名，不能都泛称 `character_data`；现有 `FighterLoadout` 可作为角色构建选择入口，是否拆分子资源由实际需求决定。

## 11. 命名修改的执行边界

- 统一命名时同步脚本、测试、资源和当前说明，不为凑齐命名系列新增空类型或未使用字段。
- `selected_` 是内容选择语义，不改变转换条件、输入裁决或状态机推进顺序。
- 函数用一句 `##` 说明作用，资源字段按身份、引用/依赖、规则、表现和数值顺序排列并简短注释。


## 12. 状态脚本与资源目录

现有执行脚本统一放 scripts/states/fighterstates/，包括共用 fighter_state.gd 与各叶子；不按动作类型再加子目录，也不预留空类型目录。状态定义统一放 resource/states/。


## 13. 判定资源与构建命名

- FighterHitStateDefinition / fighter_hit_state_definition.gd 是静态姿态定义；FighterHitStateBuilder / fighter_hit_state_builder.gd 只从 Loadout 构建，不作为运行时 Controller 或 Runtime 保存。
- hit_states 表示静态判定定义资源到本角色 FrayHitState2D 的映射，Builder 与 Fighter 使用一致名称。不以节点名或资源文件名替代定义身份。
- _current_hit_state 表示当前姿态节点，不表示全库条目或已装配集合。select_hit_state / clear_hit_state / set_hit_state_mask 是 Fighter 的运行时入口，不放进 Builder。
- 姿态定义统一放 resource/combat/hit_states/，场景统一放 scenes/combat/hit_states/；使用 *_hit_state.tres / *_hit_state.tscn，不按动作分类建子目录。当前轻攻击文件 01010001_hit_state 使用招式编号帮助归档，不改变状态路径或动画键。
- HURT / ATTACK / PUSH 表示框用途；当前物理层为第 2/3/4 层（位值 2/4/8），与世界实体碰撞层分开；default_active_hitboxes 是框启用位掩码，不是物理 collision_mask。


## 14. 输入设备绑定与输入类型命名

### 14.1 设备到角色输入的绑定

设备分配统一使用 device／binding，不称为 session。FighterInputBindings 保存 device ID 到当前 FighterInput 的弱引用映射，既支持多个设备独立查询，也检查同一设备的活动占用。它不是物理按键重映射、网络会话、Matcher 历史或组合技执行会话。

| 名称 | 含义 |
| --- | --- |
| _device_bindings | Dictionary，device ID → FighterInput 的 WeakRef |
| bind_device(device, fighter_input) | 登记设备归属并检查当前活动占用 |
| unbind_device(device, fighter_input) | 仅在绑定仍属于该输入对象时解除 |
| get_device_input(device) | 取得设备当前绑定的角色输入对象 |
| fighter_input | 参数／局部变量，表示实际输入上下文对象，不泛称 session |

条件输入回调 _faces_left(device) 通过 get_device_input 查询该角色已发布朝向。配置、设备切换和离场都使用同一组绑定接口；不保留旧函数别名。设备 ID 不是 P1/P2 身份，绑定本身也不会把同一个键盘自动拆成两个输入通道。

### 14.2 Combination、Sequence 与组合技

- SINGLE：单按钮触发，可另检查触发时方向；不是多步序列。
- COMBINATION／FrayCombinationInput：多个按钮组件共同成立，例如轻拳＋重拳。Bindings 的 for command in commands 仅处理此类型，按排序后的 buttons 去重定义，并返回 command_id → 复合输入名。
- SEQUENCE：按时间顺序匹配方向／按钮，例如下→下前→前→轻拳；由 FighterInput 编译到 SequenceTree／Matcher，不由上述循环注册。
- Combo／组合技：状态之间的接续流程，可复用原子攻击输入；不能因为有多段攻击就把它命名为 Combination 或额外整串 Sequence。

当前按钮组合定义使用 ASYNC，共同持有即可成立；各 Command 的按下帧容错与方向限制仍由 FighterInput 检查。required_direction 不属于 Bindings 循环生成的组合键名，不把当前“方向快照检查”误述为已注册方向＋攻击复合树。


### 14.3 输入配置与历史清理

configure 表示战前注入依赖并编译配置，返回 void；不维护重复配置成功标记，也不为缺失推进器或错误初始化顺序静默回退。clear_history 表示清除运行历史，不表示 new Matcher 或重新编译树；重新编译仅发生于 configure。公开 Matcher.clear_history 在游戏层使用，私有 _reset 不跨插件直接调用。设备／焦点权限、同源消费与时限是游戏规则，不归为配置兜底删除。毫秒换帧直接使用 Fray.msec_to_frame；保留 frames_to_seconds 处理插件整数秒精度问题，不新增无调用的转发接口。
