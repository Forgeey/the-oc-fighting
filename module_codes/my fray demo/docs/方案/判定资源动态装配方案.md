# 判定资源动态装配方案

> 修订日期：2026-10-27。
>
> 状态：本轮已实施动态装配、姿态选择/清理、朝向镜像和专项测试。只新增项目侧判定代码，不修改 Fray 插件；当前验证及既有转换资源问题见末尾“实施结果”。
>
> 本方案保留此前讨论的资源模型和首期范围，替换旧方案从第 4 部分开始的初始化安排：**删除 Fighter.tscn 预置的 Manager；在 Fighter._ready() 初始化过程中，先离树组装完整的 Manager + HitState 子树，再一次性挂载到 Fighter。** 不增加 Fighter._enter_tree()，不实现战斗中热注册。
>
> 当前决策：FighterHitStateBuilder 直接读取 Loadout 解析判定依赖，不读取 TransitionLibrary，不依赖 FighterSMBuilder 的构建输出；不新增 FighterHitStateRuntime。原“计划”文档已移至本目录并更名，不保留双份正文。
>
> 先前《判定系统动态装配方案》仅作历史设计背景；若其内容涉及 _enter_tree 提前装配、BuildPlan/VisualRoot、Runtime 类型或从 SMBuilder 获取状态集合，本轮初始化、命名与最小改动边界以本文件为准。

## 1. 本轮范围

### 完成

- 从同一份只读 Loadout 解析已选状态与已装备招式的状态依赖，收集判定定义，不增加第二份判定装备清单。
- 只实例化需要的完整判定姿态；同角色相同定义去重，不同角色节点与可变形状独立。
- 在运行时创建唯一 Manager，预先装好全部 HitState，整体挂给 Fighter。
- 保证原生 Manager 的 ready 接线、source、姿态互斥和接触信号转发正确。
- 进入状态时选择姿态、应用默认掩码，退出时可靠关闭旧框。
- 让判定随角色朝向镜像，保留当前动画播放和预留解析入口。
- 补充专项与原有行为回归测试、实际资源和接入说明。

### 不完成

- 攻击有效帧自动开启 Attackbox；只预留 Fighter 统一应用掩码的入口。
- 命中队列、去重、伤害、生命值、受击、防御和推挤解算。
- 双人对战场景、AI、hitstop、自定义动画映射或完整外观系统。
- 战斗中换装、向已 ready 的 Manager 追加/移除姿态、角色移出再加入的完整生命周期协议。
- 重写插件、转换检查、MANUAL 推进、输入裁决或招式 ID 规则。

轻攻击本轮装配完整姿态，但默认只开 Hurt/Push，Attackbox 保持关闭。Pushbox 仅提供判定范围，不会自动把角色推开。

## 2. 资源模型

### 2.1 判定定义

新增 scripts/hit/fighter_hit_state_definition.gd：

```gdscript
class_name FighterHitStateDefinition
extends Resource

@export var hit_state_scene: PackedScene
@export var default_active_hitboxes: int = 0
```

- hit_state_scene 根节点为 FrayHitState2D，保存完整姿态。
- default_active_hitboxes 是该场景自己的默认启用掩码；位序按直接子 FrayHitbox2D 的实际顺序计算，不把非框节点的索引当框位序。
- 共享资源只存静态配置，不保存 Fighter、运行节点、当前掩码或命中进度。
- 常态资源的默认掩码明确开启其 Hurt/Push；空定义与零掩码的禁用行为由 Fighter 的判定选择/清理入口统一处理。

### 2.2 只由状态定义引用

FighterStateDefinition.hit_state_definition 从 Resource 预留字段改为可空 FighterHitStateDefinition：

```text
Loadout.selected_state_paths + 已选 Move.required_state_paths
    → 最终 FighterStateDefinition
        → hit_state_definition
            → 完整 HitState PackedScene
```

Move 不重复增加判定依赖；不恢复 transition_ids，不按未选择的全库内容生成判定节点。

无判定定义的状态允许存在，但进入后必须清理之前的姿态，不能继承旧框。

## 3. 首批姿态和框属性

首批只制作三套几何：

| 姿态 | 绑定的行为 | 包含的框 | 默认开启 |
|---|---|---|---|
| standing | neutral/idle、neutral/fwalk、neutral/bwalk | Hurtbox、Pushbox | Hurt、Push |
| crouch | neutral/crouch | 较低的 Hurtbox、Pushbox | Hurt、Push |
| light_attack | action/basic_attack/light_attack | 本姿态 Hurtbox、Pushbox、Attackbox | Hurt、Push；Attack 关闭 |

建议目录：

```text
scripts/hit/
resource/combat/hit_states/neutral/
resource/combat/hit_states/action/basic_attack/
scenes/combat/hit_states/neutral/
scenes/combat/hit_states/action/basic_attack/
```

每套姿态包含一个矩形 Pushbox，初版 Hurt/Attack 也先采用简单矩形，不追求逐帧美术拟合。节点结构遵循插件的直接子级约束：

```text
FrayHitState2D
├─ Hurtbox      FrayHitbox2D
│  └─ CollisionShape2D
├─ Pushbox      FrayHitbox2D
│  └─ CollisionShape2D
└─ Attackbox    FrayHitbox2D  # 仅攻击姿态
   └─ CollisionShape2D
```

新增最小 @tool FighterHitboxAttribute，继承 FrayHitboxAttribute，区分 HURT/ATTACK/PUSH、调试颜色及最小检测关系；不加入伤害、硬直等结果数据。战斗判定层/掩码与世界实体碰撞分开，同源框的过滤继续使用 Fray source 机制。

## 4. 初始化方式：完整 Manager 离树组装后整体挂载

### 4.1 方案

正确顺序不是“先把空 Manager 加到 Fighter，再补子节点”，而是：

1. 创建一个尚未进入 SceneTree 的 FrayHitStateManager2D。
2. 把本角色所有选中 HitState 实例作为它的直接子节点加入，全部保持禁用。
3. 将这个完整子树一次性 add_child() 到 Fighter。
4. Manager 首次 ready 时就能遍历全部姿态并完成插件原生接线。
5. 挂载就绪后设置 source，再允许状态初始化激活姿态。

Manager.new() 本身就是创建运行实例。给它装好子节点后 add_child() 即可，不需要把已组装的节点再 PackedScene.pack()/instantiate() 一遍，也不需要每个角色生成/保存一份 Manager .tscn。

### 4.2 为什么不需要 Fighter._enter_tree()

Godot 的新子树具有自己的首次进入和 ready 流程，子节点先 ready、父节点后 ready。Fighter 已处于 ready 初始化过程中，不会让刚创建的 Manager 跳过首次 ready。

当前 Manager 的 _ready() 遍历其已有直接子 HitState，因此只要子树在挂载前完整，就满足它的原生注册方式。没有运行期热注册，也不手工复制插件的信号连接逻辑。

Godot 节点生命周期依据：官方 Node 文档的 Description 与 _ready/add_child 说明；实际行为另用当前 Godot 4.7 与工程插件做临时用例核对，结果见第 10 节。

### 4.3 删除场景中预置 Manager

修改 scenes/Fighter.tscn：

- 删除 FrayHitStateManager2D 节点及只为该节点使用的脚本 ext_resource。
- 其他现有节点路径不变，不增加 VisualRoot，不移动 Sprite、实体碰撞体、Controller 或状态机。

修改 fighter.gd 的成员：

```gdscript
var hit_state_manager: FrayHitStateManager2D
```

不再使用 @onready 的 $FrayHitStateManager2D 查找；运行时装配完成后保存直接引用。为方便调试，可给动态节点仍命名 FrayHitStateManager2D，但该名称不作为判定定义资源身份。

### 4.4 判定 Builder 直接读取 Loadout，不依赖状态机输出

新增 FighterHitStateBuilder，入口为 `build(loadout: FighterLoadout) -> FrayHitStateManager2D`。只读以下字段：

- loadout.selected_state_paths：显式选择的状态。
- loadout.selected_move_ids：已装备招式的数字 ID。
- loadout.move_library：将所选 ID 解析为 MoveDefinition，并读取 required_state_paths。
- loadout.state_library：将最终状态路径解析为 StateDefinition，再读取 hit_state_definition。

不读取 loadout.transition_library、转换端点、转换条件、SMBuilder.selected_transitions 或组默认入口来推导判定依赖。转换控制何时从哪里到哪里，不是判定资源的所有者。

解析步骤：

```text
state_path → StateDefinition 查找表
move_id → MoveDefinition 查找表
    ↓
selected_state_paths
    ∪ 已选 Move.required_state_paths
    ↓ 按完整路径有序去重
最终需要的 StateDefinition
    ↓ 读取非空 hit_state_definition
按判定定义资源引用去重
    ↓
完整离树 Manager + HitState 子树
```

不能只遍历 selected_state_paths，否则会漏掉仅由招式依赖带入的攻击判定；也不能扫描所有 Move 后装入它们的状态。Move.entry_path 是否已列入 required_state_paths 继续遵循当前配置约定，不为判定 Builder 单独补入一套与状态机不同的隐式状态规则。

初版允许两个职责明确的 Builder 分别从同一个 Loadout 解析相同的选择关系，以消除构建次序和输出依赖，而不是复制两份可编辑选择。配置在本次构建过程中保持只读，路径去重及招式依赖合并规则必须一致；通过一致性测试约束它们，不为此提前新增通用解析框架。未来选择规则明显复杂且两边开始漂移时，再抽取无状态的公共解析工具，不让 SMBuilder 变成判定 Builder 的上游。

FighterSMBuilder 保持当前接口，不为判定装配新增 selected_state_definitions 输出，也不要求先创建行为树才能构建判定。它现有 selected_moves 仍服务输入配置，selected_transitions 仍服务转换执行，不在本轮删除或转交给判定 Builder。

### 4.5 Fighter._ready() 内的实际顺序

```text
现有 Fighter._ready() / _init_fighter()
├─ 初始化输入动作、物理执行顺序、世界碰撞体和 Movement
├─ 创建一次性的 FighterHitStateBuilder
├─ hit_builder.build(loadout)
│  ├─ 直接解析已选状态 + 已装备招式的 required_state_paths
│  └─ 返回完整离树 Manager，并提供“定义 → HitState 实例”绑定字典
├─ Fighter 接收 Manager、绑定字典，保存自己的运行时当前姿态引用
├─ Fighter.add_child(hit_state_manager)
│  └─ Hitbox → HitState → Manager 完成首次 ready 和原生信号接线
├─ hit_state_manager.source = self
├─ 设置初始 facing，并同步图像/判定镜像
├─ 原有 FighterSMBuilder.build(fighter, loadout) 创建行为状态树
├─ 按 SMBuilder 现有 selected_moves 配置输入，保存 selected_transitions
└─ state_machine.initialize(context, root, entry_path)
   └─ 真实初始叶子进入，通过 Fighter 选择自己的判定姿态
```

原 _init_fighter() 中依赖 Manager 的 source 设置、判定镜像以及必要的 set_facing() 调用调整到 Manager 挂载之后。MANUAL、暂停的 Advancer、输入采样顺序保持原样。

source 不在离树装配阶段通过 Manager.source 指向已在树内的 Fighter：该 setter 会为姿态计算相对 NodePath。统一在挂载后、初始姿态激活前设置，避免跨树路径问题；无需插入额外的物理帧等待。

使用插件当前普通同步生命周期，挂载完成后即可继续初始化。本轮不使用 call_deferred("add_child", ...) 再立即初始化状态机，否则会制造新的先后顺序问题。若未来改成异步加载/延迟挂载，再显式等待 ready 后继续，不把它隐含进当前接口。

## 5. Builder 的职责与构建后的运行管理

### 5.1 命名：FighterHitStateBuilder

新增 scripts/hit/fighter_hit_state_builder.gd，类名 FighterHitStateBuilder，继承 RefCounted。

Builder 的职责只有一次性构建：

- 直接读取同一份 Loadout，解析状态选择与已装备招式的状态依赖。
- 按 FighterHitStateDefinition 资源引用去重；同定义一次，不按 state_name、节点名或 PackedScene 路径去重。
- 实例化完整离树 Manager 和全部所需 HitState，设置初始禁用状态。
- 处理需要独立修改的 Shape2D，避免不同 Fighter 共享可变几何。
- 返回 Manager，并在 hit_state_by_definition 字典中提供“定义资源 → 本角色 HitState 实例”的构建绑定。

不负责选择当前姿态、退出清理、逐帧更新、攻击阶段、伤害、推挤或运行期热换装。不将同一个 Builder 长期保存到 Fighter 或状态 context，也不把 Runtime 的全部行为仅改名塞进 Builder。

构建接口简化示意（实现见 scripts/hit/fighter_hit_state_builder.gd）：

```gdscript
class_name FighterHitStateBuilder
extends RefCounted

var hit_state_by_definition: Dictionary[FighterHitStateDefinition, FrayHitState2D] = {}

func build(loadout: FighterLoadout) -> FrayHitStateManager2D:
    # 解析所选内容 → 离树组装 → 返回 Manager
    pass
```

每名 Fighter 本次初始化使用自己的 Builder；构建结束后将结果交给 Fighter，Builder 即可释放。返回结果是节点引用和映射，不是新的可编辑 Resource，也不需要再定义一个只为包裹两项返回值的构建结果类型。

### 5.2 Fighter 保存必要运行状态

Fighter 接收并持有：

- hit_state_manager：本角色唯一 Manager。
- _hit_state_by_definition：接收构建绑定的私有字典。
- _current_hit_state：当前由行为状态选择的 HitState 引用，允许为空。

将少量必要的运行入口放在 Fighter，具体名称在实施时依现有规范确定，例如 select_hit_state(definition)、clear_hit_state()、set_hit_state_mask(mask)。这些方法只封装判定姿态，不承担战斗结果。

构建绑定转交后不再由 Builder 改写。Manager 挂到 Fighter 后由场景树管理释放，Fighter 只保留本角色映射；不让状态切换重复实例化/释放节点。

这样不新增另一个 Controller/Runtime 类型，也不把 Builder 当作常驻运行服务。未来若运行管理显著增大，再按实际职责拆分，不在本轮预先增加空层。

### 5.3 零掩码与插件回调的注意点

插件当前 active_hitboxes_changed 处理函数会调用 hitstate.activate()，包括零掩码通知；不能认为调用一次 deactivate() 就一定使 is_active 标记与所有框状态一致。

清理由 Fighter 的公共判定方法统一封装：在当前姿态节点上短暂保存并屏蔽信号，清零 active_hitboxes、调用 deactivate()，然后恢复此前的信号屏蔽状态。清理完成后再正常激活新姿态，让 Manager 原生互斥接线生效。不调用插件私有 setter，也不改写插件的通用语义。

Fighter._current_hit_state 是本轮清理/选择的权威状态，不把 Manager 在“全部关闭”时可能保留的最后姿态名称误认为仍有框启用；不伪造清空它的私有 _current_state。

这一处理必须有测试覆盖：mask=0、is_active、monitoring、monitorable、visible 均符合预期，不能只测试节点隐藏。接触回调不得直接执行判定切换；未来真实接触结算仍在安全阶段处理。

## 6. 状态绑定与进入/退出

保留 FighterState.state_definition 和现有 fighter context 引用；状态通过 fighter.select_hit_state(...) / clear_hit_state() 等公共入口选择和清理姿态。不向 context 注入 Builder 或新的 Runtime，状态无需按节点名寻找姿态。

- FighterState 公共进入逻辑：按 state_definition.hit_state_definition 选择已装配姿态。
- FighterState 公共退出逻辑：清理本状态选择的姿态，不让旧框残留。
- Idle/FWalk/BWalk/Crouch/BasicAttackState 调用公共进入/退出协议，保留原移动、动画、计时功能。
- CrouchState 已有退出恢复世界碰撞体逻辑，必须同步调用父类清理。
- 无判定定义时清理旧姿态；共享 standing 的行为状态之间切换也走明确的退出与进入，不依赖旧掩码残留。
- BasicAttackState 本轮仅选择其默认 Hurt/Push 姿态，保留既有帧数和完成模式，不接 active 阶段开攻击框。

初始化、普通同组转换、external 跨组转换均通过相同状态生命周期选择姿态，不修改转换资源的输入/接地/完成条件，不恢复 transition_ids。

## 7. 朝向与节点结构

不新增 VisualRoot，不更改当前实体碰撞体和显示节点的位置：

- Sprite 继续按现有贴图方向使用 flip_h。
- 判定场景约定面向右、前方为局部正 X。
- 动态 Manager 挂载后，在 set_facing() 中只为 Manager 做一次水平镜像。
- 不再逐个翻转 HitState/Hitbox，不镜像 CharacterBody2D 的世界碰撞体。
- 图像和判定由同一个 facing_dir 驱动，但不要求两者使用同一种翻转属性。

当前动画键仍由 StateDefinition 配置，_resolve_animation_key() 预留接口不扩展。

## 9. 实施顺序与验收（下列首期功能已完成）

1. 运行现有 resources、moves、neutral 测试，固定修改前基线。
2. 增加判定定义、最小属性和三套场景，所有新框初始 monitoring/monitorable=false、掩码为零。
3. FighterHitStateBuilder 直接读取 Loadout，合并状态/招式依赖并完成离树装配和去重；不改 SMBuilder 输出。
4. 删除 Fighter.tscn 静态 Manager，在现有 ready 初始化链整体挂载并设置 source。
5. Fighter 接收构建绑定并提供姿态选择/清理，状态调用这些公共入口；补朝向镜像。
6. 增加新判定套件并运行全部回归和默认场景冒烟测试。

必须覆盖：

- Fighter.tscn 没有预置 Manager，生成后只有一个完整的动态 Manager。
- 默认角色只装配 standing、crouch、light_attack 三套；只选 idle 时只有 standing。
- 没有装备攻击且未显式选择攻击状态时，不装配攻击姿态；反过来，仅通过已装备 Move.required_state_paths 引入的攻击状态必须装配其姿态。
- 判定 Builder 独立工作，无需创建行为树；测试夹具未提供 transition_library 时也能构建判定，证明它没有读取转换库。
- 对同一只读 Loadout，判定 Builder 得到的状态依赖范围与 SMBuilder 实际装配的叶子一致，覆盖路径去重、多个招式共享状态、仅显式状态、仅招式依赖、相同路径末段但不同组的状态。
- 改转换规则、来源许可或条件不改变判定构建结果；已装配但当前不可达的状态仍按其定义装配判定，不能因没有转换就过滤其姿态。
- Builder 只构建；挂载后的选择/清理不再调用 Builder，Fighter 和状态 context 不保存 Builder 作为运行服务。
- idle/fwalk/bwalk 共用同一定义，单角色只创建一个实例；不同定义即便引用相同 PackedScene 也不误合并。
- 不同 Fighter 的 Manager、HitState、运行掩码和可变 Shape2D 独立。
- Manager ready 前已经具备全部姿态；原生信号每个只接一次。
- source 设置后到达全部框；初始状态进入前没有任何攻击/受击/推挤框提前启用。
- 首次进入 idle 时，standing 正确选择；任意状态切换、同姿态切换和 external 中断无旧框残留。
- 无判定定义、零掩码和全部清理路径正确处理，不因 Manager 的 activate 回调留下假活动姿态。
- Hitbox → HitState → Manager 的 intersected/separated 转发有效；本轮不把模拟信号测试等同于命中结算。
- 左右朝向切换几何正确镜像，无重复翻转；世界碰撞体和原动画不受影响。
- 原有招式 ID、状态动画、输入、转换条件及自动循环回归继续通过。
