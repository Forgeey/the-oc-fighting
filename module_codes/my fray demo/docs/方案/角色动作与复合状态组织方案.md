## 1. 用复合状态表达流程，而不是目录

```text
角色根 FrayCompoundState
  ├─ idle / fwalk / bwalk / crouch       多数基础移动直接同根
  ├─ light_attack                      无方向单键的基础攻击 A
  ├─ forward_medium                    方向＋攻击的基础攻击 A2
  ├─ fireball                          快速方向序列特殊技，可直接同根
  ├─ hitstun / knockdown               独立受击行为，可直接同根
  ├─ string_lmh : FrayCompoundState     真正有局部路线／生命周期的组合技
  │    ├─ second_hit B  ← start_state
  │    ├─ third_hit C
  │    └─ fourth_hit D（B/C/D 均可正常收招，无强制 done）
  └─ throw_forward : FrayCompoundState  一次投掷的专属流程
       ├─ grab          ← start_state
       ├─ throw_attack
       ├─ whiff_recovery
       └─ break_recovery（需要时，动作完成后由父出口离组）
```

- 大多数状态仍是根的直接子状态。只有进入／内部步骤／完成／退出确实构成局部整体的行为才建子组。
- **这是一种合适的 CompoundState 用法，不是唯一正确用法。**架势、飞行模式等有局部行为和共享出口的流程也可以用复合状态；简单攻击可以始终只用 FrayState。
- 同一状态脚本／只读资源可复用，但**一个 FrayState 运行对象只能属于一个父组**。若根基础攻击和组合技子段复用脚本／配置，要创建独立实例，不能把同一对象 add_state 两次。

## 2. 输入类型与执行结构分开

| 类型 | 输入识别／注册 | 执行结构 |
| --- | --- | --- |
| 基础移动 | 稳定 bind／前后条件输入，持续意图 | 同根直接状态及普通条件边 |
| 无方向单键攻击 | SINGLE，真实攻击按钮 press／配置的 release | 同根直接攻击叶子 |
| 方向＋攻击 | **按组合输入注册**：相对方向条件组件＋攻击按钮 | 通常同根攻击叶子；与两颗攻击按钮组合是同属复合输入但含义不同 |
| 组合技 | 单键或方向＋攻击组成的有序后续命令，按动作接收／取消时序接续 | 根起手 A → 路线子组，B→C→D；每段可完整恢复后自然停止 |
| 特殊技 | 固定快速 SEQUENCE，原生 Sequence／Matcher 识别完成 | 常可直接进入一个同根特殊技状态；多步骤执行才另建组 |
| 投掷 | 固定投掷命令，可由单键／按钮组合触发 | 根合法来源 → 投掷子组 → grab → 确认后 throw_attack |

**输入不是状态拓扑。**一个命令可以被不同活动来源的边接受；同一逻辑命令不对应唯一 move_id。一次 Matcher 命中也不自动规定攻击应有几个状态。

## 3. 方向＋攻击：组合输入注册的明确语义

### 3.1 目标接线

- 在 selection 之后统一向 FrayInputMap 注册需要的组合输入。例如 forward＋medium_attack、down＋light_attack。
- 前后由 FrayConditionalInput 按 device 查询**当前合法角色朝向**，不是按 P1/P2 身份；换边不重新注册，作者只写一份相对指令。
- 组合优先用 FrayCombinationInput 的 ASYNC 持有关系。先按住前，再按攻击可以发动；**方向与攻击不要求在两帧／10 ms 内同时按下**。两攻击键同步组合的容错配置不机械套用到方向＋按钮。
- 组合成立还要处理触发边：只有新的攻击按钮事件才创建本次攻击命令。先按住攻击，再转向或按方向使复合状态成立，不得自动多出一拳；如某招刻意允许此输入，作者单独声明。
- 若要求恰好“前”而不接受“下前”，需要当前规范方向约束／明确复合条件。单纯 all-components-held 不能证明其他方向没按。
- FraySimpleInput.from_bind 只引用 bind，不能假装已注册的复合名就是 bind。组合树中使用独立的 conditional／simple 组件构造，避免一个 composite 实例被多根重复拥有。
- 单键 M 与前＋M 重叠时在输入薄层按明确优先／归属规则裁决，不能先两者都入队后再靠状态随机选中。

### 3.2 当前实现差距

现有代码用 SINGLE.required_direction 读取按钮触发时方向；COMBINATION 只注册 command.buttons 的攻击按钮组合。**这还不是本节要求的方向＋攻击复合注册**。后续应迁移方向组合的输入资源与注册，不删除时序保护后把“held 变 true”当成真实攻击按下。本轮仅记录目标，不改运行代码。

特殊技的跨转向历史继续保持已有“世界方向记录、按完成时朝向解释整条路径”；不能因为移动／方向攻击使用条件前后，就把历史变成逐事件相对方向再声称行为等价。每角色继续只用一个原生 Matcher。

## 4. 组合技子组：从第二击进入，不重播第一击

### 4.1 同级转换直接交给 Fray，B/C/D 均可结束

```text
根：
  A --命令 M＋合法取消／请求提交--> combo1
  A --完整恢复且不接续--> idle
  combo1 --当前动作完成＋无合法待执行后续--> idle

combo1（start_state=B，end_state 不配置，is_persistent=false）：
  B --H 请求＋本连接可用＋B 段合法条件--> C
  C --K 请求＋本连接可用＋C 段合法条件--> D
```

根 A 与 combo1 是直接兄弟，B/C/D 是组内直接孩子。四个可展示结果为 A、AB、ABC、ABCD；不存在“必须打到唯一最后一击才能退出”的要求，也不强制加入 done。

`start_state=B` 只负责合法进入组后默认执行下一击 B，不重播 A，不在 enter 回调 goto(B)，也不根据完整路线反复修改默认入口。B/C/D 都是普通 FrayState，不因出现在多条招式表记录中就复制或再嵌套组。

同一个 group 内共享段，招式表条目可以分别有身份和名字；如何控制装备路线的合法连接见[组合技路线条目与多出口设计方案](组合技路线条目与多出口设计方案.md)。
### 4.2 输入窗口、取消提交、状态开始三个时刻

1. L 发动根的 A。
2. A 的接收窗口允许 M 被认领为本次路线的 B 请求；A 暂不退出。
3. A 到规定取消／衔接点时，复核真实活动源、请求、资源／命中等条件，执行根 A→string_lmh；这次事件只提交一次。
4. Fray 根据 start_state 进入 B，B 从第 0 帧开始起手／有效／恢复。
5. H 在 B 的合法窗口或明确允许的路线预输入窗口成为 B→C 请求；到 B 的提交点才执行。
6. 无有效后续则本段正常恢复，由根 combo1 出口条件结束路线；受击、跳出路线、死亡等立即清未执行后缀和攻击框。

取消剩余恢复通常用 **IMMEDIATE＋明确取消条件**，而不是 AT_END 等完整恢复结束。按键刚到达、start_state 已配置，都不能替代取消条件。

### 4.3 不同入口／分支

- 每个组只有一个 start_state，不要为一次命令临时改共享组的默认入口。
- A 接到 B、A2 接到 X 时可使用不同路线组；或者建立真正有意义的公共入口选择流程。首期优先明确分组，不恢复任意深层路径跳转。
- 路线在子组内部才分支时，B→C／D 使用普通 Fray 条件和输入边即可；已经执行的段、未来允许段和当前输入路线游标仍要分清。
- 同一类 B 可以在不同路线中有独立状态实例，读取相同只读 Attribute；不是把根 A 对象搬进子组。

## 5. CompoundState 不自动实现 MK 风格拨入缓冲

- 原版 FrayBufferedInputAdvancer 仍是 FIFO、统一期限、尝试失败即出队。M 过早且 A→组条件未开时，正常尝试会丢掉 M；不会在 commit_frame 自动重试。
- paused 可以推迟整队尝试，但不冻结墙钟、不等于逐路线输入窗口，也不能同时精确表达所有特殊技取消和组合后缀。
- 完整 dial-a-combo 若允许 A 期间连输 M、H，需要动作局部的有限路线请求／pending：输入进度可以领先执行进度；这属于游戏路线语义，不是第二个可重试全局命令缓冲。
- 这项局部协议尚未实现。实施前要决定事件在入 advancer 前由谁认领、何时从普通输入流排除、何时向转换提供“已请求接续”的条件／令牌；不能先让 advancer 失败丢掉，再声称还保留着。
- 只做“窗口打开时即时按 M 接 B”可以先用原生输入边实现，但**它不等同于完整预输入拨入体验**；文档和验收必须明确分期。
- 组合技不通过“整串 L→M→H 全部匹配才开始 A”的 Matcher 实现；特殊技取消仍由唯一 Matcher 识别，再检查当前动作／路线开放的窗口。

## 6. 投掷子组：抓取结果决定下一状态

```text
根合法来源 --throw 命令＋范围／姿态／取消条件--> throw_forward
throw_forward.start_state = grab

子组内部：
  grab --真实确认 captured--> throw_attack
  grab --抓取窗口结束且未确认--> whiff_recovery
  grab／throw_attack --合法拆投／失效事件--> break_recovery（逐招规则）
  throw_attack／whiff_recovery／break_recovery 完整结束，且目标事务可清理

根：throw_forward --明确自然结束条件--> idle
```

- 抓取不是普通攻击框一碰就保证成功。范围、可投状态、无敌、已被其他投掷占用、拆投等由战斗规则确认，组只按确认事实走边。
- captured 时必须绑定具体目标和本次抓取实例；不能只存一个全局 bool，然后让另一次投掷误用。
- throw_attack 是投掷专属攻击叶子，不从 grab 无条件推进；未抓到只能走空挥恢复。
- 被投角色有自己的状态机／受投状态，攻击者的 CompoundState 不会自动控制对方。锁定／位置同步／伤害／释放需要双方协议，目标失效和中断时清理。
- 抓取窗口结束可以 AT_END 到空挥恢复，抓到后立即过渡可 IMMEDIATE＋captured。攻击属性仍是 FighterHitboxAttribute 只读数据，各状态保存各自运行进度。

## 7. 组完成与生命周期：必须明确的 Fray 行为

### 7.1 递归完成与显式退出

两份 Fray 的 CompoundState 已修正：不设 end_state 时，等待当前子状态完成；设置 end_state 时，还要求当前是指定子状态且该子状态自身完成。子状态是组时递归查询，不再只检查名字，也不再需要额外 active_leaf_done 前置条件。

B/C/D 的 BasicAttackState 完整恢复前 false、恢复后 true。combo1 不设 end_state，因此任一段都能完整收招；父边 combo1→idle 配置 AT_END、auto_advance=true。没有 done，没有业务组子类。

有合法组内接续时仍优先执行子边；IMMEDIATE 取消不被恢复完成限制。未来 pending 等待仍需真实业务条件，不能由插件猜测。

完成为 true 本身不转换；仍必须配置父边并调用 advance。无边时不自动出栈，不自动寻找 idle。

### 7.2 父组行为与叶子行为分工

父组进入／退出管理路线实例、目标绑定等一次性事务；叶子进入／退出管理本段计时、动画和判定。B→C 时父组保持活动，避免每段重新初始化路线。子组默认 is_persistent=false，重入从 B／grab 开始，不恢复上次中断段。

父组不调用 FighterState 的攻击姿态清理流程；攻击叶子先 super-enter 选择自己的姿态，再读取属性。单个活动分支不代表父组和子叶子能同时拥有两套攻击框。

## 8. 已实施的局部组最小接线

| 位置 | 已实施 | 保持边界 |
| --- | --- | --- |
| 组定义 | state_name/start_state/states/transitions，StateLibrary.compound_states | 不新增 Node，不按目录造组，不配置唯一 end_state |
| 状态与边 | 叶子不记录父组；内部规则随复合定义存放，根边在转换库 | 归属由容器确定，同一静态定义可多处实例化 |
| Loadout | Move.state 引用叶子或组，selection 区分根放置和依赖并集 | 不自动装备子招式；装配成员不等于连接授权 |
| Builder | 原生组实例、默认入口、本地条件、普通／命令边注册 | 根下仅一层局部组；不枚举任意状态对 |
| Fighter | get_active_leaf 用于转向；插件负责递归完成 | 不把原生组当 FighterState，不替未来 pending 猜条件 |

当前支持的父出口是 combo1→idle 的 AT_END（prereqs 留空）；空 end_state 的组会等待实际子状态完成。若未来加入已认领、延后提交的接续，需要增加真实的无 pending 条件；本轮不新增 route_session。

完整路线身份、前缀依赖、授权与捕获事务仍属于后续业务，并非有了组接口就自动完成。

- 本次已实施局部组装配、插件递归完成及父 AT_END，测试通过正式 Builder 构建 B/C/D。没有往 Fighter 场景新增组 Node、回退插件或声称完整组合技／投掷内容已经存在。
- 临时原生 API 用例已验证 A→combo 默认 B、组内 B→C、显式 done、重入、grab→throw_attack／whiff 分支，共 19 项通过；其中有一项记录现存子组否定继承问题，测试用组内条件绑定绕开，不是正式修复。
