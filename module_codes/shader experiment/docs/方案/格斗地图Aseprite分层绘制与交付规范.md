# 格斗地图Aseprite分层绘制与交付规范

> 日期：2026-11-14。适用于“参考视角静态总图 + 分面/分深度素材 + 方案B相对映射”的制作流程。  
> 状态：本文件是制作规范与验收清单，不是已经实现的Aseprite自动导入器。当前运行代码只支持本文明确列出的子集。  
> 本轮只更新文档，不改场景、Shader、素材或屏幕配置。

## 1. 推荐流程：先画完整参考地图，再按用途拆出可动部件

**建议用一份Aseprite工程制作整张参考机位地图。** 它是构图、比例、色彩、透视和接合关系的统一母稿，不是要求把最终游戏地图压平成一张图片。

推荐顺序：

1. 确定战斗画面比例、参考机位与允许的相机X/Height范围。
2. 在透视辅助层记录地平线、主点、建筑共用的灭点方向、战斗线和画面边界。
3. 单独放入左右两名角色作比例参考，确认双方站位、头顶空间、动作与前景遮挡关系。
4. 用简单体块构建地面和建筑，先验证体量与透视，再细画纹理。
5. 各建筑正面、左右侧面、必要顶面分别绘制；按深度/动画/遮挡用途分组。
6. 隐藏前景及当前遮挡面，补画允许镜头移动后会露出的内容。
7. 对中央建筑，先隐藏正面完成独立侧面，再恢复总图合成；侧图记录非零面积的参考形状，需要时另用辅助视图标定。
8. 独立导出素材和标定记录，放入程序验证默认和极限机位。
9. 来回调整美术与世界体量，直至参考画面和移动效果都符合目标。

这与Aseprite的透明层、分组、可见性控制相配套；原始工程保留全部图层，导出时只选择需要的可见内容或独立层。[A1][A2]

**先在一栋建筑上走通完整流程，再绘制全地图细节。** 避免总图已画完，才发现正面/侧面切法、辅助机位或源像素比例无法使用。

## 2. 开画前的“地图规格单”

| 项目 | 必须记录 | 当前实验参考，不是强制所有地图照抄 |
| --- | --- | --- |
| 参考视窗 | 静态总图中的有效游戏画面矩形 | 当前输出1280×720 |
| 工程画布 | 总画布尺寸、参考视窗在画布内的偏移 | 可大于参考视窗，向四周预留可揭露区域 |
| 参考机位 | 相机世界X/Y/Z、朝向 | (0,210,-1400)，平视+Z |
| 投影中心 | 参考视窗内主点O、地平线 | O≈(640,460)，地平线v=460 |
| 焦距/视野 | 与总图透视相容的参数 | 当前f≈933.3333，单位为参考视窗像素 |
| 战斗线 | 双方站立的世界平面/深度、参考脚点 | 地面Y=0，战斗Z=0；脚点约(1080,600)/(200,600) |
| 相机运动范围 | 左右、最低/最高、是否有缩放/旋转 | 当前只改X/Height；无旋转，Z固定 |
| 建筑规格 | 世界位置、宽/高/深、需要哪些面 | 当前轴对齐立方体，无运行屋顶 |
| 素材分辨率 | 源图实际尺寸、有效区域、源图到总图的缩放/位移 | 每素材可不同，不由角色像素决定整屏规格 |
| 输出目标 | 参考窗口、测试分辨率、裁边/留边策略 | 当前内部1280×720、窗口同尺寸 |
| 美术范围 | 明暗是否烘焙、近远细节档位、是否需要独立阴影 | 不让程序重复压暗已画好的静态阴影 |

### 2.1 母稿画布不等于内部渲染分辨率

可以直接用1280×720参考视窗绘制，也可以用较低的工作尺寸作像素母稿，并在参考图中按明确倍数预览。

- 必须记录工作素材到参考视窗的变换，不暗中缩放、拉伸或丢失裁切偏移。
- 参考视窗之外用于镜头揭露的内容可以超出1280×720，不因“当前看不到”裁掉。
- 程序当前用1280×720渲染；更换2K/4K实验不意味着必须重画世界或从角色尺寸重新计算地图画幅。
- 不把动画帧的透明留白当成角色身高，角色是视觉标尺，不是全屏分辨率计算器。

### 2.2 地平线、主点与灭点不要混用

当前相机不旋转，建筑与世界轴对齐：

- 竖直边保持竖直。
- 固定Z正面为矩形，横边保持水平。
- 沿Z延伸的侧面边趋向主点O=(screen_width/2,horizon)。当前这个方向的灭点与主点重合。
- 其他配置下主点不等于所有方向的灭点；不能拿一个点吸附全部边。

因此当前原型适合**与固定朝向相机一致的一点透视布局**。如果母稿改成明显的两点透视、旋转建筑或俯仰相机，当前正面矩形与求交逻辑不会自动支持，需要另立功能计划，不能只靠四角扭曲假装完整支持。

## 3. 两个角色参考层：必须有，但不导出进地图

建议在母稿中保留以下独立参考层：

```text
REF_players（分组，不导出）
├─ player1_right
├─ player2_left_mirrored
├─ action_envelopes
└─ feet_and_battle_line
```

制作要求：

- 使用实际角色素材，右侧Player1、左侧镜像Player2，相向放置。
- 先按选定参考机位的实际显示比例放入，不强制所有角色永远源图1:1。
- 记录脚点，不以素材画布底部猜测脚底；当前idle素材有较多透明留白。
- 至少预留站立、伸展、跳跃、角落对战、武器/大型招式的范围；不能只验收两名角色站着好看。
- 预留HUD和重要特效区域，避免高对比建筑细节争抢角色轮廓。
- 两名角色层、辅助线、注释必须能单独关闭，不烘焙到地面或建筑导出图。

角色参考尺寸可以记录，例如现有有效宽约127、高约105～108源像素；这里仅用于资源识别，不用它反推屏幕高度或规定自定义角色都同大。

## 4. 分层原则：按空间、面、动画与遮挡拆，不只按颜色拆

建议的母稿层级：

```text
map_stage_master.aseprite
├─ REF_perspective（地平线/主点/灭线/参考视窗/机位记录，不导出）
├─ REF_players（两个角色与动作范围，不导出）
├─ sky（需覆盖可见范围）
├─ far_background
│  ├─ far_building_a
│  └─ far_building_b
├─ midground
│  └─ building_center
│     ├─ front
│     ├─ side_left
│     ├─ side_right
│     ├─ roof_if_required
│     ├─ ornaments
│     └─ shadow_if_separate
├─ ground
│  ├─ surface
│  └─ markings
└─ foreground
   ├─ tree_or_column
   └─ foreground_shadow
```

以上是本项目命名建议，不是Aseprite或Godot强制的目录结构。

### 4.1 图层顺序作为前后/深度顺序的制作约定

**可以约定母稿图层顺序暗示世界深度。** 例如顶层为近景、底层为远景，导出时保留这个顺序，代码据此建立初始绘制层级或有序景深档位。这是本项目主动制定的约定，不是PNG自带的空间信息。

建议规则：

- 天空最远；远景、中景、战斗附近、前景按组有序排列。
- 普通物件组位于哪个深度档位，由母稿中的组顺序暗示。
- 建筑组内部的front/side/装饰顺序只表示该建筑的组成/参考遮挡，不能把每个面都分配为独立景深层。
- REF辅助组不参与世界排序或导出，隐藏的有效侧面则仍需纳入导出清单。

**顺序只给出“谁在前、谁在后”，不给出“相距多远”。** 相同前后顺序可以对应很多不同的Z数值，而Z差决定视差和投影；因此必须补充明确的Z，或规定一张可调整的“深度档位→Z”表。不能仅靠图层索引恢复透视空间。

对于纯背景纸片，可以先按组顺序分配深度档位，再在游戏中调Z和世界尺寸；对于建筑，多个面共同构成一个体积，应配置一组位置、宽高深，再各自挂素材/参考四角。地面是水平面，不按竖直纸片处理。

最终运行绘制也不能永远只信母稿列表：如果对象会移动、遮挡会改变，仍需按运行时关系更新。当前原型的整栋z_index排序只适用于当前布局，不等于Aseprite顺序能自动解决任意交错遮挡。

## 5. 正面和侧面怎么画、怎么接

### 5.1 以总图透视先确定体块，再画像素细节

在母稿中先记录建筑各角点、正侧面接合竖棱、地基脚点与近/远端，确认体量与相机相容。然后分别完成墙面和像素轮廓，侧面可以保留按该参考透视直接绘制的像素台阶。

- 正侧面接合的高度、色彩、线条位置应连续。
- 接合边不要在两面各画一条厚边导致程序里合成双重轮廓。
- 跨面的招牌、管线、窗带应共享高度/定位；必要时拆为独立装饰对象。
- 不要求所有对象同样源图尺寸或世界纹素密度；要求在参考画面中颗粒、明暗和体量协调。
- 正面和侧面纹理不是可以任意互换的同一张图，侧面深度与正面宽度也不必相同。

### 5.2 与当前方案B配套的导出

正面目前使用矩形face_uv；侧面使用预绘参考四边形。

侧面必须记录四角，顺序：

```text
近端顶 → 远端顶 → 远端底 → 近端底
```

程序先求当前面位置，再回到参考四边形取色，避免把已有斜侧面的透明画布再次整体压入梯形。

如果参考建筑正面本身也是带透视的非矩形，不应直接塞进当前Front Texture期待正确还原；当前只给侧面做参考四边形映射。两点透视正面需要额外的分面参考映射/几何支持，属于未实现功能。

### 5.3 源参考形状与当前投影形状不必相同，但要可标定

每张侧面图可以有自己的参考四边形；当前三栋建筑共用wall2只是演示，不要求正式素材都按同一个斜度画。

最好从程序投影的角点建立母稿辅助线，再像素化细画，减少反解歧义。若先凭美术画好，再接入，也应允许调世界体量和参考四角；四点只确定一个平面映射，不会复原作者未知的相机或任意局部手工修形。

## 6. 中央建筑：隐藏正面补画侧面，再恢复正面

**本规范采用你提出的制作操作：Aseprite中先隐藏front图层，把独立side图层补画完整，完成后再恢复front图层可见。** 侧图作为独立资源保留，默认总图看不到它也不等于不需要制作。

### 6.1 被遮住的侧图可以保留并交给Shader使用

制作时可以在同一工程中先画好一张有面积、方向和角点的侧面模板，让它在最终合成中被front或其他物体遮住。隐藏front只是为了看见并编辑这张模板；恢复front后继续检查总图，不必为了保存隐藏侧面把它强行露在参考画面里。

程序读取的是**侧图资源及其参考四角**，不是合并总图中最后剩余的可见部分。相机移动到一侧后，将该参考侧面映射到当前侧墙投影，它就可以显示出来。不要从合并图中截取一条被压扁的边当作完整侧图。

若母稿默认机位中的真实侧墙退化为线，隐藏front并不会改变该几何事实。但是不需要强迫画师只在那条线上作画：将侧面当成一个**独立、可被隐藏的非退化参考素材**绘制并记录它自己的四角即可。它可以留在同一工程，也可以另设辅助视图；**额外辅助相机截图不是每次必需的步骤**。

区别是：隐藏模板的位置/斜度属于其源参考，不必就是默认总图机位真实可见的投影；只要用正确四角标定，方案B可以将其映射到当前观察位置。零面积四边形依然不能作为有效标定。

### 6.2 相机到另一侧时，可以“对称”过来吗？

可以作为**允许对称复用的美术约定**，当前原型也这样做：

- 同一side_texture，局部横向始终近端0→远端1。
- 相机位于建筑另一侧，目标侧墙的空间方向改变，参考侧图随映射呈现相反方向。
- 不再为了“对称”额外随意做一次1-u，以免把近远角点反转。

但这是另一侧复用同一张侧面，不是Shader恢复了没画过的信息：

- 没有文字、明显非对称结构时，可以接受镜像复用。
- 左右窗户、招牌或文字不同，必须分别画left/right。
- 原图静态阴影也会随复用而变化；若左右光照不能镜像，需分图或把可变照明另做。
- 远近边高度、宽度仍随当前投影变化，不保证相机两边是简单水平flip后的同一屏幕形状。

当前代码是一张侧图+一套四角，支持对称复用；独立left/right素材槽仍未实现。

### 6.3 运行时不应靠手动关闭正面露出侧面

Aseprite中front的临时显隐是制作便利，不是运行时“显示侧面时必须隐藏正面”的规则。当前固定朝向、相机位于建筑前方时，左右平移通常同时看见正面和一侧，默认正对时侧面才可退化不见。

Shader根据当前射线命中哪张墙决定取正面还是侧面；不需要把整个front资源关闭。以后若支持转到建筑背后，需另做面可见性和背面，不由本次隐藏图层操作自动获得。

## 7. 补画与防露空：补的是会被揭露的有效区域

“每层尽量画满”应精确理解为：**镜头允许范围中可能被看到的实物表面必须有内容**，不是把所有透明画布涂满。

### 应补画

- 被近景树/人物挡住的地面和远墙。
- 正侧面接合处稍后会暴露的边缘。
- 镜头向上后露出的天空/建筑上部，向下后露出的前景地面。
- 左右移动后露出的背景边缘。
- 动画物件离开原位置后露出的底图。

### 应保留透明

- 物件轮廓外的留白。
- 侧面参考四边形之外的画布区域。
- 真实洞口、树叶间隙以及另有后景填充的镂空。
- 按遮挡设计应显示后层的区域。

透明洞口不意味着存在内部空间；若相机可透过洞口看到内部，需另画内部面/后景，否则只是透明孔。Alpha直接填实或把正面烘焙进侧图都可能破坏遮挡关系。

## 8. 补画范围如何估计

先确定允许相机范围，再估计素材覆盖，最后用极限机位验证；不凭感觉只加固定几十像素。

### 8.1 固定Z平面背景的简化估算

在焦距、相机Z与Horizon不变时，该层投影系数：

```text
s = focal_length / (layer_z - camera_z)
水平相机变化ΔX → 图层屏幕变化Δu = -s*ΔX
相机高度变化ΔH → 图层屏幕变化Δv = s*ΔH
```

可据此为参考画框计算左右/上下额外覆盖范围。左右机位、最低/最高高度不对称时，补画边距也分别计算，不强制四边相等。

若源素材在参考画面有已知缩放a，屏幕边距转换为源图补画量约为“屏幕边距/a”，还需考虑裁切偏移。这里只适合平面背景；当前跨深度的侧墙/地面不能一律按单个s估算。

### 8.2 地面和侧墙用可见区域并集

对允许相机的角点机位及中间采样：

- 将视窗采样点投到有限地面/建筑面上。
- 只保留有效交点，取这些可见表面区域的并集。
- 为采样误差、边缘覆盖与少量镜头插值保留余量。
- 面UV非线性、遮挡变化较大时不能只看一张截图；四角机位也不自动证明所有中间机位已覆盖。

当前地面shader在地平线附近可能得到很远的交点，但有限ground_min/max会裁切；制作时应明确地图边界外是天空、远景还是不允许看见，不要求无限补画。

本节为覆盖分析方法，当前没有自动扫描/生成补画区域的工具。第一张地图可用程序极限机位截图+人工叠图完成。

## 9. 图层导出与坐标记录

### 9.1 两种导出方式选一种，不能默默混用

**A：保留母稿全画布**

- 各层使用共同画布，位置容易核对。
- 透明区域较多，运行资源可能浪费；面四角仍应对应有效表面，不能取整张画布四角代替。

**B：各物件/面裁成独立PNG（推荐运行资源）**

- 记录原裁切矩形crop_rect、脚点和参考四角。
- 母稿中位置为p，裁切左上为c时，局部坐标为p-c；有导出缩放a则为a*(p-c)。
- PNG尺寸、角点、pivot必须在同一导出像素单位内。
- 只保存母稿坐标而丢掉裁切偏移，会让方案B映射或接合位置错误。

导出按指定层/组清单执行，不能带入角色参考、透视线或注释。**总图预览中隐藏的有效侧图也要单独导出**，不能只导出合成时的可见层，否则会漏掉刚补画好的面。建议先列资源清单，再逐个显示/导出或使用指定层导出。Aseprite导出与层机制参考[A1][A2]；具体名称与菜单以所用版本为准。

### 9.1.1 必须记录：图层距母稿画布四边的像素距离

**每个运行资源除了图片本身，还必须记录它在绘制画布中的位置。** 你在Aseprite中按Ctrl查看上下左右距离的操作，可以作为手动采集这些信息的入口。具体快捷键与显示对象以本机版本、工具和按键配置为准；不能把测量框、选区、当前帧cel范围和最终导出裁切框默认为同一个范围。

采集时选定目标层/组和对应帧，核对显示的边界到底包住了什么。资源可以临时单独显示，避免误测到前景、角色参考或其他层。截图可作辅助，但最终需将像素数填入交付表，不仅保存在截图里。

#### 统一记录口径

- 原点：**母稿全画布左上角**；X向右，Y向下；单位为母稿源像素。
- 记录画布宽高 `canvas_size=(W,H)`，不能只记四个距离而不记画布尺寸。
- 距离顺序固定为 `canvas_margins=(left,top,right,bottom)`，不要与其他工具的上下左右排列混用。
- 明确测的是 `content_bounds`（目标资源有效内容范围），还是 `export_rect`（实际保留透明边距的导出范围）。两者可能不同，**必须分别记录**。
- 范围使用像素边界、右/下端不含的矩形约定；例如宽200表示占200列，不是201列。若显示的是最后一个像素的索引，计算右/下边界时需要加1。
- 补画、移动图层、改变画布、裁切、导出缩放或增加透明留边后，要重新采集；旧距离不能继续套用。

设目标范围左上为 `(x0,y0)`，宽高为 `(w,h)`：

```text
left   = x0
top    = y0
right  = W - (x0 + w)
bottom = H - (y0 + h)

x0 = left
y0 = top
w  = W - left - right
h  = H - top - bottom
```

因此四边距与画布尺寸能够还原该二维范围。只需要定位时，`(x0,y0,w,h)`已足够；仍保留四边距可方便与Aseprite的读数逐项核对。

若内容或cel延伸出母稿边界，右/下/左/上距离可能为负，不能悄悄截成0。应明确记录越界或先扩大母稿；同时确认PNG导出没有把这些补画区域裁掉。完全透明的资源没有有效内容范围，应明确标为辅助/不导出，不能拿它产生任意世界位置。

#### 数值例子

```text
母稿 canvas_size = (1280,720)
目标内容四边距 = (200,120,880,200)

content_bounds = (200,120,200,400)
```

如果按有效范围紧裁切且不缩放，导出PNG为200×400；将它的左上角放回母稿 `(200,120)`，就能还原原来的位置，而不是任意居中放置。

如果为了透明留边，实际导出 `export_rect=(192,112,216,416)`，则PNG左上应放回 `(192,112)`；内容在PNG内从 `(8,8)` 开始。**不能拿内容左上 `(200,120)` 当PNG左上，否则又偏移8像素。**

### 9.1.2 将四边距、裁切、脚点与参考四角放进同一坐标链

四边距解决“素材原来在画布哪”，脚点与四角解决“素材的哪个位置要对齐、怎样映射”。建议同时记录：

| 信息 | 坐标空间 / 用途 |
| --- | --- |
| `canvas_size` | 母稿全画布尺寸 |
| `reference_viewport_rect` | 游戏参考视窗在大母稿中的位置；可与画布不同 |
| `content_bounds` / `canvas_margins` | 有效内容在母稿中的范围 / 四边距 |
| `export_rect` | 真正裁切范围，包含有意保留的透明边 |
| `export_scale` | 母稿像素到导出像素的倍率，默认1 |
| `export_padding` | 裁切缩放后额外添加的透明边；左/上偏移以导出像素计 |
| `pivot_canvas` / `reference_corners_canvas` | 脚点或面角点在母稿中的位置 |
| `pivot_texture` / `reference_corners_texture` | 最终PNG中的位置，当前材质标定应使用这一套 |

当前规范默认不旋转、不非等比缩放、不翻转导出；若另做这些操作，需要额外记录并转换，不能仅套下面的平移公式。

设母稿点为p、实际裁切左上为c、等比导出倍率为a、额外左/上留边为b：

```text
PNG局部点 q = a * (p - c) + b
还原母稿点 p = c + (q - b) / a
```

例如紧裁切 `(200,120,200,400)`、放大2倍、不另加边：母稿脚点 `(300,520)` 在400×800的PNG中为 `(200,800)`。脚点可以位于底部边界，不必恰好是一个不透明像素中心。参考四角按完全相同公式转换，不能一部分保留母稿坐标、一部分使用PNG坐标。

如果用于还原游戏参考画面，先从母稿位置减去 `reference_viewport_rect.position`，再应用“参考视窗→当前渲染画面”的明确变换；不要误用大母稿原点当游戏视窗原点。独立侧面模板/辅助视图中的测量数据应绑定其自己的画布与参考视图ID，不能当成主总图上的实际摆放位置。

### 9.1.3 代码接入与回贴检查

1. 先在一个**纯二维参考重组预览**中，按记录位置把PNG放回母稿；这里验证导出定位，不先掺入动镜头。
2. 若使用左上原点的TextureRect，可直接对应还原后的矩形；普通Sprite2D默认中心原点则需补偿图片半尺寸，或显式采用已记录的pivot。不能把左上位置直接当中心位置。
3. 检查正侧面接合棱、地面标记、背景轮廓与角色参考是否和母稿吻合，可叠加半透明总图作对照。
4. 静态回贴无误后，使用世界深度、体量和面参考四角接入伪3D；当前建筑/角色Transform会被脚本计算覆盖，不把回贴的屏幕位置直接写入它们就结束。
5. 对组导出使用最终组合资源的范围；动画逐帧裁切时逐帧记录偏移，或使用统一固定裁切框，避免动画抖动。当前静态地图优先固定导出范围，减少隐式变化。

**上下左右距离可以还原参考机位的二维摆放，但不能独自确定世界X/Y/Z、建筑厚度或相机参数。** 参考画面重组是第一步，伪3D空间设置是第二步；两者的数据共同交付，才不会在程序中凭感觉乱放。

Aseprite官方脚本接口区分 `Cel.position`、`Cel.bounds` 和 `Cel.image`，将来若做采集工具可以据此读取对应信息；这些范围仍需与有效Alpha范围、组导出范围及最终PNG裁切框核对，不能直接混同。[A3] 当前项目没有实现自动采集器或地图生成器。

### 9.3 分层导出后，代码如何构建地图

**是的：母稿画好后，将需要独立显示/投影的层或组分别导出，代码再用这些图片和清单构建地图。** 不必导出所有画笔辅助层，也不必为每个仅用于上色的内部子层创建游戏节点；不会独立变形/运动的绘画子层可合并导出为一个运行资源。

建议的构建步骤：

1. 按导出清单导出sky、背景物件、地面、各建筑front/side、独立装饰与动画。
2. 保留母稿层/组顺序、画布尺寸、四边距、content_bounds、实际export_rect、导出缩放/留边，以及每张图的object_id、脚点和面四角；先通过二维回贴验证位置。PNG单文件不会自动保留这些对应关系。
3. 代码按资源类型选择显示方式：背景纸片/视差层、地面Shader、建筑盒子与方案B材质、普通动画等。
4. 用明确Z或深度档位表设置空间；母稿顺序可用于初始层级/档位，但不能给出精确深度差。
5. 同一建筑的front/side绑定到同一个建筑对象，配置World Size与参考四角，避免把不同朝向的面误当平行图层。
6. 默认机位先还原参考总图，再移动相机检查补画、对称复用、遮挡和侧图揭露。

初期可以完全手动在Godot中建节点并指定PNG，这是当前原型的接入方式；将来可以读取导出清单自动生成，但本轮没有自动读取aseprite/JSON、推算Z或还原建筑的代码。

**单靠“一组PNG+文件名排序”通常不足以重建可移动伪3D地图。** 如果保留共同全画布，默认2D合成定位会简单些；一旦需要深度视差、参考侧面投影或裁切导出，仍需要上面的空间与坐标元数据。

## 10. 地面、阴影、装饰与动画

### 10.1 地面不要和立面共用错误的素材解释

- 当前ground_texture按世界X/Z平铺，输入是无透视地面模块。
- 母稿里的预透视完整地面不能直接丢进这个槽位再透视一次。
- 可以从母稿单独制作无透视地面模块；若确需使用整张预透视地面，应另加地面参考映射，当前未实现。
- 地面模块边缘、色块和线宽需要测试重复与远处压缩，不把原生一像素线当任何距离都清楚的保证。

### 10.2 静态明暗与动态光照分开

- 如果侧面已手绘暗色，避免再默认强乘固定阴影。
- 不需要随着角色或光源变化的阴影可烘焙；会移动、被遮挡或单独淡出的阴影应分层。
- 不把角色影子画死在地面里。
- 正式动态日月光、光束和反射仍是未来独立实验，不作为本轮母稿规范已实现功能。

### 10.3 跨面装饰和动画需要自己的锚点

吊灯、旗帜、树叶、门、招牌若独立运动，单独图层和稳定pivot。跨面对象在动镜头后需要正确空间锚点；不能把母稿上的屏幕位置直接当成永久世界坐标。

## 11. 验收：一张漂亮总图不等于可移动地图

### 参考机位

- [ ] 总图与程序默认画面在几何、站位、主要接合边上匹配。
- [ ] 角色参考层已从运行地图中排除。
- [ ] 每个资源记录母稿画布、帧/层/参考视图、上下左右距离；测量范围与实际导出裁切框已区分。
- [ ] PNG按记录的偏移/倍率/pivot回贴母稿后，接合边与构图一致，没有任意居中或重复补偏移。
- [ ] 参考角点在正确的裁切局部坐标中。
- [ ] 正侧面未被二次透视，近远端没有反转。
- [ ] 素材手绘明暗未被重复压暗，Alpha未误填实。

### 可移动范围

- [ ] 最左/最右、最低/最高及中间机位没有未补画的实物区域。
- [ ] 中央建筑左右露面符合设计，没有为露侧面而错误关闭正面。
- [ ] 左右不对称内容没有被错误镜像。
- [ ] 镜头上移时若应看到屋顶，已实现屋顶或明确限制了相机范围；当前程序未画屋顶。
- [ ] 前景与后景遮挡、洞口后内容、物件移动后的底图均正确。
- [ ] 慢移录像检查纹理闪动、透明轮廓与接合棱，静态截图不能代替。

### 战斗用途

- [ ] 双角色、角落站位、跳跃、伸展与大特效有空间。
- [ ] 重要攻击轮廓不被前景或背景高频花纹遮蔽。
- [ ] 分辨率变化只改变显示采样/构图换算，不改变逻辑碰撞或攻击距离。
- [ ] 自定义角色的合理体型差异通过样例验证，不只按当前待机角色决定地图布局。

## 12. 第一张正式地图的最小交付

1. 一个保留透视线、双角色参考和分面层的Aseprite母工程。
2. 一张参考机位合成预览，以及机位/参考视窗记录。
3. 一栋建筑的front和隐藏补画side测试素材；允许对称复用时可共用side，非对称时分别left/right。每张side都有非退化参考四角，需要时附辅助视图。
4. 一份地面模块、覆盖充足的天空/背景，以及最少的前景遮挡物。
5. 每个运行资源对应的PNG、层/组顺序、object_id、画布尺寸、四边像素距离、内容/裁切范围、导出变换、脚点/四角记录、深度档位或Z和世界体量建议。
6. 默认、左、右、上、下观察图和一段慢移录像；记录允许相机范围。

先验证这一套，再扩大地图美术量。当前代码能接入front+一张side与四角；独立左右图、屋顶、预透视地面、自动分层导入都应在需要时单独实施，不在交付规范中假装已经存在。
