# 伪3D空间、素材尺度与参考映射公式

> 更新：2026-11-14。对照当前Reference / Nearest两个场景；旧示意图只解释数学，不代表启动配置。

## 1. 空间与单位

| 约定 | 当前含义 |
| --- | --- |
| 世界X | 向右 |
| 世界Y | 向上；地面Y=0 |
| 世界Z | 向地图深处；角色战斗线Z=0 |
| 相机 | 固定看向+Z，不旋转 |
| `Vector2 ground_position` | (世界X,世界Z)，不是X/Y高度 |
| 屏幕 | 逻辑视口左上为原点，右/下为正 |
| 素材UV | 图片相对坐标，不是世界坐标或屏幕像素 |

高度、尺寸、世界位置用同一套自定义世界单位。焦距、horizon、project()输出用当前视口的像素单位。源图像素与世界单位没有固定1:1要求。

当前父节点保持单位变换，没有额外Camera2D。若增加画布缩放或子视口，必须核对CPU投影与FRAGCOORD属于同一空间。

## 2. 相机变量

来源：`map_camera.gd`。

| 名称 | 当前值 | 用途 |
| --- | --- | --- |
| ground_position.x | 0 | 相机X，A/D修改 |
| ground_position.y | -1400 | 相机Z，按键不改 |
| height | 210 | 相机世界Y，W/S改，当前范围80～420 |
| focal_length | 约933.3333 | 焦距，当前视口像素单位 |
| horizon | 460 | 竖直投影中心，当前视口像素单位 |
| speed | 320 | 世界单位/秒 |
| initial_ground_position / initial_height | 启动值 | R复位依据 |

完整相机位置 `C=(ground_position.x,height,ground_position.y)`。`sync_shader_parameters(material,screen_size)`将其分解成camera_ground / camera_height等普通uniform。材质不是另一套相机配置。

horizon是构图偏移，不是pitch；Height真实升降与horizon整体平移的效果不同。

## 3. 世界点到屏幕点：CPU正向投影

来源：`scale_at(world_z)`、`project(point,screen_width)`。

```text
D = point.z - camera.ground_position.y
s = focal_length / D
screen_x = screen_width/2 + (point.x-camera.ground_position.x)*s
screen_y = horizon + (camera.height-point.y)*s
```

D是前向Z深度，不是欧氏直线距离。当前所有表面必须在相机前D>0，不处理穿近平面。

角色预览：

```text
position = round(project(世界脚点))
scale = world_units_per_texel * s
```

角色Z=0、相机Z=-1400、world_units_per_texel=3，所以当前1280×720输出缩放≈2。世界X=±660对应屏幕X=1080/200；脚点Y=460+210×2/3=600。这只是已有世界体量投影后的结果，不用于反推屏幕高度。

修改玩家Transform会被重算；Ground Position与Jump Height才是输入。改变深度会同时改大小、脚点与遮挡，不用于代替跳跃。

## 4. 素材像素、世界体量、屏幕大小

对于固定Z的竖直正面：

```text
N = 有效源像素高度
H = 世界高度
q = H/N，每个源像素代表的世界长度
P = H*focal_length/D = N*q*focal_length/D
```

若先决定希望屏幕高度P，再选深度D：

```text
H = P*D/focal_length
q = H/N
```

不要求所有物体q相同。105像素高的角色可代表315世界单位；同样105像素的远楼可代表1260世界单位，并放在4倍D处，同一参考机位显示高度相同。

远楼仍具有更小视差：

```text
水平相机移动ΔX → 屏幕移动量 = -ΔX*focal_length/D
```

在Y=0地面上，远处脚点更靠近horizon。因此屏幕一样高不等于失去空间感。

侧面跨越多个Z，地面有方向压缩；上述单个尺度用于正面标尺，不宣称每个表面每个格子完全等大。

## 5. 建筑几何与CPU范围

`building.gd`每帧计算：

```text
box_min = (ground_position.x-world_size.x/2,0,ground_position.y)
box_size = world_size
box_max = box_min+box_size
```

| 建筑 | ground_position(X/Z) | world_size(宽/高/深) |
| --- | --- | --- |
| LeftTall | (-360,450) | (240,620,400) |
| LeftFront | (-310,50) | (260,350,320) |
| Right | (330,240) | (280,460,380) |

脚点是正面底边中心，深度向+Z延伸，不是盒子体积中心。八角点经project()得到bounds，设置ColorRect.position/size。它只是承载矩形，真正墙形由Shader决定。

z_index=-int(正面Z)，玩家Z=0在这些建筑前面。整对象排序适合当前布局，不是任意交错体积的深度缓冲。

## 6. 屏幕到世界表面：GPU反向求交

两种建筑Shader和地面Shader都使用当前屏幕像素：

```text
origin = (camera_ground.x,camera_height,camera_ground.y)
ray = ((FRAGCOORD.x-screen_size.x/2)/focal_length,
       (horizon-FRAGCOORD.y)/focal_length,1)
P(t) = origin+t*ray
```

ray不归一化，ray.z=1，所以t等于前向Z深度。

| 平面 | 参数t | 后续有限范围检查 |
| --- | --- | --- |
| 地面Y=0 | -camera_height/ray.y | 地面X/Z范围；只保留向下射线 |
| 正面Z=box_min.z | box_min.z-origin.z | 建筑X/Y范围 |
| 侧面X=side_x | (side_x-origin.x)/ray.x | t>0、建筑Y/Z范围 |

普通平面Shader中distance_z也是这个t，不是斜射线直线距离。相机在建筑左/右侧时选择对应侧墙；相机在正面宽度内时侧面可以消失，不能保证任意机位都能数出台阶。

## 7. 普通平面UV与参考侧面UV

正面：

```text
u = (hit.x-box_min.x)/box_size.x
v = (box_max.y-hit.y)/box_size.y
```

侧面局部坐标：

```text
u = (hit.z-box_min.z)/box_size.z
v = (box_max.y-hit.y)/box_size.y
```

这里u从近端到远端，v从楼顶到楼底。Reference左侧不再额外1-u，因为同一素材已经由空间映射自然镜像。

普通平面Shader直接按wall_uv读取整张纹理；Reference将face_uv再映射到已绘制透视的素材四边形，才读取side_texture。

## 8. 方案B的单应矩阵

`reference_building.gd::square_to_quad()`计算单位矩形→源图四边形，结果是Basis，作为mat3参数side_reference_map。

参考四角按顺序p0近顶、p1远顶、p2远底、p3近底，先除以side_texture尺寸得到源UV。

```text
d1 = p1-p2
d2 = p3-p2
d3 = p0-p1+p2-p3

g = cross(d3,d2)/cross(d1,d2)
h = cross(d1,d3)/cross(d1,d2)
a = p1-p0+g*p1
b = p3-p0+h*p3

H_ref的列 = (a.x,a.y,g)、(b.x,b.y,h)、(p0.x,p0.y,1)
```

给定局部面点(u,v)：

```text
reference = H_ref*(u,v,1)
reference_uv = reference.xy/reference.z
```

把当前画面→局部面记为H_now^-1，则合成关系为：

```text
参考图坐标 = H_ref*H_now^-1*当前画面坐标
```

这是平面映射，不补体积。参考四边形可以来自手工标定，不必对应已知的真实相机；若原画包含非投影式的手工修形，四点只能拟合整体，不能完全反解每个细节。

## 9. Alpha、颜色、采样

- Reference分别读取front_texture/side_texture，保留原图Alpha，不再强行填实。
- Tint默认白；Side Brightness默认1，避免覆盖手绘明暗。
- floor仍按 `(ground-ground_min)/tile_size` 重复；guide_z是世界Z，不是屏幕Y。
- 当前统一使用Nearest取色，它不改变世界位置，不生成固定台阶，也不保证移动时颜色稳定。
- 固定世界点的基础UV不随相机变，但同一屏幕格观察的世界点会变，因此静态纹理仍可能运动闪烁。

## 10. 计算频率与数据来源

| 数据 | 来源 / 时机 |
| --- | --- |
| 相机状态 | MapCamera，输入后每帧同步材质 |
| 玩家Transform | 每帧由世界脚点和q投影 |
| 建筑几何、z_index、bounds | building.gd每帧 |
| H_ref | reference_building.gd每帧从可编辑角点计算，当前仅三栋，无缓存框架 |
| hit、face_uv、reference_uv、颜色 | 每个绘制片元GPU计算 |
| 贴图与Tint | 场景材质，美术输入不被相机覆盖 |

同样的uniform接口存在于多个独立Shader，是GPU输入，不是多套手工配置。场景可能保存旧输出快照，运行时以节点输入和更新代码为准。

官方变量、类型与材质传参：`https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/shading_language.html`。更具体的素材四角、截图和验证见《参考视角侧面方案B制作与使用说明》。
