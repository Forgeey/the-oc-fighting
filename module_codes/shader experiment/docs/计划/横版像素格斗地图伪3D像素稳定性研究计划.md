# 参考视角像素地图：制作与高分辨率验证计划

> 更新：2026-11-14。本轮内部画布提高至1280×720，方案B仍为主线。

## 1. 当前决定

- 使用Aseprite逐像素绘制的正面/预绘侧面，保留原有伪3D世界与参考四边形相对映射。
- 当前内部画布1280×720，按构图、采样效果和性能选择，不再根据角色有效宽高或预计角色占比计算屏幕尺寸。
- 不强制所有素材world_units_per_texel相同；角色和建筑可有不同世界体量。
- 不要求所有源像素投影等大、任意机位保持固定台阶数或必须使用精灵堆叠。
- 当前只保留Reference与Nearest两个运行场景；本轮不增加其他过滤或后处理算法。

## 2. 输入先规范什么

| 项目 | 要记录的内容 |
| --- | --- |
| 素材 | 源图尺寸、有效Alpha、透明留白、正面/参考侧面/地面模块类型 |
| 参考侧面 | 近/远端定义、四角、接合棱、手绘明暗与可接受变形范围 |
| 世界体量 | Ground Position、World Size，不由图片画布直接当世界尺寸 |
| 相机 | 世界位置/高度、焦距、Horizon、允许移动范围 |
| 输出 | 实际渲染目标、最终窗口尺寸、缩放方式；不要把窗口放大当提高取样 |
| 验收 | 构图、采样清晰度、时间稳定性、性能分开记录 |

角色素材和动画可以记录尺寸作资源事实，但不是选择屏幕分辨率的公式输入。自定义体型范围仍待决定，不在这里根据单角色姿势制定限制。

## 3. 当前运行基线

| 项目 | 当前值 |
| --- | --- |
| 主场景 | battle_map_reference.tscn |
| 内部/窗口 | 1280×720 / 1280×720 |
| 输出策略 | viewport、keep、integer，初始1:1；最小窗口1280×720 |

与上一640×360版本相比，相机世界高度、Z与所有物体体量不变，只将焦距、Horizon和画布尺寸同比加倍。角色源像素不再要求与输出像素1:1。

## 4. 闪动的解释与本轮假设

当前Shader逐输出像素求交，再按连续UV取Nearest。相机运动会让同一屏幕位置取到不同纹素。

“一个素材像素约对应一个输出像素”可能是易发生跳色的尺度，但不是唯一原因：

- 侧面压缩后，一个输出像素可能覆盖多个源纹素。
- 斜视使纹理两个方向的投影尺度不同。
- 即使一个源纹素覆盖多个输出像素，硬边经过像素采样中心时也会变化。
- 参考侧图的Alpha阶梯、大角度形变、面接合与包围框也可能形成边界问题。

本轮假设：在同一物理窗口和构图下，提高原生渲染采样密度，可以细化轮廓并减少部分粗粒跳变。不能在未录制动态对照前认定它完全消除闪动。

## 5. 方案B仍如何工作

```text
当前屏幕像素 → 当前侧墙交点 → 局部face_uv
→ side_reference_map → wall2参考四边形取色
```

wall1为正面，wall2为预绘侧面。素材四角初值(0,4)、(113,41)、(113,256)、(0,256)，只是按有效轮廓近似标定，不恢复原作者相机。

增加输出采样不会改变这套几何或素材角点，不应重新把预绘斜图当无透视矩形。仍需按建筑尺寸和机位判断效果。

## 6. 实施与验收顺序

| 编号 | 工作 | 状态/完成条件 |
| --- | --- | --- |
| H00 | 提高内部画布、保持构图 | 已接入1280×720，焦距/Horizon同比换算；技术测试通过 |
| H01 | 同窗口旧低清放大图与新原生输出静态比较 | 已保存两张1280×720图；观察侧面纹理、透明轮廓与接合边 |
| H02 当前优先 | 同世界速度、同X/Height轨迹的慢移录像 | 分清面内部跳色、轮廓跳步和实际裁边，不能只靠静帧 |
| H03 | 校准一栋建筑的wall2四角/世界比例 | 默认参考外观合理，不同时盲改三栋 |
| H04 | 独立配置远景体量/深度与素材细节 | 颗粒协调、视差明确，不强制全部素材同世界密度 |
| H05 | 评估是否继续提高画布或改为窗口原生绘制 | 保持构图与世界不变，记录GPU帧时间和显存/带宽代价 |
| H06 | 仅处理仍有明确证据的问题 | 必要时研究边界覆盖、缩小细节、限制视角；不预先加复杂框架 |
| H07 | 双角色/跳跃/UI/窗口联合验证 | 画面规格与性能目标统一，不按角色像素反算屏幕 |

不假设更多像素无限有效。1280×720为640×360的4倍输出像素，真实性能取决于材质重叠与GPU，不把像素数比例直接当耗时比例。

## 7. 问题与修改环节

| 问题/表现 | 优先核对 | 环节 |
| --- | --- | --- |
| 新画面仍像低清马赛克 | 实际渲染纹理是否1280×720，而非窗口大小 | 视口输出 |
| 提高画布后场景变小/脚点改变 | 焦距、Horizon、CPU与Shader尺寸是否同尺度 | 相机与传参 |
| 面内部细线跳色 | 单像素采样、纹理压缩方向、源细节频率 | UV与取样 |
| Alpha边缘跳步 | 原图轮廓和透视重采样；接受硬边或另定覆盖策略 | Alpha合成 |
| 侧面二次变形 | 参考四角、近远方向、World Size | 素材标定 |
| 真正缺行/列 | ColorRect是否覆盖全部投影范围 | CPU包围框 |
| 图案近远尺度差过大 | 各素材世界体量/深度和画面大小 | 美术与布局 |
| 修改Inspector没用 | 改了运行输出还是配置源；Local或Remote | 参数入口 |

先定位再改。提高分辨率不是校准错误参考角点、错贴图或错包围框的替代品。

## 8. 素材与空间尺度

对固定Z的竖直面，投影高P=世界高H×焦距f/前向深度D。它可帮助摆放建筑，但不再用它选择整个游戏屏幕高度。

同分辨率的远景图可以代表更大世界物体；相机视差仍随1/D变化。远景可以手绘更少细节、更大色块，不必把它理解为一定要程序模糊。

预绘侧面应记录四角与接合棱，保留透明区域；一张图不能生成没有画过的背面或屋顶。不能要求所有机位均可数固定数量台阶。

## 9. 输出和主界面

当前固定1280×720是一次独立试验，不等于最终必须固定这个值。无需从角色像素高度反推它。

- 只要菜单和战斗分开显示，可以切换根Window的内容缩放策略，不强行改变外部窗口大小。
- 若战斗将来直接按窗口目标绘制，普通Control/CanvasLayer可以组织UI，不必为了像素素材自动增加子视口。
- 若同屏必须使用不同渲染画布，再使用一个战斗SubViewport。CanvasLayer本身不提供独立分辨率。
- 当前没有新增菜单、子视口或动态窗口分辨率跟随逻辑；更大窗口仍按整数倍显示，不能误称已经任意窗口原生渲染。

| 编号 | 工作 | 完成条件/当前支持 |
| --- | --- | --- |
| M00 | 定参考视窗、相机、地平线/主点、运动范围，放两名角色参考 | 记录一份规格单；不据角色像素反推全屏规格 |
| M01 | 母稿粗画体块、地面和分面，先完成一栋测试楼 | 与当前固定朝向的一点透视相容；H03四角校准可在此进行 |
| M02 | 依遮挡关系拆层，隐藏前景和正面补画 | 实物潜在可见区域完整；轮廓外与真实洞口保留透明 |
| M03 | 隐藏正面补画独立侧层，再恢复母稿；需要时作辅助参考视图 | 侧图有非零面积和四角；对称复用按美术许可，独立左右素材槽尚未实现 |
| M04 | 输出PNG、裁切、脚点、四角与世界体量表 | 母稿/裁切/导出像素坐标换算一致；当前手动接入 |
| M05 | 默认/极限/中间机位与双角色动作验收 | 无漏画、错误隐藏正面或错误镜像；与H02慢移检查同时进行 |
| M06 | 确认需要的代码扩展，再量产地图 | 独立左右侧图、屋顶、预透视地面等按需实现，不假定当前原型已有 |

约定：

- 静态总图统一美术透视，不必把最终地图烘焙为单张图。
- Aseprite层/组顺序约定为前后深度线索；代码仍需要明确Z/深度档位、定位和面类型。同一建筑各面不分配为独立平行景深层。
- 补画的侧层可作方案B输入，允许对称时另一侧复用；隐藏正面只是绘制操作，运行时通常仍同时见到正面和一侧。
- 正中央侧面可在隐藏的独立层里补画并导出，记录它自己的非退化四角；同工程模板或辅助视图均可，不强制另拍机位。
- 当前Front Texture是矩形正面，Side Texture支持参考四边形；两点透视正面、独立左右图和屋顶并未实现。
- 当前地面输入是无透视平铺图，母稿中的预透视整张地面不能直接再投影一次。
- 仅对允许机位下会揭露的实物补画，不把每个透明图层无条件画成不透明矩形。
- 不改当前1280×720或以角色像素决定屏幕；本轮只补制作规范。
